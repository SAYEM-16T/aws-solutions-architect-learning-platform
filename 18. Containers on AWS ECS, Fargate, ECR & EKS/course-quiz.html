18·1U18-Q1Udemy quiz · sec 18 · Q1

You have multiple Docker-based applications hosted on-premises that you want to migrate to AWS. You don't want to provision or manage any infrastructure; you just want to run your containers on AWS. Which AWS service should you choose?

Correct: C. Why it is right

Shorto: infrastructure provision ba manage korbo na, shudhu container chalabo. Eta-i Fargate er definition: kono EC2 instance nai, tumi shudhu task definition e CPU/RAM bolo, AWS task chalay (PDF p. 424).

Scale korte shudhu task er shonkha barao. Course e instructor bolechen exam Fargate pochondo kore, karon serverless ar manage kora shohoj.

Why the other options are wrong

  • A. ECS EC2 launch type e EC2 instance gulo tumi-i provision ar maintain koro (ECS Agent, patching, scaling), ja 'manage korbo na' shorto bhange.
  • B. ECR shudhu Docker image store kore; container run kore na.

Keyword: don't want to provision or manage any infrastructure + run containers → Fargate on ECS

Instructor feedback (English)

A: Amazon ECS allows you to run your containers on AWS but you must provision and maintain the EC2 instances where your containers will be run on.

B: Amazon ECR is a fully managed container registry that makes it easy to store, manage, share, and deploy your container images. It won't help in running your Docker-based applications.

C: AWS Fargate allows you to run your containers on AWS without managing any servers.

18·2U18-Q2Udemy quiz · sec 18 · Q2⚠ outdated

Amazon Elastic Container Service (ECS) has two Launch Types: .................. and ..................

⚠ Outdated: Course/exam e ECS er 2 ta launch type (EC2, Fargate) - ei answer-i dhoro. Kintu ekhon ECS e EXTERNAL launch type (ECS Anywhere, on-prem server) ar ECS Managed Instances o ache, tai 'shudhu 2 ta' kotha ta ar puro thik na. source

Correct: A. Why it is right

Course e ECS er duita launch type: EC2 launch type (tumi EC2 instance provision kore, protita te ECS Agent) ar Fargate launch type (serverless, instance nai) (PDF p. 423-424).

Aajker din e ECS docs e External (ECS Anywhere) ar ECS Managed Instances o ache, tai 'shudhu 2 ta' kotha ta ar puro thik na; tobu ei option gulor moddhe A-i ekmatro thik.

Why the other options are wrong

  • B. EKS alada service (managed Kubernetes), ECS er launch type na.
  • C. Fargate thik, kintu EKS ECS er launch type na; EKS nije ekta orchestrator jeta Fargate use korte pare.

Keyword: ECS launch types → EC2 + Fargate (EKS kokhono ECS launch type na)

18·3U18-Q3Udemy quiz · sec 18 · Q3

You have an application hosted on an ECS Cluster (EC2 Launch Type) where you want your ECS tasks to upload files to an S3 bucket. Which IAM Role for your ECS Tasks should you modify?

Correct: B. Why it is right

Container er bhitorer app je AWS API call kore (ekhane S3 e upload), tar permission ashe ECS Task Role theke. Task Role task definition e define hoy, EC2 ar Fargate duitai te kaj kore (PDF p. 425).

EC2 launch type holeo app er permission instance profile e dewa thik na.

Why the other options are wrong

  • A. EC2 Instance Profile use kore ECS Agent: ECS API call, ECR theke image pull, CloudWatch Logs e log pathano. Task er app er S3 access er jonno na.

Keyword: ECS tasks upload files to S3 → ECS Task Role

Instructor feedback (English)

A: EC2 Instance Profile is the IAM Role used by the ECS Agent on the EC2 instance to execute ECS-specific actions such as pulling Docker images from ECR and storing the container logs into CloudWatch Logs.

B: ECS Task Role is the IAM Role used by the ECS task itself. Use when your container wants to call other AWS services like S3, SQS, etc.

18·4U18-Q4Udemy quiz · sec 18 · Q4

You're planning to migrate a WordPress website running on Docker containers from on-premises to AWS. You have decided to run the application in an ECS Cluster, but you want your docker containers to access the same WordPress website content such as website files, images, videos, etc. What do you recommend to achieve this?

Correct: A. Why it is right

Shob container ke same WordPress content (files, images, videos) dekhte hobe = shared storage. EFS ECS task e mount kora jay, EC2 ar Fargate duitai e kaj kore, ar je kono AZ er task same data dekhe (PDF p. 427).

Course: EFS = container er jonno persistent multi-AZ shared storage.

Why the other options are wrong

  • B. EBS volume ek AZ e bandha, sadharonoto ek instance e attach; onek task/instance jure same content share er jonno na. ECS e EBS ekhon task e attach hoy, kintu task proti alada notun volume, shared na.
  • C. Instance store ephemeral (instance stop/terminate hole data jay) ar shudhu oi ek EC2 er; share ba Fargate e use hoy na.

Keyword: docker containers access the same website content → shared storage → EFS

Instructor feedback (English)

A: EFS volume can be shared between different EC2 instances and different ECS Tasks. It can be used as a persistent multi-AZ shared storage for your containers.

B: This can be used when all your ECS tasks run on the same EC2 instance. It's not suitable when your tasks are spread across multiple EC2 instances and can't be used with AWS Fargate.

C: EC2 Instance Store can't be shared between different EC2 instances.

18·5U18-Q5Udemy quiz · sec 18 · Q5

You are deploying an application on an ECS Cluster made of EC2 instances. Currently, the cluster is hosting one application that is issuing API calls to DynamoDB successfully. Upon adding a second application, which issues API calls to S3, you are getting authorization issues. What should you do to resolve the problem and ensure proper security?

Correct: B. Why it is right

Notun app S3 call kore kintu permission nai. Fix: oi app er jonno alada IAM task role (S3 permission shoho) baniye task definition e dao. Course: alada ECS service er jonno alada task role (PDF p. 425).

Constraint word: ensure proper security = least privilege: shudhu notun app S3 pabe, DynamoDB app pabe na.

Why the other options are wrong

  • A. Instance role e S3 dile oi EC2 er shob task (DynamoDB app o) S3 access pabe; least privilege bhange, security risk.
  • C. Fargate e gele o permission ashe task role theke; launch type bodlale authorization problem solve hoy na, ar Fargate e instance role-i thake na.
  • D. Bucket policy te ECS task ke allow korte holeo task er ekta IAM identity (task role) lagbe; ar AWS API call er jonno identity-side permission (task role) i proper fix.

Keyword: second application S3 authorization issue + proper security → notun IAM task role oi app er jonno

Instructor feedback (English)

A: This would allow the first application to access S3 as well, which is a security risk.

18·6U18-Q6Udemy quiz · sec 18 · Q6

You are migrating your on-premises Docker-based applications to Amazon ECS. You were using Docker Hub Container Image Library as your container image repository. Which is an alternative AWS service which is fully integrated with Amazon ECS?

Correct: B. Why it is right

Docker Hub er bodole AWS er container image registry = Amazon ECR. ECR Docker image store ar manage kore (private + ECR Public Gallery), ECS er sathe fully integrated, pichone S3, access IAM diye (PDF p. 436).

Course: 'storing Docker images' dekhlei ECR.

Why the other options are wrong

  • A. Fargate container chalay (serverless compute), image store kore na.
  • C. EKS managed Kubernetes, container chalanor orchestrator; image registry na.
  • D. EC2 virtual server; container image repository service na.

Keyword: Docker Hub alternative, fully integrated with ECS → ECR

Instructor feedback (English)

A: AWS Fargate allows you to run your containers on AWS without managing any servers.

B: Amazon ECR is a fully managed container registry that makes it easy to store, manage, share, and deploy your container images. ECR is fully integrated with Amazon ECS, allowing easy retrieval of container images from ECR while managing and running containers using ECS.

C: Amazon EKS allows you to start, run, and scale Kubernetes applications in AWS or on-premises and run fully-managed EKS clusters on AWS.

D: Amazon EC2 can't be used to store Docker container images.

18·7U18-Q7Udemy quiz · sec 18 · Q7

Amazon EKS supports the following node types, EXCEPT ………………..

Correct: D. Why it is right

Course e EKS er node type 3 ta: Managed Node Groups (EKS EC2 + ASG manage kore), Self-Managed Nodes (tumi banao, register koro), ar AWS Fargate (kono node nai) (PDF p. 439).

Lambda function, Kubernetes node na; tai EXCEPT er answer Lambda. (Aajker din e EKS Auto Mode ar Hybrid Nodes o ache, kintu Lambda kokhono na.)

Why the other options are wrong

  • A. Managed Node Groups EKS er node type: EKS EC2 node create ar manage kore, On-Demand/Spot.
  • B. Self-Managed Nodes EKS er node type: tumi node banao, cluster e register koro, EKS Optimized AMI use korte paro.
  • C. Fargate EKS e supported: serverless, node manage korte hoy na.

Keyword: EKS node types EXCEPT → Managed / Self-Managed / Fargate ache, Lambda nai

18·8U18-Q8Udemy quiz · sec 18 · Q8⚠ outdated

A developer has a running website and APIs on his local machine using containers and he wants to deploy both of them on AWS. The developer is new to AWS and doesn’t know much about different AWS services. Which of the following AWS services allows the developer to build and deploy the website and the APIs in the easiest way according to AWS best practices?

⚠ Outdated: AWS App Runner 2026 theke new customer der jonno bondho (existing customer ra use korte pare); new user der jonno AWS ekhon Amazon ECS Express Mode recommend kore. Course/exam er answer ekhono App Runner. source

Correct: A. Why it is right

Developer AWS e notun, website + API container e ache, chay easiest deploy. App Runner fully managed: source code ba container image dao, vCPU/RAM bolo, App Runner build + deploy kore URL dey; auto scaling, load balancing, HA, encryption nije kore. Infrastructure jante hoy na (Lecture 12).

Aajker din: App Runner April 30, 2026 theke notun customer der jonno bondho, AWS ekhon ECS Express Mode recommend kore. Kintu course/exam er answer ekhono App Runner.

Why the other options are wrong

  • B. EC2 + ALB e instance, AMI, ASG, load balancer, deploy sob nije set up korte hoy; notun developer er jonno sobcheye kothin.
  • C. ECS e cluster, task definition, service, load balancer, scaling configure korte hoy; App Runner er cheye beshi kaj.
  • D. Fargate serverless compute, kintu ECS/EKS er bhitore task definition, service, ALB, networking tumi-i configure koro; 'easiest, kichu jane na' er jonno App Runner.

Keyword: new to AWS, website + APIs in containers, easiest way → App Runner
