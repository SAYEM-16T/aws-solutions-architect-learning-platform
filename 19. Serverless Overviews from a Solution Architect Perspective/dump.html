A company is building an ecommerce web application on AWS. The application sends information about new orders to an Amazon API Gateway REST API to process. The company wants to ensure that orders are processed in the order that they are received. Which solution will meet these requirements?

Correct: B. Why it is right

Processed in the order that they are received = ordering. Shudhu SQS FIFO queue message er order guarantee kore (First In First Out, PDF p. 391).

API Gateway direct AWS service integration diye SQS FIFO queue te message pathay, ar Lambda oi queue ke event source hisebe use kore order maintain kore process kore.

Why the other options are wrong

  • A. SNS standard topic order guarantee kore na; Lambda subscriber e message je kono order e aste pare.
  • C. Authorizer authentication/authorization er jonno; request block kore order maintain kora jay na, ar eta scalable o na.
  • D. SQS standard queue best-effort ordering dey, order guarantee kore na; tai order matter korle FIFO lagbe.

Keyword: processed in the order that they are received → SQS FIFO queue + Lambda

Dump explanation (English)

To ensure that orders are processed in the order that they are received, the best solution is to use an Amazon SQS FIFO (First-In-First-Out) queue. This type of queue maintains the exact order in which messages are sent and received. In this case, the application can send information about new orders to an Amazon API Gateway REST API, which can then use an API Gateway integration to send a message to an Amazon SQS FIFO queue for processing. The queue can then be configured to invoke an AWS Lambda function to perform the necessary processing on each order. This ensures that orders are processed in the exact order in which they are received.
