19·1U19-Q1Udemy quiz · sec 19 · Q1

You have created a Lambda function that typically will take around 1 hour to process some data. The code works fine when you run it locally on your machine, but when you invoke the Lambda function it fails with a "timeout" error after 3 seconds. What should you do?

আপনি একটি Lambda function তৈরি করেছেন, যা সাধারণত কিছু data process করতে প্রায় 1 ঘণ্টা সময় নেবে। আপনার machine-এ locally চালালে code ঠিকভাবে কাজ করে, কিন্তু আপনি যখন Lambda function invoke করেন, তখন 3 সেকেন্ড পরে এটি একটি "timeout" error দিয়ে fail করে। আপনার কী করা উচিত?

Correct: C. Why it is right

Lambda er maximum timeout 900 s = 15 minute (PDF p. 451). Job ta 1 ghonta lage, tai timeout jotoi barao, Lambda te eta kokhono shesh hobe na.

3 s e fail korche karon default timeout 3 s; kintu 15 min porjonto barale-o 1 ghontar kaj fit hoy na. Tai code ta EC2 (ba ECS / Fargate) e chalao, jekhane kono time limit nai.

Why the other options are wrong

  • A. Lambda timeout max 15 min; 25 min set-i kora jay na, ar 1 ghontar job er jonno eta-o kom.
  • B. 10 GB RAM dile CPU bare, code ektu fast hoy, kintu 1 ghontar kaj 15 min er niche nambe na.

Keyword: process ~1 hour + Lambda timeout → Lambda max 15 min, tai EC2 / ECS e chalao

Instructor feedback (English)

A: The maximum timeout you can configure in Lambda is 15 minutes.

B: This may speed up the function processing time, but it wouldn't reduce execution time below 15 minutes.

C: Lambda's maximum execution time is 15 minutes. You can run your code somewhere else such as an EC2 instance or use Amazon ECS.

19·2U19-Q2Udemy quiz · sec 19 · Q2

Before you create a DynamoDB table, you need to provision the EC2 instance the DynamoDB table will be running on.

একটি DynamoDB table তৈরি করার আগে, আপনাকে সেই EC2 instance provision করতে হবে, যেটিতে DynamoDB table চলবে।

Correct: B. Why it is right

DynamoDB fully managed, serverless NoSQL database (PDF p. 469). Tumi shudhu table banao; server provision, patch, maintenance kichui korte hoy na.

Capacity thik koro RCU/WCU (provisioned) ba on-demand diye, EC2 diye na. Tai statement ta False.

Why the other options are wrong

  • A. DynamoDB er jonno kono EC2 instance nai ba lage na; AWS pura infrastructure manage kore, tumi shudhu table ar capacity mode thik koro.

Keyword: DynamoDB + provision EC2? → False, DynamoDB serverless

Instructor feedback (English)

B: DynamoDB is serverless with no servers to provision, patch, or manage and no software to install, maintain or operate. It automatically scales tables up and down to adjust for capacity and maintain performance. It provides both provisioned (specify RCU & WCU) and on-demand (pay for what you use) capacity modes.

19·3U19-Q3Udemy quiz · sec 19 · Q3

You have provisioned a DynamoDB table with 10 RCUs and 10 WCUs. A month later you want to increase the RCU to handle more read traffic. What should you do?

আপনি 10 RCUs এবং 10 WCUs সহ একটি DynamoDB table provision করেছেন। এক মাস পরে আপনি আরও বেশি read traffic handle করতে RCU বাড়াতে চান। আপনার কী করা উচিত?

Correct: A. Why it is right

Provisioned mode e RCU ar WCU alada alada set kora jay (PDF p. 472). Read barbe, tai shudhu RCU barao; WCU jemon ache temon rakho.

Chaile auto scaling diye-o RCU/WCU alada vabe scale kora jay.

Why the other options are wrong

  • B. RCU ar WCU decoupled; read barate WCU barano lage na, shudhu extra khoroch hobe.
  • C. Write traffic komeni, tai WCU komale write throttle hote pare; ar read barate WCU komano lage na.

Keyword: increase RCU for more read traffic → RCU barao, WCU same (independent)

Instructor feedback (English)

A: RCU and WCU are decoupled, so you can increase/decrease each value separately.

19·4U19-Q4Udemy quiz · sec 19 · Q4

You have an e-commerce website where you are using DynamoDB as your database. You are about to enter the Christmas sale and you have a few items which are very popular and you expect that they will be read often. Unfortunately, last year due to the huge traffic you had the ProvisionedThroughputExceededException exception. What would you do to prevent this error from happening again?

আপনার একটি e-commerce website আছে, যেখানে আপনি database হিসেবে DynamoDB ব্যবহার করছেন। আপনি Christmas sale-এ প্রবেশ করতে যাচ্ছেন এবং আপনার কয়েকটি item আছে, যেগুলো খুব জনপ্রিয় এবং আপনি আশা করেন যে সেগুলো প্রায়ই read হবে। দুর্ভাগ্যবশত, গত বছর বিপুল traffic-এর কারণে আপনি ProvisionedThroughputExceededException exception পেয়েছিলেন। এই error যাতে আবার না ঘটে, তা প্রতিরোধ করতে আপনি কী করবেন?

Correct: B. Why it is right

Kichu popular item bar bar read hocche = hot key problem, tai ProvisionedThroughputExceededException.

DAX DynamoDB er samne fully managed in-memory cache, microsecond latency, code change lage na (PDF p. 473). Hot item gulo cache theke ashe, table e read kome jay, throttle bondho hoy.

Why the other options are wrong

  • A. RCU onek barale khoroch onek bare, ar hot key ekta partition e pore bole RCU barale-o throttle puro thambe na.
  • C. Sale er jonno database migrate kora onek effort ar risk; DAX diye easily solve hoy.

Keyword: few popular items read often + ProvisionedThroughputExceeded → DAX cache

Instructor feedback (English)

A: This is not a good solution to solve the Hot Key problem and it will cost you a lot of money.

B: DynamoDB Accelerator (DAX) is a fully managed, highly available, in-memory cache for DynamoDB that delivers up to 10x performance improvement. It caches the most frequently used data, thus offloading the heavy reads on hot keys off your DynamoDB table, hence preventing the "ProvisionedThroughputExceededException" exception.

C: This requires too much effort and it might not deliver the required performance.

19·5U19-Q5Udemy quiz · sec 19 · Q5

You have developed a mobile application that uses DynamoDB as its datastore. You want to automate sending welcome emails to new users after they sign up. What is the most efficient way to achieve this?

আপনি একটি mobile application develop করেছেন, যা datastore হিসেবে DynamoDB ব্যবহার করে। নতুন user-রা sign up করার পরে আপনি তাদের welcome email পাঠানো automate করতে চান। এটি অর্জনের সবচেয়ে efficient উপায় কী?

Renamed: CloudWatch Events -> Amazon EventBridge (the answer is the same).

Correct: C. Why it is right

DynamoDB Streams table er protita item-level change (create/update/delete) er ordered stream (PDF p. 475). Stream e Lambda trigger lagale notun user insert holei Lambda real-time e welcome email pathay.

Course e exact ei use case: "React to changes in real-time (welcome email to users)".

Why the other options are wrong

  • A. Prati minute pura table scan kora slow ar dami (RCU khay), table boro hole aro kharap; event-driven Streams efficient.
  • B. DynamoDB er direct 'SNS integration' bole kono feature nai; change dhorte Streams + Lambda lage.

Keyword: new user sign up e auto welcome email → DynamoDB Streams + Lambda

Instructor feedback (English)

A: This would work but it wouldn't be a scalable, cheap, or efficient solution.

B: There's no such feature.

C: DynamoDB Streams allows you to capture a time-ordered sequence of item-level modifications in a DynamoDB table. It's integrated with AWS Lambda so that you create triggers that automatically respond to events in real-time.

একটি serverless API তৈরি করতে আপনার Amazon API Gateway-কে ...................... -এর সাথে integrate করা উচিত।

19·7U19-Q7Udemy quiz · sec 19 · Q7

When you are using an Edge-Optimized API Gateway, your API Gateway lives in CloudFront Edge Locations across all AWS Regions.

আপনি যখন একটি Edge-Optimized API Gateway ব্যবহার করছেন, তখন আপনার API Gateway সব AWS Regions জুড়ে CloudFront Edge Locations-এ থাকে।

Instructor feedback (English)

A: An Edge-Optimized API Gateway is best for geographically distributed clients. API requests are routed to the nearest CloudFront Edge Location which improves latency. The API Gateway still lives in one AWS Region.

19·8U19-Q8Udemy quiz · sec 19 · Q8

You are running an application in production that is leveraging DynamoDB as its datastore and is experiencing smooth sustained usage. There is a need to make the application run in development mode as well, where it will experience the unpredictable volume of requests. What is the most cost-effective solution that you recommend?

আপনি production-এ একটি application চালাচ্ছেন, যা datastore হিসেবে DynamoDB ব্যবহার করছে এবং মসৃণ, স্থির (sustained) usage পাচ্ছে। application-টি development mode-এও চালানোর প্রয়োজন আছে, যেখানে এটি request-এর unpredictable পরিমাণের সম্মুখীন হবে। আপনি সবচেয়ে cost-effective কোন solution recommend করবেন?

Correct: B. Why it is right

Prod e smooth sustained (predictable) traffic → Provisioned + Auto Scaling, eta sosta. Dev e unpredictable request → On-Demand, capacity plan lage na, use onujayi pay (PDF p. 472).

Ajker note: Nov 2024 e on-demand er dam ~50% komeche, kintu exam er logic (predictable → provisioned, unpredictable → on-demand) ekhono same.

Why the other options are wrong

  • A. Dev e traffic unpredictable; provisioned capacity hoy beshi set kore khoroch, noyto kom set kore throttle. On-demand dev er jonno better.
  • C. Ulta: prod predictable bole provisioned sosta, ar dev unpredictable bole on-demand.
  • D. Kaj korbe, kintu prod er smooth traffic e on-demand provisioned + auto scaling er cheye beshi dami; most cost-effective na.

Keyword: prod smooth sustained → Provisioned + Auto Scaling; dev unpredictable → On-Demand

Instructor feedback (English)

D: This will work, but it would be extremely expensive as On-Demand Capacity Mode is much more expensive than Provisioned Capacity Mode. As we know production has a smooth sustained curve, Provisioned Capacity Mode with Auto Scaling enabled would be perfect.

You have an application that is served globally using CloudFront Distribution. You want to authenticate users at the CloudFront Edge Locations instead of authentication requests go all the way to your origins. What should you use to satisfy this requirement?

আপনার একটি application আছে, যা CloudFront Distribution ব্যবহার করে globally serve করা হয়। authentication request আপনার origin পর্যন্ত যাওয়ার বদলে আপনি CloudFront Edge Locations-এ user authenticate করতে চান। এই requirement পূরণ করতে আপনার কী ব্যবহার করা উচিত?

Correct: A. Why it is right

Lambda@Edge CloudFront er edge location e code chalay, origin e jaoyar agei (viewer request e) user authenticate kora jay (PDF p. 461). Course er use case list e "User Authentication and Authorization" ache (PDF p. 459).

(Simple JWT check CloudFront Functions diye-o hoy, kintu option e shudhu Lambda@Edge ache.)

Why the other options are wrong

  • B. API Gateway ekta region e API host kore; CloudFront edge e code chalay na.
  • C. DynamoDB database, edge e code ba authentication chalate pare na.
  • D. Global Accelerator AWS network diye traffic route kore (anycast IP); edge e custom code chalay na.

Keyword: authenticate at CloudFront Edge Locations → Lambda@Edge

A: Lambda@Edge is a feature of CloudFront that lets you run code closer to your users, which improves performance and reduces latency.

19·12U19-Q12Udemy quiz · sec 19 · Q12

A company has a serverless application on AWS which consists of Lambda, DynamoDB, and Step Functions. একটি company-র AWS-এ একটি serverless application আছে, যা Lambda, DynamoDB এবং Step Functions নিয়ে গঠিত। গত মাসে application-এ request-এর সংখ্যা বেড়েছে, যার ফলে DynamoDB-র খরচ বেড়েছে, এবং request throttle হতে শুরু করেছে। আরও তদন্তে দেখা যায় যে বেশিরভাগ request হলো DynamoDB table-এর কিছু query-র বিপরীতে read request। throttle প্রতিরোধ করতে এবং দক্ষতার সাথে খরচ কমাতে আপনি কী recommend করবেন?

Beshirbhag request read, kichu query bar bar → throttle ar cost barche. DAX DynamoDB er jonno fully managed in-memory cache, DynamoDB API compatible tai code logic bodlate hoy na, item ar query/scan result cache kore (PDF p. 473-474).

Why the other options are wrong

  • A. EC2 te Redis install korle server nije manage korte hobe (patch, HA), app code-o bodlate hobe; serverless app er jonno extra ops overhead.
  • B. Aurora te migrate kora onek boro kaj ar risk; shudhu read cache er jonno DB bodlano lage na.
  • C. S3 database na, query chalate pare na; DynamoDB theke S3 te migrate kora ei app er jonno thik na.

Keyword: majority read requests + throttled + reduce cost efficiently → DAX

19·15U19-Q15Udemy quiz · sec 19 · Q15

You have a mobile application and would like to give your users access to their own personal space in the S3 bucket. How do you achieve that?

আপনার একটি mobile application আছে এবং আপনি আপনার user-দের S3 bucket-এ তাদের নিজস্ব personal space-এ access দিতে চান। আপনি এটি কীভাবে অর্জন করবেন?

Why the other options are wrong

  • A. Prati mobile user er jonno IAM user banano scale kore na, ar long-term credential app e rakha unsafe.
  • C. SAML federation enterprise IdP (jemon Active Directory) er jonno; mobile app er onek user er jonno Cognito best.

Keyword: mobile app users + own personal space in S3 → Cognito Identity Federation

Instructor feedback (English)

You are developing a new web and mobile application that will be hosted on AWS and currently, you are working on developing the login and signup page. The application backend is serverless and you are using Lambda, DynamoDB, and API Gateway. Which of the following is the best and easiest approach to configure the authentication for your backend?

আপনি একটি নতুন web ও mobile application develop করছেন, যা AWS-এ host করা হবে এবং বর্তমানে আপনি login ও signup page develop করার কাজ করছেন। application backend serverless এবং আপনি Lambda, DynamoDB ও API Gateway ব্যবহার করছেন। আপনার backend-এর জন্য authentication configure করার সবচেয়ে ভালো এবং সবচেয়ে সহজ পদ্ধতি নিচের কোনটি?

Correct: C. Why it is right

Cognito User Pools = app user der jonno serverless user database: sign-up, sign-in, password reset, email/phone verification, MFA (PDF p. 489).

User Pool API Gateway er sathe integrate kore: user login kore token pay, API Gateway token verify kore Lambda backend e pathay (PDF p. 490). Nijer credential store banano lage na: best ar easiest.

Why the other options are wrong

  • A. Nijer DynamoDB te credential rakhle login, hashing, reset, MFA sob nije code korte hobe; easiest na, security risk-o beshi.
  • B. S3 credential store na; nijer auth system banate hobe, onek kaj ar insecure.
  • D. Secrets Manager application er secret (DB password, API key) rakhar jonno, end-user sign-up/sign-in system na.

Keyword: login and signup + API Gateway backend + easiest → Cognito User Pools

You are running a mobile application where you want each registered user to upload/download images to/from his own folder in the S3 bucket. Also, you want to give your users to sign-up and sign in using their social media accounts (e.g., Facebook). Which AWS service should you choose?

আপনি একটি mobile application চালাচ্ছেন, যেখানে আপনি চান প্রতিটি registered user S3 bucket-এ তার নিজের folder-এ/folder থেকে image upload/download করুক। এছাড়াও, আপনি আপনার user-দের তাদের social media account (যেমন, Facebook) ব্যবহার করে sign-up ও sign in করার সুযোগ দিতে চান। আপনার কোন AWS service বেছে নেওয়া উচিত?

Correct: C. Why it is right

Amazon Cognito duita need-i mitay (PDF p. 488-491):

  • User Pool: sign-up/sign-in, Facebook/Google social login (federated identities).
  • Identity Pool: user ke temporary AWS credentials, user_id diye policy, tai nijer S3 folder e upload/download.

Course: "hundreds of users, mobile users" → Cognito, IAM na.

Why the other options are wrong

  • A. IAM AWS account er user/role er jonno; millions mobile user ke social login dite pare na.
  • B. IAM Identity Center workforce (company employee) er SSO er jonno, mobile app er end user er jonno na.
  • D. CloudFront CDN, content deliver kore; user sign-up ba AWS credential dey na.

Keyword: mobile + sign in with Facebook + own S3 folder → Amazon Cognito

Instructor feedback (English)

A: AWS IAM enables you to manage access to AWS services and resources securely. It allows you to create and manage AWS users and groups, and use permissions to allow and deny their access to AWS resources. IAM can not be used to federate mobile users.

B: AWS IAM Identity Center makes it easy to centrally manage SSO access to all of your AWS accounts and cloud applications. It helps you manage SSO access and user permissions across all your AWS accounts in AWS Organizations. It also helps when you manage access and permissions to commonly used 3rd party software as a service (SaaS) applications, AWS SSO-integrated applications as well as custom applications that support Security Assertion Markup Language (SAML) 2.0. AWS SSO also includes built-in SAML integrations to many business applications, such as Salesforce, Box, and Office 365.

C: Amazon Cognito lets you add user sign-up, sign-in, and access control to your web and mobile apps quickly and easily. Amazon Cognito scales to millions of users and supports sign-in with social identity providers, such as Apple, Facebook, Google, and Amazon, and enterprise identity providers via SAML 2.0 and OpenID Connect.

D: Amazon CloudFront is a fast content delivery network (CDN) service that securely delivers data, videos, applications, and APIs to customers globally with low latency, high transfer speeds. Amazon CloudFront does not federate mobile users or generate security credentials.
