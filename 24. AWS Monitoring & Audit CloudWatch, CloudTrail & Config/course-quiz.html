24·1U24-Q1Udemy quiz · sec 24 · Q1

You have an RDS DB instance that's configured to push its database logs to CloudWatch. You want to create a CloudWatch alarm if there's an Error found in the logs. How would you do that?

আপনার একটি RDS DB instance আছে, যা তার database log CloudWatch-এ push করার জন্য configure করা। Log-এ কোনো Error পাওয়া গেলে আপনি একটি CloudWatch alarm তৈরি করতে চান। আপনি এটি কীভাবে করবেন?

Renamed: CloudWatch Events -> Amazon EventBridge (the answer is the same).

Correct: B. Why it is right

RDS er log already CloudWatch Logs e jacche. Log theke alarm banate Metric Filter lagbe: filter ta log e Error keyword khuje count kore ekta CloudWatch metric banay (PDF p. 596).

Tarpor oi metric er upor CloudWatch Alarm banao, alarm SNS e notify korbe. Kono code lage na, near real-time.

Why the other options are wrong

  • A. Scheduled EventBridge (ager CloudWatch Events) + Lambda diye log scan kora custom code ar extra kaaj; prottek 1 ghonta por check kore, tai delay o thake. Built-in metric filter thakte eta dorkar nai.
  • C. AWS Config resource er configuration ar compliance dekhe; log er bhitorer text (Error) pore na.

Keyword: log e Error paile alarm → Metric Filter + CloudWatch Alarm

24·2U24-Q2Udemy quiz · sec 24 · Q2

You have an application hosted on a fleet of EC2 instances managed by an Auto Scaling Group that you configured its minimum capacity to 2. Also, you have created a CloudWatch Alarm that is configured to scale in your ASG when CPU Utilization is below 60%. Currently, your application runs on 2 EC2 instances and has low traffic and the CloudWatch Alarm is in the ALARM state. What will happen?

আপনার একটি application EC2 instance-এর একটি fleet-এ host করা, যা একটি Auto Scaling Group manage করে, এবং আপনি এর minimum capacity 2 configure করেছেন। এছাড়া, আপনি একটি CloudWatch Alarm তৈরি করেছেন, যা CPU Utilization 60%-এর নিচে হলে আপনার ASG scale in করার জন্য configure করা। বর্তমানে আপনার application 2টি EC2 instance-এ চলছে, traffic কম, এবং CloudWatch Alarm ALARM state-এ আছে। কী ঘটবে?

Correct: B. Why it is right

ASG kokhono minimum capacity er niche jay na (PDF p. 153). Min = 2, ekhon cholche 2 ta, tai scale-in alarm fire korleo ASG kono instance terminate korbe na.

Alarm er state change hoy metric dekhe: CPU 60% er niche thakle alarm ALARM state ei thakbe, kintu kono effect hobe na.

Why the other options are wrong

  • A. Alarm ASG er minimum capacity change kore na. Min 2 thakle ASG 2 er niche namte parbe na.
  • C. Alarm nije nije ASG theke detach hoy na; scaling policy attached thakbe, shudhu kaaj korbe na karon min e ache.
  • D. Alarm state metric er upor nirbhor kore. CPU ekhono 60% er niche, tai OK hobe na, ALARM ei thakbe.

Keyword: minimum capacity 2 + already 2 instances → alarm ALARM e thake kintu scale-in hoy na

Instructor feedback (English)

B: The number of EC2 instances in an ASG can not go below the minimum capacity, even if the CloudWatch alarm would in theory trigger an EC2 instance termination.

Why the other options are wrong

  • B. Bhul: EC2 default e memory usage pathay na, shudhu CPU, disk, network.

Keyword: EC2 memory usage → Unified CloudWatch Agent + custom metric

24·4U24-Q4Udemy quiz · sec 24 · Q4

You have made a configuration change and would like to evaluate the impact of it on the performance of your application. Which AWS service should you use?

আপনি একটি configuration change করেছেন এবং আপনার application-এর performance-এ এর প্রভাব evaluate করতে চান। আপনার কোন AWS service ব্যবহার করা উচিত?

Correct: A. Why it is right

Application er performance (CPU, latency, error, request count) maapa hoy CloudWatch Metrics ar dashboard diye (PDF p. 620: CloudWatch = performance monitoring).

Change er age ar pore metric graph compare korlei impact bojha jay.

Why the other options are wrong

  • B. CloudTrail shudhu API call record kore (ke, kokhon, ki change korlo); performance metric dey na.

Keyword: impact on performance → CloudWatch

Instructor feedback (English)

A: Amazon CloudWatch is a monitoring service that allows you to monitor your applications, respond to system-wide performance changes, optimize resource utilization, and get a unified view of operational health. It is used to monitor your applications' performance and metrics.

B: AWS CloudTrail allows you to log, continuously monitor, and retain account activity related to actions across your AWS infrastructure. It provides the event history of your AWS account activity, audit API calls made through the AWS Management Console, AWS SDKs, AWS CLI. You can use CloudTrail to detect unusual activity in your AWS accounts.

24·5U24-Q5Udemy quiz · sec 24 · Q5

Someone has terminated an EC2 instance in your AWS account last week, which was hosting a critical database that contains sensitive data. Which AWS service helps you find who did that and when?

গত সপ্তাহে কেউ আপনার AWS account-এ একটি EC2 instance terminate করেছে, যেটি sensitive data থাকা একটি critical database host করছিল। কে এবং কখন এটি করেছে তা খুঁজে পেতে কোন AWS service আপনাকে সাহায্য করে?

Renamed: CloudWatch Events -> Amazon EventBridge (the answer is the same).

Correct: D. Why it is right

CloudTrail account er sob API call record kore: ke (IAM user/role), kokhon, kon IP theke (PDF p. 608). Instance terminate holo TerminateInstances API call, eta CloudTrail e thakbe.

Course er tip: resource delete hole age CloudTrail dekho. Event 90 din thake, tai last week er event pawa jabe.

Why the other options are wrong

  • A. CloudWatch Metrics performance data (CPU, network); 'ke' terminate korlo ta bole na.
  • B. CloudWatch Alarm metric threshold e notify kore; kono user er action record kore na.
  • C. CloudWatch Events (ekhon EventBridge) event react kore real-time e, kintu purono 'who did it' history rakhe na. Eta CloudTrail er data dhoreo kaaj kore.

Keyword: who did that and when + terminated → CloudTrail

Instructor feedback (English)

A: CloudWatch Metrics are data about the performance of your systems, it won't indicate "who" did what.

B: CloudWatch Alarms allows you to trigger notifications/actions based on any CloudWatch Metrics or other CloudWatch Alarms, it won't indicate "who" did what.

C: CloudWatch Events delivers a stream of system events that describe changes in your AWS resources, it won't indicate "who" did what.

D: AWS CloudTrail allows you to log, continuously monitor, and retain account activity related to actions across your AWS infrastructure. It provides the event history of your AWS account activity, audit API calls made through the AWS Management Console, AWS SDKs, AWS CLI. So, the EC2 instance termination API call will appear here. You can use CloudTrail to detect unusual activity in your AWS accounts.

You have CloudTrail enabled for your AWS Account in all AWS Regions. What should you use to detect unusual activity in your AWS Account?

সব AWS Regions-এ আপনার AWS Account-এর জন্য CloudTrail enable করা আছে। আপনার AWS Account-এ অস্বাভাবিক activity detect করতে আপনার কী ব্যবহার করা উচিত?

Keyword: detect unusual activity → CloudTrail Insights

আপনার এক teammate 4 মাস আগে critical data থাকা একটি EC2 instance terminate করেছে। কে এটি করেছে আপনি জানেন না, তাই আপনি CloudTrail ব্যবহার করে এই সময়ের মধ্যে সব API call review করবেন। আপনার CloudTrail ইতিমধ্যে set up করা এবং S3 bucket-এ log পাঠানোর জন্য configure করা আছে। কে এটি করেছে তা বের করতে আপনার কী করা উচিত?

You are running a website on a fleet of EC2 instances with OS that has a known vulnerability on port 84. You want to continuously monitor your EC2 instances if they have port 84 exposed. How should you do this?

আপনি EC2 instance-এর একটি fleet-এ একটি website চালাচ্ছেন, যার OS-এ port 84-এ একটি পরিচিত (known) vulnerability আছে। আপনার EC2 instance-গুলোতে port 84 exposed আছে কিনা, তা আপনি continuously monitor করতে চান। আপনার এটি কীভাবে করা উচিত?

Correct: C. Why it is right

AWS Config Rules resource er configuration continuously evaluate kore, ar non-compliant hole flag kore (PDF p. 615-616).

Course er example: 'Is there unrestricted SSH access to my security groups?' Same bhabe rule likho: kono security group e port 84 open ache kina. Rule config change hole ba regular interval e check hoy.

Why the other options are wrong

  • A. CloudWatch Metrics performance number (CPU, network) dey; security group e kon port open ta bole na.
  • B. CloudTrail API call record kore (ke SG change korlo), kintu current configuration compliant kina evaluate kore na.
  • D. Scheduled EventBridge (ager CloudWatch Events) + Lambda diye nije scanner likhte hobe: extra code ar maintenance. Config Rules ei kaaj managed bhabe kore.

Keyword: continuously monitor configuration (port 84 exposed) → Config Rules

24·14U24-Q14Udemy quiz · sec 24 · Q14

The application is hosted on a couple of EC2 instances in private subnets and is fronted by an Application Load Balancer in a public subnet. Which of the following can help the DevOps engineer to analyze those logs?

Correct: C. Why it is right

VPC Flow Logs already CloudWatch Logs e ache, tai Contributor Insights rule diye top 10 IP address ber kora jay: attack kina bojha shohoj.

Why the other options are wrong

  • A. Metric Stream metrics bahire (Firehose/3rd party) pathay; log analyze kore top IP ber kore na.
  • B. Alarm ekta metric threshold e notify kore; log er top contributor dekhay na.
  • D. Metric Filter ekta pattern count kore metric banay; kon IP sobcheye beshi request korche emon ranking (top-N) dey na.

Keyword: top IP addresses from VPC Flow Logs → Contributor Insights

একটি company-র AWS-এ একটি চলমান Serverless application আছে, যা application-এর ভেতরের বিভিন্ন service-এর মধ্যে inter-communication channel হিসেবে EventBridge ব্যবহার করে। কিছু test করার জন্য prod environment-এর event-গুলো dev environment-এ ব্যবহার করার একটি requirement আছে। Test-গুলো প্রতি 6 মাসে করা হবে, তাই event-গুলো store করে পরে ব্যবহার করতে হবে। EventBridge event store করে পরে ব্যবহার করার সবচেয়ে efficient ও cost-effective উপায় কোনটি?

Correct: A. Why it is right

EventBridge event bus e jawa event archive kora jay (sob ba filter kore, indefinitely ba nirdishto period), ar pore replay kora jay (PDF p. 600).

Built-in feature, kono custom code ba extra storage design lage na: tai most efficient ar cost-effective.

Why the other options are wrong

  • B. Lambda diye S3 e save korle custom code, maintenance, ar pore replay korar logic o nijeke likhte hobe. Built-in archive/replay thakte eta beshi kaaj.
  • C. EventBridge er DynamoDB te event store korar built-in option nai (direct target na); Lambda/custom code lagbe, ar replay o nije banate hobe.
