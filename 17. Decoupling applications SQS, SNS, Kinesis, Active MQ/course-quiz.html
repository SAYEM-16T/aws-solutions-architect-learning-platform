17·1U17-Q1Udemy quiz · sec 17 · Q1

You have an e-commerce website and you are preparing for Black Friday which is the biggest sale of the year. You expect that your traffic will increase by 100x. Your website already using an SQS Standard Queue, and you're running a fleet of EC2 instances in an Auto Scaling Group to consume SQS messages. What should you do to prepare your SQS Queue?

আপনার একটি e-commerce website আছে এবং আপনি Black Friday-র জন্য প্রস্তুতি নিচ্ছেন, যা বছরের সবচেয়ে বড় sale। আপনি আশা করছেন আপনার traffic 100x বাড়বে। আপনার website ইতিমধ্যে একটি SQS Standard Queue ব্যবহার করছে, এবং SQS message consume করতে আপনি একটি Auto Scaling Group-এ EC2 instance-এর একটি fleet চালাচ্ছেন। আপনার SQS Queue প্রস্তুত করতে আপনার কী করা উচিত?

Correct: D. Why it is right

SQS Standard fully managed, unlimited throughput ar queue te unlimited message (PDF p. 381). Tai traffic 100x holeo queue er jonno tomake kichui korte hoy na: SQS nije scale kore.

Scale korte hobe consumer side: ASG ta queue length (ApproximateNumberOfMessages) dekhe EC2 barabe (PDF p. 385, 392).

Why the other options are wrong

  • A. SQS e pre-warm bole kichu nai. Pre-warm purono ELB er concept; SQS ager thekei unlimited throughput dey.
  • B. SQS queue e Auto Scaling setting nai; queue nije-i scale kore. Auto Scaling hoy consumer EC2 der ASG te.
  • C. SQS queue er kono capacity setting nai (provision korte hoy na), throughput ar message count dui-i unlimited.

Keyword: SQS Standard + traffic 100x → do nothing, SQS scales automatically

17·2U17-Q2Udemy quiz · sec 17 · Q2

You have an SQS Queue where each consumer polls 10 messages at a time and finishes processing them in 1 minute. After a while, you noticed that the same SQS messages are received by different consumers resulting in your messages being processed more than once. What should you do to resolve this issue?

আপনার একটি SQS Queue আছে, যেখানে প্রতিটি consumer একবারে 10টি message poll করে এবং 1 মিনিটে সেগুলোর processing শেষ করে। কিছুক্ষণ পরে আপনি লক্ষ করলেন যে একই SQS message বিভিন্ন consumer receive করছে, ফলে আপনার message একাধিকবার process হচ্ছে। এই সমস্যা সমাধানে আপনার কী করা উচিত?

Correct: C. Why it is right

Consumer 10 ta message niye 1 minute dhore process kore, kintu default visibility timeout 30 s (PDF p. 388). 30 s por message delete hoy ni, tai abar visible hoye jay ar onno consumer o pay: duibar process.

Fix: visibility timeout barao processing time er cheye beshi (jemon 2 min). Process lomba hole consumer ChangeMessageVisibility call korte pare.

Why the other options are wrong

  • A. Long polling shudhu empty response ar API call komay (queue khali hole wait kore); receive korar por message lukano thake na.
  • B. DelaySeconds message queue te dhokar shomoy lukay (delay queue/timer); receive er por processing er shomoy duplicate atkay na.
  • D. Timeout komale message aro taratari abar visible hobe, duplicate processing aro barbe.

Keyword: same message different consumers + process 1 min → Visibility Timeout barao

Instructor feedback (English)

A: When SQS Long Polling is enabled, Amazon SQS reducing the number of empty responses when there are no messages available to return and eliminating false empty responses (when SQS messages are available but aren't included in a response).

B: SQS Delay Queues is a period of time during which Amazon SQS keeps new SQS messages invisible to consumers. In SQS Delay Queues, a message is hidden when it is first added to the queue. (default: 0 mins, max.: 15 mins)

C: SQS Visibility Timeout is a period of time during which Amazon SQS prevents other consumers from receiving and processing the message again. In Visibility Timeout, a message is hidden only after it is consumed from the queue. Increasing the Visibility Timeout gives more time to the consumer to process the message and prevent duplicate reading of the message. (default: 30 sec., min.: 0 sec., max.: 12 hours)

17·3U17-Q3Udemy quiz · sec 17 · Q3

Which SQS Queue type allows your messages to be processed exactly once and in order?

কোন SQS Queue type আপনার message-গুলোকে ঠিক একবার (exactly once) এবং order অনুযায়ী process হতে দেয়?

Correct: D. Why it is right

SQS FIFO = strict ordering (Message Group ID er bhitore) + exactly-once (Deduplication ID diye 5 min er moddhe duplicate remove) (PDF p. 391).

Throughput limited: 300 msg/s, batch e 3,000 msg/s; queue naam .fifo diye shesh hoy.

Why the other options are wrong

  • A. Standard queue at-least-once (duplicate hote pare) ar best-effort ordering; exactly-once ba strict order guarantee na.
  • B. DLQ alada queue jekhane bar bar fail kora message jay (debug er jonno); ordering ba exactly-once dey na.
  • C. Delay queue notun message ke kichukkhon (0-15 min) invisible rakhe; order ba dedup er sathe somporko nai.

Keyword: exactly once + in order → SQS FIFO

Instructor feedback (English)

A: SQS Standard Queue doesn't have ordering capability and doesn't guarantee to process your messages exactly once.

B: SQS Dead Letter Queue is where other SQS queues (source queues) can send messages that can't be processed (consumed) successfully. It's useful for debugging as it allows you to isolate problematic messages so you can debug why their processing doesn't succeed.

C: SQS Delay Queues is a period of time during which Amazon SQS keeps new SQS messages invisible to consumers. In SQS Delay Queues, a message is hidden when it is first added to the queue. (default: 0 mins, max.: 15 mins)

D: SQS FIFO (First-In-First-Out) Queues have all the capabilities of the SQS Standard Queue, plus the following two features. First, The order in which messages are sent and received are strictly preserved and a message is delivered once and remains available until a consumer process and deletes it. Second, duplicated messages are not introduced into the queue.

17·4U17-Q4Udemy quiz · sec 17 · Q4

You have 3 different applications that you'd like to send them the same message. All 3 applications are using SQS. What is the best approach would you choose?

আপনার 3টি ভিন্ন application আছে, যেগুলোতে আপনি একই message পাঠাতে চান। 3টি application-ই SQS ব্যবহার করছে। আপনি কোন approach-টিকে সবচেয়ে ভালো (best) হিসেবে বেছে নেবেন?

Correct: B. Why it is right

SNS + SQS fan-out: message ekbar SNS topic e publish koro, 3 ta SQS queue topic e subscribe kora, prottek queue ekta copy pay (PDF p. 401).

  • Fully decoupled, no data loss (SQS e persist, retry).
  • Pore notun app/queue add korte shudhu subscribe.
  • Queue er access policy te SNS ke write allow korte hobe.

Why the other options are wrong

  • A. SQS e "replication feature" bole kichu nai.
  • C. Producer nije 3 queue te alada alada pathale tightly coupled hoy, notun queue add korle code bodlate hoy, majhe crash korle kichu queue miss korte pare; scale kore na.

Keyword: same message to 3 apps all on SQS → SNS + SQS fan-out

Instructor feedback (English)

A: There's no such feature.

B: This is a common pattern where only one message is sent to the SNS topic and then "fan-out" to multiple SQS queues. This approach has the following features: it's fully decoupled, no data loss, and you have the ability to add more SQS queues (more applications) over time.

C: This is not a common pattern and doesn't scale well.

17·5U17-Q5Udemy quiz · sec 17 · Q5

You have a Kinesis data stream with 6 shards provisioned. This data stream usually receiving 5 MB/s of data and sending out 8 MB/s. Occasionally, your traffic spikes up to 2x and you get a ProvisionedThroughputExceeded exception. What should you do to resolve the issue?

আপনার একটি Kinesis data stream আছে, যাতে 6টি shard provisioned। এই data stream সাধারণত 5 MB/s data receive করে এবং 8 MB/s পাঠায়। মাঝে মাঝে আপনার traffic 2x পর্যন্ত spike করে এবং আপনি একটি ProvisionedThroughputExceeded exception পান। এই সমস্যা সমাধানে আপনার কী করা উচিত?

Correct: A. Why it is right

Provisioned mode e protita shard = 1 MB/s in, 2 MB/s out (PDF p. 409). 6 shard = 6 MB/s in, 12 MB/s out.

Normal 5 in / 8 out thik ache, kintu 2x spike e 10 MB/s in, 16 MB/s out lage → limit par, tai ProvisionedThroughputExceeded. Fix: shard barao (jemon 10+ shard). (On-demand mode o kaj korto, kintu option e nai.)

Why the other options are wrong

  • B. "Kinesis Replication" namer kono feature nai; ar replication throughput barato na.
  • C. SQS ke Kinesis er shamne buffer hishebe boshano bhalo design na; ordering/replay hariye jay, ar asol somossa shard capacity.

Keyword: 6 shards + 2x spike + ProvisionedThroughputExceeded → add shards

Instructor feedback (English)

A: The capacity limits of a Kinesis data stream are defined by the number of shards within the data stream. The limits can be exceeded by either data throughput or the number of reading data calls. Each shard allows for 1 MB/s incoming data and 2 MB/s outgoing data. You should increase the number of shards within your data stream to provide enough capacity.

B: Unfortunately, this feature doesn't exist!

C: This is not a good design.

17·6U17-Q6Udemy quiz · sec 17 · Q6

You have a website where you want to analyze clickstream data such as the sequence of clicks a user makes, the amount of time a user spends, and where the navigation begins and how it ends. You decided to use Amazon Kinesis, so you have configured the website to send these clickstream data all the way to a Kinesis data stream. While you checking the data sent to your Kinesis data stream, you found that the users' data is not ordered and the data for one individual user is spread across many shards. How would you fix this problem?

আপনার একটি website আছে, যেখানে আপনি clickstream data analyze করতে চান, যেমন একজন user কোন sequence-এ click করেন, একজন user কত সময় কাটান, এবং navigation কোথায় শুরু হয় ও কীভাবে শেষ হয়। আপনি Amazon Kinesis ব্যবহারের সিদ্ধান্ত নিয়েছেন, তাই website-কে এই clickstream data সরাসরি একটি Kinesis data stream-এ পাঠানোর জন্য configure করেছেন। আপনার Kinesis data stream-এ পাঠানো data check করার সময় আপনি দেখলেন যে user-দের data ordered নয় এবং একজন user-এর data অনেকগুলো shard-এ ছড়িয়ে আছে। আপনি এই সমস্যা কীভাবে ঠিক করবেন?

Correct: C. Why it is right

Kinesis record er partition key dekhe thik kore kon shard e jabe. Same partition key → same shard, ar ek shard er bhitore data order e thake (PDF p. 408).

Tai partition key = user ID dile ek user er shob click ek shard e, order e thakbe, ar onek shard diye scale o korte parbe.

Why the other options are wrong

  • A. 1 shard e total order paoya jay, kintu throughput 1 MB/s e atke jay; scale korte parbe na.
  • B. Ek consumer diye re-order korle scale kore na, ar asol problem consumer na, record onek shard e chhoriye pora (partition key).

Keyword: one user er data many shards e + not ordered → partition key = user identity

Instructor feedback (English)

A: Using 1 shard would guarantee total ordering but wouldn't allow us to scale.

B: This wouldn't allow us to scale.

C: Kinesis Data Stream uses the partition key associated with each data record to determine which shard a given data record belongs to. When you use the identity of each user as the partition key, this ensures the data for each user is ordered hence sent to the same shard.

17·7U17-Q7Udemy quiz · sec 17 · Q7

You are running an application that produces a large amount of real-time data that you want to load into S3 and Redshift. Also, these data need to be transformed before being delivered to their destination. What is the best architecture would you choose?

আপনি এমন একটি application চালাচ্ছেন যা বিপুল পরিমাণ real-time data তৈরি করে, যা আপনি S3 ও Redshift-এ load করতে চান। এছাড়া এই data destination-এ deliver হওয়ার আগে transform করতে হবে। আপনি কোন architecture-কে সবচেয়ে ভালো (best) হিসেবে বেছে নেবেন?

Renamed: Kinesis Data Firehose -> Amazon Data Firehose (the answer is the same).

Correct: C. Why it is right

Kinesis Data Streams real-time data ingest kore; Firehose sheta S3 ar Redshift e load kore, ar Lambda diye transform korte pare (PDF p. 410-412).

Tai "real-time data + transform + S3/Redshift e load" = KDS + Firehose. Note: Kinesis Data Firehose er naam ekhon Amazon Data Firehose (Feb 2024), shudhu naam bodleche.

Why the other options are wrong

  • A. SQS + Lambda diye nije code likhe S3/Redshift e likhte hobe; SQS er S3/Redshift er sathe direct integration nai, ar streaming big data er jonno na.
  • B. SNS + HTTP endpoint notification push kore; S3/Redshift e load ba transform er built-in way nai.

Keyword: large real-time data + transform + load into S3 and Redshift → KDS + Firehose

Instructor feedback (English)

A: This doesn't have a direct integration with S3 or Redshift.

B: This doesn't have a direct integration with S3 or Redshift.

C: This is a perfect combo of technology for loading data near real-time data into S3 and Redshift. Kinesis Data Firehose supports custom data transformations using AWS Lambda.

নিচের কোনটি AWS SNS-এর একটি supported subscriber নয় (NOT)?

17·9U17-Q9Udemy quiz · sec 17 · Q9

Which AWS service helps you when you want to send email notifications to your users?

আপনি যখন user-দের email notification পাঠাতে চান, তখন কোন AWS service আপনাকে সাহায্য করে?

Correct: B. Why it is right

SNS e email subscription built-in: topic e publish korle email subscriber ra mail pay (PDF p. 397; hands-on e email subscription confirm kore dekhano).

One-to-many notification (email/SMS/mobile push) = SNS.

Why the other options are wrong

  • A. SQS + Lambda diye email pathate gele nije code likhe SNS er feature abar banate hobe; SQS nijei email pathay na.
  • C. Kinesis streaming data er jonno; email pathate pare na, consumer chain kore oi SNS er moto kichu banate hobe.

Keyword: send email notifications to users → SNS

Instructor feedback (English)

A: You would be re-implementing a feature from SNS.

C: Amazon Kinesis on its own can not send emails. You would need to chain it with a consumer, and in the end, you would re-create something like SNS.

17·10U17-Q10Udemy quiz · sec 17 · Q10

You're running many micro-services applications on-premises and they communicate using a message broker that supports MQTT protocol. You're planning to migrate these applications to AWS without re-engineering the applications and modifying the code. Which AWS service allows you to get a managed message broker that supports the MQTT protocol?

আপনি on-premises-এ অনেক micro-services application চালাচ্ছেন এবং সেগুলো MQTT protocol support করে এমন একটি message broker ব্যবহার করে communicate করে। আপনি application re-engineer না করে এবং code modify না করে এই application-গুলো AWS-এ migrate করার পরিকল্পনা করছেন। কোন AWS service আপনাকে MQTT protocol support করে এমন একটি managed message broker দেয়?

Correct: D. Why it is right

On-premises app MQTT (open protocol) broker use kore, ar code na bodlai migrate korte chay → Amazon MQ (PDF p. 414).

Amazon MQ = managed RabbitMQ / ActiveMQ broker: MQTT, AMQP, STOMP, Openwire, WSS support kore. SQS/SNS cloud-native AWS API, oigulote gele app re-engineer korte hoto.

Why the other options are wrong

  • A. SQS AWS er nijer API use kore, MQTT support kore na; app code bodlate hobe.
  • B. SNS o AWS proprietary API, MQTT broker na; re-engineering lagbe.
  • C. Kinesis streaming service, MQTT message broker na.

Keyword: MQTT + without re-engineering / modifying code → Amazon MQ

Instructor feedback (English)

A: Amazon SQS does not support the MQTT protocol.

B: Amazon SNS does not support the MQTT protocol.

C: Amazon Kinesis does not support the MQTT protocol.

D: Amazon MQ supports industry-standard APIs such as JMS and NMS, and protocols for messaging, including AMQP, STOMP, MQTT, and WebSocket.

17·11U17-Q11Udemy quiz · sec 17 · Q11

An e-commerce company is preparing for a big marketing promotion that will bring millions of transactions. Their website is hosted on EC2 instances in an Auto Scaling Group and they are using Amazon Aurora as their database. The Aurora database has a bottleneck and a lot of transactions have been failed in the last promotion they have made as they had a lot of transaction and the Aurora database wasn’t prepared to handle these too many transactions. What do you recommend to handle those transactions and prevent any failed transactions?

একটি e-commerce company একটি বড় marketing promotion-এর প্রস্তুতি নিচ্ছে, যা লক্ষ লক্ষ transaction নিয়ে আসবে। তাদের website একটি Auto Scaling Group-এর EC2 instance-এ hosted এবং তারা database হিসেবে Amazon Aurora ব্যবহার করছে। Aurora database-এ একটি bottleneck আছে, এবং তাদের আগের promotion-এ অনেক transaction fail হয়েছিল, কারণ transaction অনেক বেশি ছিল এবং Aurora database এত বেশি transaction handle করার জন্য প্রস্তুত ছিল না। এই transaction-গুলো handle করতে এবং কোনো failed transaction ঠেকাতে আপনি কী recommend করবেন?

Correct: A. Why it is right

Course er common pattern: SQS as a buffer to database writes (PDF p. 394). App transaction shorashori Aurora te na likhe SQS e pathay; SQS infinitely scalable, message durably thake.

Alada worker (ASG) dequeue kore Aurora te insert kore, insert confirm hole message delete kore. Tai spike e transaction fail/harabe na, queue te wait korbe.

Why the other options are wrong

  • B. Fargate e website nile shudhu compute bodlay; bottleneck Aurora te, DB te ek-i spike jabe, transaction fail hobe.
  • C. RDS for SQL Server e migrate korle o ek-i somossa (Aurora theke beshi bhalo na); write spike buffer hoy na.

Keyword: Aurora bottleneck + millions of transactions + prevent failed transactions → SQS buffer

17·12U17-Q12Udemy quiz · sec 17 · Q12

A company is using Amazon Kinesis Data Streams to ingest clickstream data and then do some analytical processes on it. There is a campaign in the next few days and the traffic is unpredictable which might grow up to 100x. What Kinesis Data Stream capacity mode do you recommend?

একটি company clickstream data ingest করে তার ওপর কিছু analytical process চালাতে Amazon Kinesis Data Streams ব্যবহার করছে। আগামী কয়েক দিনের মধ্যে একটি campaign আছে এবং traffic অনুমান করা যায় না, যা 100x পর্যন্ত বাড়তে পারে। আপনি কোন Kinesis Data Stream capacity mode recommend করবেন?

Correct: B. Why it is right

On-demand mode e shard provision/manage korte hoy na; gato 30 din er observed peak er upor automatically scale kore (default 4 MB/s ba 4,000 records/s write) (PDF p. 409).

"Traffic unpredictable, 100x hote pare" = on-demand er textbook case. Provisioned e nije shard hishab ar manually barate hoy.

Why the other options are wrong

  • A. Provisioned mode e shard shonkha nije thik korte hoy ar manually scale korte hoy; unpredictable 100x spike e ProvisionedThroughputExceeded hobe.

Keyword: unpredictable traffic, 100x → On-demand mode
