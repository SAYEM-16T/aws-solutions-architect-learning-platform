Synchronous vs asynchronous (event based) communication

Shohoj kore (restaurant): Waiter jodi order niye nije kitchen e dariye thake jotokkhon rana na hoy (synchronous), bhir hole sob atke jay. Tar bodole waiter order slip ekta hook e jhulay (queue), radhuni nijer gotite slip tule ney (asynchronous). Waiter ar radhuni ekhon decoupled: keu karo jonno wait kore na, ar duijon alada bhabe barano jay.

1) Synchronous (application to application)
Buying Service→ direct call Shipping Service
2) Asynchronous / event based (application to queue to application)
Buying Service→ put Queue→ poll Shipping Service

Async e buying ar shipping service shorashori jora na; majhe middleware (queue).

  • Onek app deploy korle tader nijeder moddhe communicate korte hobei.
  • Synchronous er somossa: hothat traffic spike. Example: shadharonoto 10 ta video encode hoy, hothat 1000 ta → encoding service overwhelmed, outage.
  • Tai app decouple koro, decoupling layer nije scale korbe:
ServiceModel
SQSQueue model
SNSPub/sub model
KinesisReal-time streaming model (big data)

Ei service gulo amader app theke alada (independently) scale kore, ar khub bhalo scale kore.

Exam: "Decouple", "sudden spike", "requests are lost", "tightly coupled monolith" → asynchronous messaging (shadharonoto SQS). Queue = SQS, pub/sub = SNS, real-time stream = Kinesis.

Lecture 4 · SQS - Message Visibility Timeout · PDF p. 388-389 (part p. 12-13)

Visibility timeout: receive korar por message kichukkhon lukano thake

Shohoj kore (library book): Tumi ekta boi (message) tulle, library 30 minute er jonno boi ta onnoder list theke lukiye rakhe. 30 min er moddhe ferot dile (delete) shesh. Na dile boi abar shelf e chole ashe, onno keu niye nite pare: ek-i boi dui jon porlo (duplicate). Beshi shomoy lagle librarian ke bolo "aro shomoy dao" = ChangeMessageVisibility.

Visibility timeline (time bam theke dane)
ReceiveMessagemessage returned→ Visibility timeoutdefault 30 s→ Onno ReceiveMessagenot returned→ timeout shesh, delete hoy ni ReceiveMessagemessage returned (again)

Timeout er moddhe delete korle message ar fire ashe na.

  • Consumer poll korle message onno consumer der kache invisible hoye jay.
  • Default message visibility timeout = 30 seconds → message process korte 30 s shomoy.
  • Timeout shesh, kintu message delete hoy ni → message abar "visible", onno (ba same) consumer abar pabe.
  • Timeout er moddhe process na hole message duibar process hote pare.
  • Consumer jane aro shomoy lagbe → ChangeMessageVisibility API call kore oi message er timeout barao.

Hands-on (same lecture)

  • Duita "send and receive" window = duita consumer. Window 1 poll → message pelo. Window 2 poll → kichu nai (visibility window er bhitore).
  • 30 s por window 2 e message elo (receive count 2). Tarpor delete.
  • Queue edit e visibility timeout 0 seconds theke 12 hours set kora jay (0 recommended na).

Dead Letter Queue (DLQ) amar jana, course e nai

Course hands-on e shudhu "redrive / dead-letter queue" option ta dekhano hoyeche. Official docs theke:

  • DLQ = ekta alada queue, jekhane source queue er process hote na para message chole jay → debug, isolate kora jay.
  • Redrive policy e maxReceiveCount: ek message koto bar receive hole DLQ te jabe (console e 1-1,000). Visibility timeout shesh hoye bar bar fire ashle receive count bare.
  • DLQ ar source queue same account + same Region. FIFO queue er DLQ FIFO, standard er DLQ standard.
  • Standard queue e retention gona hoy original enqueue time theke → DLQ er retention source er cheye beshi rakho.
  • DLQ redrive diye message abar source queue e ferot pathano jay (fix er por).

Source: Using dead-letter queues in Amazon SQS, Configure a dead-letter queue

Exam:
  • Process 1 min lage, ek-i message onno consumer o pacche → visibility timeout barao (U17-Q2). Long polling ba DelaySeconds noy.
  • "Period during which SQS prevents other consumers from receiving a message" → Visibility Timeout (B5-Q25).
  • EC2 message niye 5 min por crash → timeout shesh hole message abar available onno instance er jonno (B5-Q59).
  • Orders er cheye beshi email → consumer delete korche na (B1-Q15, B2-Q58, S2-Q25).
  • "Poison message", "bar bar fail kora message alada koro" → DLQ (maxReceiveCount).
