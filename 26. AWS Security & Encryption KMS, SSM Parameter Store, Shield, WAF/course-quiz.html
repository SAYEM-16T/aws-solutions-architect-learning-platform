In-flight Encryption (In-Transit Encryption) enable করতে, আমাদের থাকতে হবে ........................

Correct: B. Why it is right

Eta hoy TLS/SSL diye, mane HTTPS. Ar HTTPS endpoint chalu korte ekta SSL/TLS certificate lagbei.

Keyword: In-flight encryption → HTTPS + SSL/TLS certificate

Instructor feedback (English)

B: In-flight Encryption = HTTPS, and HTTPS can not be enabled without an SSL certificate.

Server-Side Encryption means that the data is sent encrypted to the server.

Server-side encryption at rest e data server receive korar pore server nije encrypt kore, ar pathanor age decrypt kore (PDF p. 653).

Tumi data plain (HTTPS diye) pathao; agei encrypt kore pathano holo client-side encryption. Tai statement ta False.

Why the other options are wrong

  • A. Bhul: data age theke encrypt kore pathano client-side encryption er kaaj. Server-side e server nije receive korar por encrypt kore.

Keyword: Server-Side Encryption → server receive korar por encrypt kore → False

Instructor feedback (English)

B: Server-Side Encryption means the server will encrypt the data for us. We don't need to encrypt it beforehand.

26·3U26-Q3Udemy quiz · sec 26 · Q3

In Server-Side Encryption, where do the encryption and decryption happen?

Server-Side Encryption-এ encryption এবং decryption কোথায় ঘটে?

Correct: A. Why it is right

Server-side encryption e key server er kache (ba server er access ache, jemon S3 + data key). Tai encrypt o server kore, decrypt o server kore pathanor age (PDF p. 653).

Client er hate key thake na, tai client nije kichu encrypt/decrypt kore na.

Why the other options are wrong

  • B. Dutoi client e hole seta client-side encryption, server-side na.
  • C. Client er kache server er key nai, tai client decrypt korte parbe na; server-i decrypt kore pathay.
  • D. Client encrypt korle server er kache oi key nai, server decrypt korte parbe na. Eta mixed model, server-side encryption na.

Keyword: Server-Side Encryption → encrypt + decrypt dutoi server e

Instructor feedback (English)

A: In Server-Side Encryption, we can't do encryption/decryption ourselves as we don't have access to the corresponding encryption key.

Client-side encryption e client nije encrypt kore pathay, server shudhu encrypted object store kore, kokhono decrypt kore na (PDF p. 654).

Server ke tai encryption scheme ba key janar dorkar nai. Je kono storage (FTP, S3...) e rakha jay. Tai statement False.

  • B. Bhul: server ekhane kono encrypt/decrypt kore na, shudhu bytes store kore. Scheme jana lage na; server decrypt korte parbe na eta-i uddesho.

Keyword: Client-Side → server shudhu store kore, scheme jane na → False

Instructor feedback (English)

A: With Client-Side Encryption, the server doesn't need to know any information about the encryption scheme being used, as the server will not perform any encryption or decryption operations.

26·6U26-Q6Udemy quiz · sec 26 · Q6

AWS KMS supports both symmetric and asymmetric KMS keys.

AWS KMS symmetric এবং asymmetric দুই ধরনের KMS key-ই support করে।

Correct: A. Why it is right

KMS dui type key support kore (PDF p. 656):

  • Symmetric (AES-256): ek key diye encrypt + decrypt; AWS service gulo eta use kore.
  • Asymmetric (RSA, ECC pair): public key download kora jay, encrypt/decrypt ba sign/verify er jonno.

Why the other options are wrong

  • B. Bhul: KMS symmetric (AES-256) ar asymmetric (RSA/ECC) dutoi support kore.

Keyword: symmetric and asymmetric KMS keys → True

Instructor feedback (English)

A: KMS keys can be symmetric or asymmetric. A symmetric KMS key represents a 256-bit key used for encryption and decryption. An asymmetric KMS key represents an RSA key pair used for encryption and decryption or signing and verification, but not both. Or it represents an elliptic curve (ECC) key pair used for signing and verification.
