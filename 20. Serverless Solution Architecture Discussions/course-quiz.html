20·1U20-Q1Udemy quiz · sec 20 · Q1

A startup company plans to run its application on AWS. As a solutions architect, the company hired you to design and implement a fully Serverless REST API. Which technology stack do you recommend?

একটি startup company AWS-এ তার application চালানোর পরিকল্পনা করছে। একটি সম্পূর্ণ Serverless REST API design ও implement করতে company আপনাকে একজন solutions architect হিসেবে নিয়োগ দিয়েছে। আপনি কোন technology stack recommend করবেন?

Correct: A. Why it is right

Fully serverless REST API er classic stack = API Gateway + Lambda (data lagle DynamoDB). API Gateway HTTPS REST endpoint dey, Lambda ke invoke kore; duita-i AWS manage kore, auto scale kore, pay per usage.

MyTodoList ar MyBlog.com duitai ei pattern e shuru (PDF p. 496, PDF p. 504).

Why the other options are wrong

  • B. EC2 serverless na: instance tumi provision, patch, scale koro. ALB thakleo backend server-based.
  • C. ECS (EC2 launch type) ar EBS volume duita-i server / capacity manage kora jinish, serverless na.
  • D. CloudFront + S3 serverless thik, kintu shudhu static content serve kore; API er dynamic logic chalate pare na.

Keyword: fully Serverless REST API → API Gateway + Lambda

Instructor feedback (English)

A: This is fully serverless.

B: EC2 is not serverless.

C: Both ECS and EBS are not serverless.

D: This is serverless but it won't help as you want to create an API. This combination allows you to distribute the static part of your application globally.

20·2U20-Q2Udemy quiz · sec 20 · Q2

The following AWS services have an out of the box caching feature, EXCEPT .................

নিচের AWS service-গুলোর out of the box caching feature আছে, শুধু ................. ছাড়া (EXCEPT)। অর্থাৎ কোনটির নেই?

Correct: B. Why it is right

Lambda er kono out-of-the-box response cache nai. Tai EXCEPT er uttor Lambda.

  • API Gateway: stage e response caching on kora jay, hit hole Lambda call-i hoy na (MyTodoList, PDF p. 499).
  • DynamoDB: DAX = in-memory cache, microsecond latency (PDF p. 498).

Why the other options are wrong

  • A. API Gateway e built-in caching ache: stage level e response TTL porjonto cache kore.
  • C. DynamoDB er built-in cache ache: DAX (DynamoDB Accelerator), same API, read cache kore.

Keyword: out of the box caching, EXCEPT → Lambda (API Gateway cache ache, DynamoDB e DAX ache)

Instructor feedback (English)

A: You can enable API caching in Amazon API Gateway to cache your endpoint's responses. With caching, you can reduce the number of calls made to your endpoint and also improve the latency of requests to your API. When you enable caching for a stage, API Gateway caches responses from your endpoint for a specified time-to-live (TTL) period, in seconds. API Gateway then responds to the request by looking up the endpoint response from the cache instead of making a request to your endpoint.

B: Lambda does not have an out-of-the-box caching feature.

C: Amazon DynamoDB Accelerator (DAX) is a fully managed, highly available, in-memory cache for DynamoDB that delivers up to a 10x performance improvement – from milliseconds to microseconds – even at millions of requests per second. DAX does all the heavy lifting required to add in-memory acceleration to your DynamoDB tables, without requiring developers to manage cache invalidation, data population, or cluster management.

20·3U20-Q3Udemy quiz · sec 20 · Q3

You have a lot of static files stored in an S3 bucket that you want to distribute globally to your users. Which AWS service should you use?

আপনার একটি S3 bucket-এ প্রচুর static file store করা আছে, যেগুলো আপনি আপনার user-দের কাছে globally distribute করতে চান। আপনার কোন AWS service ব্যবহার করা উচিত?

Correct: B. Why it is right

S3 bucket ekta region e thake. Sara prithibir user ke druto dite CloudFront (CDN): edge location e static file cache kore, user kachakachi edge theke pay.

MyBlog.com er prothom dhap thik eta: S3 + CloudFront (PDF p. 502).

Why the other options are wrong

  • A. S3 CRR pura bucket onno region e copy kore; kaj korbe kintu onek copy, onek region, beshi dam, ar eta CDN na.
  • C. Route 53 shudhu DNS; content distribute ba cache kore na.
  • D. API Gateway API expose kore (dynamic content), S3 er static file global distribution er jonno na.

Keyword: static files in S3 + distribute globally → CloudFront

Instructor feedback (English)

A: S3 CRR enables automatic, asynchronous copying of objects across S3 buckets. This would work but it would be expensive as you'll have multiple copies of data in different S3 buckets around the globe.

B: Amazon CloudFront is a fast content delivery network (CDN) service that securely delivers data, videos, applications, and APIs to customers globally with low latency, high transfer speeds. This is a perfect use case for Amazon CloudFront.

C: Amazon Route 53 is a highly available and scalable Domain Name System (DNS) service.

D: Amazon API Gateway is a fully managed service that makes it easy to create, publish, maintain, monitor, and secure APIs at any scale. You can create REST APIs and WebSocket APIs. It helps you expose dynamic content, not static content from S3.

You have created a DynamoDB table in ap-northeast-1 and would like to make it available in eu-west-1, so you decided to create a DynamoDB Global Table. What needs to be enabled first before you create a DynamoDB Global Table?

আপনি ap-northeast-1-এ একটি DynamoDB table তৈরি করেছেন এবং এটিকে eu-west-1-এ available করতে চান, তাই আপনি একটি DynamoDB Global Table তৈরি করার সিদ্ধান্ত নিয়েছেন। একটি DynamoDB Global Table তৈরি করার আগে প্রথমে কী enable করতে হবে?

⚠ Outdated: Ekhon global table (version 2019.11.21) e replica add korle MREC mode e DynamoDB nijei Streams on kore rakhe (off kora jay na), ar MRSC mode Streams use-i kore na. Tai age theke manually Streams enable korar dorkar nai. Course/exam er answer ekhono 'DynamoDB Streams'. source

Correct: A. Why it is right

Course (Section 19, PDF p. 477) bole: Global Table er pre-requisite holo DynamoDB Streams. Streams table er change log dey, sei change onno region er replica te replicate hoy. Exam answer: DynamoDB Streams.

Ajker din e: current version (2019.11.21) e MREC global table e DynamoDB nijei sob replica te Streams on rakhe (off kora jay na), ar MRSC mode Streams use-i kore na, tai manually age enable korar dorkar nai.

Why the other options are wrong

  • B. DAX shudhu read cache; replication er sathe somporko nai.
  • C. DynamoDB te "Versioning" bole kono feature nai (eta S3 er feature).
  • D. Backup (on-demand / PITR) disaster recovery er jonno; Global Table er prerequisite na.

Keyword: enabled first before Global Table → DynamoDB Streams (course answer)

Instructor feedback (English)

A: DynamoDB Streams enable DynamoDB to get a changelog and use that changelog to replicate data across replica tables in other AWS Regions.

B: Amazon DynamoDB Accelerator (DAX) is a fully managed, highly available, in-memory cache for DynamoDB that delivers up to a 10x performance improvement – from milliseconds to microseconds – even at millions of requests per second. DAX does all the heavy lifting required to add in-memory acceleration to your DynamoDB tables, without requiring developers to manage cache invalidation, data population, or cluster management.

C: There's no such feature.

D: Amazon DynamoDB provides the on-demand backup capability to create full backups of your tables for long-term retention and archival for regulatory compliance needs.

20·5U20-Q5Udemy quiz · sec 20 · Q5

You have configured a Lambda function to run each time an item is added to a DynamoDB table using DynamoDB Streams. The function is meant to insert messages into the SQS queue for further long processing jobs. Each time the Lambda function is invoked, it seems able to read from the DynamoDB Stream but it isn't able to insert the messages into the SQS queue. What do you think the problem is?

আপনি DynamoDB Streams ব্যবহার করে একটি DynamoDB table-এ প্রতিবার একটি item যোগ হলে চলার জন্য একটি Lambda function configure করেছেন। function-টির উদ্দেশ্য হলো পরবর্তী দীর্ঘ processing job-এর জন্য SQS queue-তে message insert করা। প্রতিবার Lambda function invoke হলে মনে হয় এটি DynamoDB Stream থেকে read করতে পারছে, কিন্তু SQS queue-তে message insert করতে পারছে না। আপনার মতে সমস্যাটি কী?

Correct: B. Why it is right

Lambda onno AWS service (SQS, SES, S3...) call kore tar execution IAM role diye. Stream pora kaj korche, tar mane trigger thik; kintu SQS e SendMessage fail → role e SQS permission nai.

MyBlog.com er welcome email flow e o same: Lambda er IAM role e SES allow thakte hoy (PDF p. 506).

Why the other options are wrong

  • A. Lambda khub bhalo bhabe SQS e message pathate pare (SDK diye); EC2 lage na.
  • C. SQS API call er jonno security group e SQS ke point kora jay na; default Lambda outbound internet access thake, tai SG problem na.
  • D. SQS queue te kono security group attach hoy na; access control hoy IAM / queue policy diye.

Keyword: read from stream works kintu can't insert into SQS → Lambda execution role e permission nai

Instructor feedback (English)

A: AWS Lambda is a perfect fit with SQS.

C: Security Groups can not point to SQS queues.

D: Security Groups can not be attached to SQS queues.

20·6U20-Q6Udemy quiz · sec 20 · Q6

You would like to create an architecture for a micro-services application whose sole purpose is to encode videos stored in an S3 bucket and store the encoded videos back into an S3 bucket. You would like to make this micro-services application reliable and has the ability to retry upon failures. Each video may take over 25 minutes to be processed. The services used in the architecture should be asynchronous and should have the capability to be stopped for a day and resume the next day from the videos that haven't been encoded yet. Which of the following AWS services would you recommend in this scenario?

আপনি একটি micro-services application-এর জন্য একটি architecture তৈরি করতে চান, যার একমাত্র উদ্দেশ্য হলো একটি S3 bucket-এ store করা video encode করা এবং encode করা video আবার একটি S3 bucket-এ store করা। আপনি এই micro-services application-কে reliable করতে চান এবং failure হলে retry করার সক্ষমতা রাখতে চান। প্রতিটি video process হতে 25 মিনিটের বেশি সময় লাগতে পারে। architecture-এ ব্যবহৃত service-গুলো asynchronous হওয়া উচিত এবং একদিনের জন্য stop করে পরদিন এখনো encode না হওয়া video থেকে resume করার সক্ষমতা থাকা উচিত। এই scenario-তে নিচের কোন AWS service-গুলো আপনি recommend করবেন?

Correct: C. Why it is right

  • Protita video > 25 min → Lambda bad, karon Lambda max 15 min (Section 19). Tai worker hobe EC2.
  • Async, reliable, retry, ar ekdin bondho rekhe porer din baki gulo theke shuru → SQS: message queue te thake (14 din porjonto), worker na thakleo harabe na; process fail hole message abar visible hoy, retry hoy.

Tai SQS + EC2: microservice er async pattern (PDF p. 511).

Why the other options are wrong

  • A. S3 event Lambda ke sathe sathe trigger kore, porer din e postpone kora jay na; ar Lambda 15 min er beshi chalte pare na.
  • B. SNS push kore, message dhore rakhe na; EC2 bondho thakle message hariye jay, queue te ferot diye retry o nai.
  • D. SQS thik, kintu Lambda er max execution time 15 min; 25 min er encoding sesh hobe na.

Keyword: over 25 minutes + retry, stopped for a day and resume → SQS + EC2

Instructor feedback (English)

A: When using a Lambda function with S3, the Lambda function would need to be triggered immediately and can't be postponed until tomorrow to be run.

B: Amazon SNS won't allow us to retry by putting back a message into a queue in case of EC2 failures.

C: Amazon SQS allows you to retain messages for days and process them later, while we can take down our EC2 instances.

D: This would work, but it can't be used in this scenario as the maximum execution time for a Lambda function is 15 minutes.

20·7U20-Q7Udemy quiz · sec 20 · Q7

You are running a photo-sharing website where your images are downloaded from all over the world. Every month you publish a master pack of beautiful mountain images that are over 15 GB in size. The content is currently hosted on an Elastic File System (EFS) file system and distributed by an Application Load Balancer and a set of EC2 instances. Each month, you are experiencing very high traffic which increases the load on your EC2 instances and increases network costs. What do you recommend to reduce EC2 load and network costs without refactoring your website?

আপনি একটি photo-sharing website চালাচ্ছেন, যেখানে আপনার image-গুলো সারা বিশ্ব থেকে download করা হয়। প্রতি মাসে আপনি সুন্দর mountain image-এর একটি master pack publish করেন, যার size 15 GB-এর বেশি। content বর্তমানে একটি Elastic File System (EFS) file system-এ host করা এবং একটি Application Load Balancer ও EC2 instance-এর একটি set দিয়ে distribute করা হয়। প্রতি মাসে আপনি অনেক বেশি traffic পাচ্ছেন, যা আপনার EC2 instance-এর load বাড়ায় এবং network খরচ বাড়ায়। আপনার website refactor না করে EC2 load এবং network খরচ কমাতে আপনি কী recommend করবেন?

Correct: D. Why it is right

Eta "software updates offloading" lecture er hubohu scenario (PDF p. 512-515): EC2 + ALB + EFS theke boro static file, monthly spike, EC2 load ar network cost beshi, ar refactor kora jabe na.

Solution: ALB er shamne CloudFront distribution. File edge e cache hoy, beshi request EC2 porjonto jay na → EC2 load ar network cost kome, app e kono change nai.

Why the other options are wrong

  • A. S3 e host korle app / link bodlate hobe (refactor), ar CloudFront chara S3 theke-o network cost beshi thakbe.
  • B. ALB te kono caching feature nai.
  • C. Boro instance = aro EC2 cost; network cost o komche na.

Keyword: static big pack + reduce EC2 load and network costs + without refactoring → CloudFront

Instructor feedback (English)

A: This would work, but it will require some kind of application refactoring. And you still may have high network costs.

B: This feature does not exist.

C: This would include higher costs for EC2 instances, and you still have high network costs.

D: Amazon CloudFront is a fast content delivery network (CDN) service that securely delivers data, videos, applications, and APIs to customers globally with low latency, high transfer speeds. Amazon CloudFront can be used in front of an Application Load Balancer.

20·8U20-Q8Udemy quiz · sec 20 · Q8

An AWS service allows you to capture gigabytes of data per second in real-time and deliver these data to multiple consuming applications, with a replay feature.

একটি AWS service আপনাকে real-time-এ প্রতি সেকেন্ডে gigabytes data capture করতে এবং এই data একাধিক consuming application-এ deliver করতে দেয়, একটি replay feature সহ।

Correct: A. Why it is right

Kinesis Data Streams: real-time e GB/s data capture kore, data retain kore (365 din porjonto, Section 17), tai replay kora jay, ar onek consumer same data porte pare.

Microservice er async pattern e Kinesis o ache (PDF p. 511).

Why the other options are wrong

  • B. S3 object storage; real-time stream capture, multiple consumer e deliver, replay er feature nai.
  • C. Amazon MQ managed message broker (ActiveMQ / RabbitMQ), purono protocol er app migrate korte; GB/s real-time streaming ar replay er jonno na.

Keyword: gigabytes per second, real-time + multiple consumers + replay → Kinesis Data Streams

Instructor feedback (English)

A: Amazon Kinesis Data Streams (KDS) is a massively scalable and durable real-time data streaming service. It can continuously capture gigabytes of data per second from hundreds of sources such as website clickstreams, database event streams, financial transactions, social media feeds, IT logs, and location-tracking events.

B: Amazon S3 is an object storage service and does not provide replay features.

C: Amazon MQ is a managed message broker service for Apache ActiveMQ and RabbitMQ that makes it easy to set up and operate message brokers on AWS. It's a replacement for Amazon SQS in case you need to support other protocols such as MQTT.
