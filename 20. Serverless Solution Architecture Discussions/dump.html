20·1D-Q21SAA-C03 dump · Q21

An ecommerce company wants to launch a one-deal-a-day website on AWS. Each day will feature exactly one product on sale for a period of 24 hours. The company wants to be able to handle millions of requests each hour with millisecond latency during peak hours. Which solution will meet these requirements with the LEAST operational overhead?

একটি ecommerce company AWS-এ একটি one-deal-a-day website launch করতে চায়। প্রতিদিন ঠিক একটি product 24 ঘণ্টার জন্য sale-এ থাকবে। company peak hour-এ millisecond latency সহ প্রতি ঘণ্টায় লক্ষ লক্ষ (millions) request handle করতে সক্ষম হতে চায়। কোন solution সবচেয়ে কম operational overhead (LEAST operational overhead)-এ এই requirement পূরণ করবে?

Correct: D. Why it is right

Puro serverless stack: S3 te static content, samne CloudFront cache (global, low latency), backend API er jonno API Gateway + Lambda, data DynamoDB te (millisecond latency, automatic scale). Kono server manage korte hoy na, tai LEAST operational overhead.

Eta course er "Serverless hosted website" architecture (PDF p. 501).

Why the other options are wrong

  • A. S3 shudhu static file serve kore, dynamic backend/API chalate pare na; order data S3 te rakha transactional na.
  • B. EC2 + ASG + 2 ta ALB + RDS kaj korbe kintu server, patching, scaling manage korte hoy; operational overhead beshi.
  • C. EKS cluster, pod autoscaler ar RDS manage kora onek kaj; serverless option er cheye overhead beshi.

Keyword: millions of requests + millisecond latency + LEAST operational overhead → S3 + CloudFront + API Gateway + Lambda + DynamoDB

Dump explanation (English)

To launch a one-deal-a-day website on AWS with millisecond latency during peak hours and with the least operational overhead, the best option is to use an Amazon S3 bucket to host the website's static content, deploy an Amazon CloudFront distribution, set the S3 bucket as the origin, use Amazon API Gateway and AWS Lambda functions for the backend APIs, and store the data in Amazon DynamoDB. This option requires minimal operational overhead and can handle millions of requests each hour with millisecond latency during peak hours. Therefore, option D is the correct answer. Reference: https: //aws.amazon.com/blogs/compute/building-a-serverless-multi-player-game-with-aws- lambda-and-amazon-dynamodb/

20·2D-Q213SAA-C03 dump · Q213

A company is building a new dynamic ordering website. The company wants to minimize server maintenance and patching. The website must be highly available and must scale read and write capacity as quickly as possible to meet changes in user demand. Which solution will meet these requirements?

একটি company একটি নতুন dynamic ordering website তৈরি করছে। company server maintenance এবং patching কমাতে চায়। website-কে highly available হতে হবে এবং user demand-এর পরিবর্তন মেটাতে যত দ্রুত সম্ভব read ও write capacity scale করতে হবে। কোন solution এই requirement পূরণ করবে?

Correct: A. Why it is right

Minimize server maintenance and patching → serverless: static content S3 + CloudFront, dynamic API Gateway + Lambda. Database DynamoDB on-demand: read ar write capacity duita-i instantly demand onujayi scale kore, capacity plan lage na. Sob managed ar highly available.

Why the other options are wrong

  • B. Serverless front thik, kintu Aurora Auto Scaling shudhu reader replica add kore; write capacity scale kore na, ar DynamoDB on-demand er moto druto na.
  • C. EC2 te patching ar maintenance lagbe; provisioned write capacity hothat demand e druto scale kore na.
  • D. EC2 patching lage, ar Aurora Auto Scaling shudhu read scale kore.

Keyword: minimize server maintenance and patching + scale read and write as quickly as possible → S3/CloudFront + API Gateway/Lambda + DynamoDB on-demand

Dump explanation (English)

Key phrase in the Question is must scale read and write capacity. Aurora is only for Read. Amazon DynamoDB has two read/write capacity modes for processing reads and writes on your tables: On- demand Provisioned (default, free-tier eligible) https: //docs.aws.amazon.com/amazondynamodb/latest/developerguide/HowItWorks.ReadWriteCapacityMode. html

References: https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/HowItWorks.ReadWriteCapacityMode

20·3D-Q874SAA-C03 dump · Q874

A company has developed an API using Amazon API Gateway REST API and AWS Lambda. How can latency be reduced for users worldwide?

একটি company Amazon API Gateway REST API এবং AWS Lambda ব্যবহার করে একটি API develop করেছে। বিশ্বজুড়ে user-দের জন্য latency কীভাবে কমানো যায়?

Correct: A. Why it is right

Worldwide user er latency komate:

  • Edge-optimized endpoint: request kache-r CloudFront edge diye dhoke.
  • Caching on: backend Lambda call kome, response fast.
  • Content encoding (compression): payload choto, transfer fast.

Why the other options are wrong

  • B. Regional endpoint ek Region theke serve kore, global user er jonno edge-optimized er cheye beshi latency.
  • C. Reserved concurrency Lambda er concurrency reserve/limit kore, latency komay na.
  • D. Regional endpoint + reserved concurrency: duitai global latency komay na.

Keyword: reduce latency for users worldwide + REST API → edge-optimized + caching + compression

Dump explanation (English)

Edge-optimized API endpointsroute requests through CloudFront, reducing latency for global users. Option Acorrectly implements edge-optimization, caching, and compression to minimize latency. Options B and Ddo not use edge optimization, leading to higher latency for global users. Reserved concurrency inOptions C and Dimproves backend scaling but does not address global latency directly.
