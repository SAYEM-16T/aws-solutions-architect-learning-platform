Lecture 1 · IAM Introduction: Users, Groups, Policies · PDF p. 24-26 (part p. 1-3)

Root user, IAM user, group, policy

Shohoj kore: AWS account ta ekta office building. Root user = building er malik, tar kache master key. Malik protidin master key niye ghure na. Protita employee ke alada ID card (IAM user) deya hoy, department (group) onujayi kon room e dhukte parbe ta thik kora hoy (policy).

Root user (PDF p. 25 (part p. 2))

  • Account create korle root account by default toiri hoy.
  • Root shudhu account setup er jonno. Tarpor use koro na, share koro na.
  • Tar bodole IAM user banao: ekta user = organization er ekjon manush.

User ar Group er niyom (PDF p. 25 (part p. 2))

Udaharon: 6 jon, 3 ta group
DevelopersAlice, Bob, Charles OperationsDavid, Edward Audit TeamCharles, David Fredkono group e nai

Charles ar David duita group e. Fred kono group e nai (allowed, kintu best practice na).

  • Group shudhu user rakhe, onno group na (nested group hoy na).
  • User er group e thakar dorkar nai (Fred). Eta kora jay, kintu best practice na.
  • Ekjon user ekadhik group e thakte pare (Charles, David).

Permission = Policy (PDF p. 26 (part p. 3))

  • User ba group ke JSON document deya hoy, naam policy (IAM policy). Eta programming na, shohoj bhashay lekha "ke ki korte parbe".
  • Slide er udaharon: ec2:Describe*, elasticloadbalancing:Describe*, ar kichu cloudwatch action Allow, "Resource": "*".
  • Least privilege principle: user er jototuku dorkar, tar beshi permission dibe na. User er 3 ta service lagle shudhu oi 3 ta.
  • Keno? Shobaike shob permission dile notun user onek service chaliye onek khoroch korte pare ba security problem korte pare.
Exam: "Group er bhitore group?" → na, group shudhu user rakhe. "Permission dewar niyom" → least privilege ("most privilege" / "employee chaile beshi dao" bhul). "IAM user root er credential diye AWS use kore" → bhul, protita user er nijer credential.

Shohoj kore: Console = website e click kore kaj. CLI = terminal e command likhe kaj. SDK = tomar app er code theke AWS ke dak deya. Console er tala password (+MFA), CLI ar SDK er tala access key.

Access keys (PDF p. 33-34 (part p. 10-11))

  • Access key Console theke generate kora hoy. Protita user nijer access key nije manage kore.
  • Access key secret, password er motoi. Colleague ke dibe na; se nijer key banate pare.
  • Access Key ID ≈ username, Secret Access Key ≈ password.
  • Slide er fake key: ID AKIASK4E37PV4983d6C, secret ekta lomba random string.

AWS CLI (PDF p. 35 (part p. 12))

  • Command-line shell theke AWS service er sathe kaj korar tool. Command aws diye shuru (jemon aws s3 cp ...).
  • AWS service er public API te direct access.
  • Script likhe resource manage / automate kora jay.
  • Open-source (GitHub e source code). Console er alternative; keu keu shudhu CLI-i use kore.

AWS SDK (PDF p. 36 (part p. 13))

  • Software Development Kit: language-specific library (API set).
  • Programmatically AWS service access/manage. Terminal e na, application er bhitore embed kora hoy.
  • Support: JavaScript, Python, PHP, .NET, Ruby, Java, Go, Node.js, C++; Mobile SDK (Android, iOS); IoT Device SDK (Embedded C, Arduino).
  • Udaharon: AWS CLI nijei AWS SDK for Python (Boto) er upor banano.
Exam: "Console access dite hobe" → user er password set koro (access key na). "Terminal/script / application code theke AWS" → access key (CLI/SDK). Access key password er moto: share na.

User, Group, Root

  • IAM global. User/role ekbar banale shob region e. Notun region e EC2 ke same permission → existing role-i attach; notun role, duplicate, AMI copy na (B5-Q18).
  • IAM identity = User, Group, Role. EC2 instance, security group, account na (B6-Q31).
  • Group e shudhu user, group er bhitore group na (U04-Q8). User 0 ta ba onek group e thakte pare (U04-Q3).
  • IAM user root er credential use kore na, nijer credential (U04-Q3).
  • Notun user kichu korte parche na → by default kono permission nai, policy attach koro. "24 ghonta wait" bhul (B1-Q52).
  • Onek user (100 / 300) ke eki permission → group banao, group e policy. Role e user "add" kora jay na; shell script / protita user e alada policy / bucket ACL na (B3-Q37, B3-Q39).
  • Group er labh: ekbare onek user ke policy + user o permission manage shohoj. Custom policy banano ba EC2 ke S3 access group er kaj na (B2-Q16).
  • IAM e manage hoy: Users, Groups, Roles, Policies, Identity providers, access keys (API keys), MFA. Cost allocation report (Billing) ar security group (EC2/VPC) na (B2-Q27, B6-Q47).
  • Best practice: root use na, ekjon = ekta user, credential share na, MFA on (U04-Q4).

Policy

  • Policy = JSON document, permission define kore, attach hoy user, group, role e (U04-Q5). "Permission define kore kon entity?" → Policy (Role/Permission na) (B5-Q26).
  • Statement e: Sid, Effect, Principal, Action, Resource, Condition. Version statement e na, policy-level (2012-10-17) (U04-Q9).
  • Least privilege = kaj er jonno jototuku permission dorkar, shudhu tai. "Kom manush ke root" / "beshi dao" / "extra admin operation o dao" bhul (U04-Q6, B2-Q39).
  • "Action": "*", "Resource": "*" = AdministratorAccess. iam:Get* = Get diye shuru shob API.
  • Resource ke pura AWS e unique bhabe chinte → ARN (Amazon Resource Name); "Normalization / Namespace" bhul (B4-Q57).

Role

  • Role = permission set, AWS service use kore (EC2, Lambda, CloudFormation) (U04-Q1).
  • EC2 e AWS API credential lagbe → IAM role banao, EC2 te assign. Key EC2 te/AMI te rakha, encrypt kore disk e, S3/Glacier e, security group e, bastion e, protita EC2 er jonno IAM user: shob bhul (B2-Q31, B2-Q36, B6-Q11, B6-Q27).
  • Credential safe rakhte duita: admin der MFA + EC2 te role (B2-Q36).
  • Ekjon user ke ekbar er jonno extra permission (jemon ELB modify) → role diye, kaj shesh e soriye dao. Root share ba throwaway user na (B6-Q10) amar jana, course e nai
  • Temporary security credential issue kore → AWS STS (SQS/SES na) (B2-Q29) amar jana, course e nai

Access: Console, CLI, SDK

  • Console = password (+MFA). CLI/SDK = access keys. Access Key ID ≈ username, Secret ≈ password; secret ekbar-i dekhay.
  • Admin der console access dite → protita user er password set kore dao. Access key dile console hoy na; MFA/password policy shudhu hardening; user security group e jay na (B5-Q22).
  • Notun user API call korbe → access key create (policy o lagbe, kintu expected uttor access key) (B6-Q36).
  • IAM user er console URL: https://<account-id>.signin.aws.amazon.com/console (B6-Q39).
  • CLI er permission = console er permission (eki IAM policy). CLI built on SDK for Python (Boto).
  • CloudShell: browser e free terminal, logged-in user er credential, default region = console er region, file thake.

Security: MFA, password policy, tools

  • Root ke aro secure → MFA. Root er permission remove kora jay na; "CLI only" / "shudhu root use" bhul (U04-Q7).
  • Root setup e: strong password + MFA. Root access key banano/share/S3 e rakha, email e password pathano na (S1-Q31).
  • MFA = password you know + device you own. Device: Virtual (Google Authenticator, Authy: ek phone e onek token), U2F key (YubiKey: ek key e onek user), Hardware fob (Gemalto), GovCloud fob (SurePassID). Ekhon root MFA mandatory.
  • Password policy: min length, char type, user nije bodlate parbe, expiration (jemon 90 din), reuse bondho. IAM → Account settings.
  • IAM security tool: Credentials Report (account-level), Access Advisor (user-level). "Root Account Manager / Services Report / Security Advisor" banano naam (U04-Q2).
  • Shob user er MFA/password/key status → Credentials Report. Kon permission asole use hoy, unused kete least privilege → Access Advisor.
  • Production e developer der minimum permission → Access Advisor dekhe notun role e shudhu use kora permission, baki revert. Group (C) na, "limited role, pore add" (A) na (S5-Q34).
