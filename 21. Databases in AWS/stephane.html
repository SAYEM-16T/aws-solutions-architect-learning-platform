21·1S3-Q32Stephane set 3 · Q32Design High-Performing Architectures

A media streaming company is looking to migrate its on-premises infrastructure into the AWS Cloud. The engineering team is looking for a fully managed NoSQL database solution with in-memory caching to maintain low latency that is critical for real-time scenarios such as video streaming and interactive content. The team expects the number of concurrent users to touch up to a million so the database should be able to scale elastically. As a solutions architect, which of the following AWS services would you recommend for this use-case?

একটি media streaming company তাদের on-premises infrastructure AWS Cloud-এ migrate করতে চাইছে। engineering team in-memory caching-সহ একটি fully managed NoSQL database solution খুঁজছে, যাতে low latency বজায় থাকে, যা video streaming ও interactive content-এর মতো real-time scenario-র জন্য অত্যন্ত জরুরি। team আশা করছে concurrent user-এর সংখ্যা এক million পর্যন্ত পৌঁছাতে পারে, তাই database-কে elastically scale করতে পারতে হবে। একজন solutions architect হিসেবে, এই use-case-এর জন্য নিচের কোন AWS service আপনি recommend করবেন?

Correct: A. Why it is right

DynamoDB fully managed serverless NoSQL, elastically scale kore (on-demand / auto scaling). DAX diye built-in in-memory cache, microsecond read latency (PDF p. 522).

Tai "fully managed NoSQL + in-memory caching + million concurrent user" er ek-matro full match DynamoDB (+ DAX).

Why the other options are wrong

  • B. DocumentDB fully managed NoSQL (MongoDB), kintu er nijer in-memory caching layer nai.
  • C. ElastiCache cache layer, fully managed primary NoSQL database na; app code change o lage.
  • D. RDS relational (SQL) database, NoSQL na.

Keyword: fully managed NoSQL + in-memory caching + scale elastically → DynamoDB (+ DAX)

Original explanation (English)

Correct option: "DynamoDB"

Amazon DynamoDB is a key-value and document database that delivers single-digit millisecond performance at any scale. It's a fully managed, multi-region, multi-master, durable database with built-in security, backup and restore, and in-memory caching for internet-scale applications. DAX is a DynamoDB-compatible caching service that enables you to benefit from fast in-memory performance for demanding applications. Companies use caching through DynamoDB Accelerator (DAX) when they have high read volumes or need submillisecond read latency.

Incorrect options: "DocumentDB" - Amazon DocumentDB is a fast, scalable, highly available, and fully managed document database service that supports MongoDB workloads. As a document database, Amazon DocumentDB makes it easy to store, query, and index JSON data. Although DocumentDB is fully managed, it does not have an in-memory caching layer.

"ElastiCache" - Amazon ElastiCache allows you to set up popular open-Source compatible in-memory data stores in the cloud. You can build data-intensive apps or boost the performance of your existing databases by retrieving data from high throughput and low latency in-memory data stores such as Redis and Memcached. Elasticache is used as a caching layer. It's not a fully managed NoSQL database.

"RDS" - RDS makes it easy to set up, operate, and scale a relational database in the cloud. It provides cost-efficient and resizable capacity while automating time-consuming administration tasks such as hardware provisioning, database setup, patching, and backups. It's not a NoSQL database.

References: https://aws.amazon.com/dynamodb/

21·2S4-Q11Stephane set 4 · Q11Design Resilient Architectures

As a Solutions Architect, you plan on creating a social media website where users can be friends with each other, and like each other's posts. You plan on performing some complicated queries such as "What are the number of likes on the posts that have been posted by the friends of Mike?". What database do you suggest?

একজন Solutions Architect হিসেবে আপনি একটি social media website তৈরির পরিকল্পনা করছেন, যেখানে user-রা একে অপরের friend হতে পারবে এবং একে অপরের post like করতে পারবে। আপনি কিছু জটিল query চালানোর পরিকল্পনা করছেন, যেমন "What are the number of likes on the posts that have been posted by the friends of Mike?"। আপনি কোন database suggest করবেন?

Renamed: Elasticsearch Service -> Amazon OpenSearch Service (the answer is the same).

Correct: A. Why it is right

Friends ar likes er moto highly connected data ar "friends of Mike er post e likes" query = graph traversal. Neptune graph DB, social network, knowledge graph, recommendation er jonno optimized (PDF p. 525).

Why the other options are wrong

  • B. Redshift data warehouse (OLAP analytics / BI), relationship traverse er jonno na.
  • C. ElasticSearch (ekhon Amazon OpenSearch Service) free text search er jonno, graph query er jonno na.
  • D. Aurora relational; join diye kora jay kintu onek hop er relationship query complex ar slow, graph DB best.

Keyword: social media, friends, likes, complicated relationship query → Neptune

Original explanation (English)

Here, we need a graph database due to the highly connected datasets and queries, therefore Neptune is our best answer

21·3S6-Q17Stephane set 6 · Q17Design Resilient Architectures

The engineering team at an IT company is deploying an Online Transactional Processing (OLTP) application, which will have unpredictable spikes of usage, that they do not know in advance.

Which database would you recommend using?

একটি IT company-র engineering team একটি Online Transactional Processing (OLTP) application deploy করছে, যার usage-এ অনুমান-অযোগ্য spike হবে, যা তারা আগে থেকে জানে না।

আপনি কোন database ব্যবহারের recommend করবেন?

Correct: A. Why it is right

OLTP = relational database er kaaj (RDS / Aurora). "Unpredictable spike, age theke jani na" → Aurora Serverless: unpredictable / intermittent workload, capacity planning nai, nije scale kore (PDF p. 520).

DynamoDB on-demand o spike handle kore, kintu NoSQL, relational OLTP na; tai eta course er intended answer.

Why the other options are wrong

  • B. ElastiCache cache layer, primary OLTP database na, SQL / relational query nai.
  • C. DynamoDB NoSQL; tachara provisioned + auto scaling dhire bara workload er jonno, hothat unpredictable spike er jonno na.
  • D. On-demand spike handle kore thik, kintu DynamoDB NoSQL, relational OLTP er jonno course eta bad dey.

Keyword: OLTP + unpredictable spikes → Aurora Serverless

Original explanation (English)

Correct option:

Aurora Serverless

Amazon Aurora Serverless is an on-demand, auto-scaling configuration for Amazon Aurora (MySQL-compatible and PostgreSQL-compatible editions), where the database will automatically start up, shut down, and scale capacity up or down based on your application's needs. It enables you to run your database in the cloud without managing any database instances. It's a simple, cost-effective option for infrequent, intermittent, or unpredictable workloads. The database design for an OLTP application fits the relational model, therefore you can infer an OLTP system as a Relational Database.

Aurora Serverless is the perfect way to create a database that can scale down to 0 servers, and scale up to many servers, as an OLTP database. So this is the correct option.

Incorrect options:

DynamoDB with Provisioned Capacity and Auto Scaling

DynamoDB with On-Demand Capacity

Amazon DynamoDB is a key-value and document database that delivers single-digit millisecond performance at any scale. It's a fully managed, multi-region, multi-master, durable database with built-in security, backup and restore, and in-memory caching for internet-scale applications.

DynamoDB is a NoSQL database and doesn't do relational queries, therefore it's a choice we have to eliminate, even though the two modes proposed here help us cope with an unpredictable amount of usage. So both these options are incorrect.

Amazon ElastiCache - Amazon ElastiCache allows you to seamlessly set up, run, and scale popular open-Source compatible in-memory data stores in the cloud. Build data-intensive apps or boost the performance of your existing databases by retrieving data from high throughput and low latency in-memory data stores. Amazon ElastiCache is a popular choice for real-time use cases like Caching, Session Stores, Gaming, Geospatial Services, Real-Time Analytics, and Queuing. Elasticache is used as a caching layer in front of relational databases. ElastiCache is a NoSQL database and doesn't facilitate relational queries, so this option is ruled out.
