Lecture 1 · Choosing the Right Database · PDF p. 517-518 (part p. 2-3)

Database bachai: age proshno koro, tarpor type milao

Shohoj kore (dokan er almari): Kapor rakhte almari, bai rakhte bookshelf, taka rakhte locker. Shob jinish ek almari te rakha jay, kintu kaaj kothin hoy. Database o temni: data er shape (table, JSON, graph, time point, file) ar kivabe porbe (join, key diye, relation dhore, time diye) dekhe database bachai.

Requirement er proshno gulo (PDF p. 517 (part p. 2))

Database types (PDF p. 518 (part p. 3))

  • RDBMS (= SQL / OLTP): RDS, Aurora. Join er jonno best.
  • NoSQL (sadharonoto join nai, SQL nai; exception ache): DynamoDB (~JSON), ElastiCache (key/value), Neptune (graph), DocumentDB (MongoDB), Keyspaces (Cassandra).
  • Object store: S3 (boro object), Glacier (backup / archive).
  • Data warehouse (= SQL analytics / BI): Redshift (OLAP), Athena, EMR.
  • Search: OpenSearch (JSON): free text, unstructured search.
  • Graph: Neptune: data er moddhe relationship.
  • Ledger: QLDB (Quantum Ledger Database).
  • Time series: Timestream.
  • Kichu database (Redshift, Athena, EMR, OpenSearch) Section 22 (Data & Analytics) e detail.

Lecture 2 · RDS Summary · PDF p. 519 (part p. 4)

Amazon RDS: provisioned, managed relational DB

Shohoj kore: RDS = tomar chena PostgreSQL / MySQL, kintu patch, backup, failover AWS kore. Tobe server size (instance) ar disk (EBS) tumi-i thik koro, tai eta provisioned, serverless na. Detail Section 09 e.

PointSummary
EnginePostgreSQL, MySQL, Oracle, SQL Server, DB2, MariaDB, Custom
CapacityInstance size + EBS volume type & size provision; storage auto-scaling ache
Read scalingRead Replica: analytics / reporting production DB te na chaliye replica te
HAMulti-AZ: standby shudhu disaster er jonno, standby te query kora jay na
SecurityIAM, Security Group (network), KMS (at rest), SSL/TLS (in transit); username/password ba IAM authentication
BackupAutomated backup 35 din porjonto + point-in-time restore (notun DB banay); long-term → manual snapshot
MaintenanceManaged + scheduled maintenance, downtime hoy (engine / OS patch)
CredentialsIAM auth (RDS Proxy diye enforce kora jay), Secrets Manager integration
RDS CustomUnderlying instance e access + customize: Oracle & SQL Server
Use caseRelational dataset (RDBMS / OLTP), SQL query, transaction
Exam: "relational, SQL, transactions (insert / update / delete)" → RDS (U21-Q1). Analytics production ke slow korche → Read Replica, Multi-AZ na. Underlying OS access → RDS Custom. RDS e built-in auto-scaling replica nai, replica / Multi-AZ nije banao: tai "max storage replica + auto scale" proshne Aurora (U21-Q4).

Subtitle e "at risk encryption" = at-rest, "intrinsic encryption" = in-flight (SSL/TLS) encryption.

Lecture 3 · Aurora Summary · PDF p. 520 (part p. 5)

Shohoj kore: Aurora te disk (storage) ekta shared, AWS-managed layer: data 6 copy, 3 AZ te, nije sare (self-healing), nije bare. Upore DB instance gulo (writer + reader) shei shared storage pore. Tai replica banano, failover, clone shob druto. Detail Section 09 e.

App→ write Writer endpointprimary instance + Reader endpointread replicas, auto-scaling
↓ duijon i ek storage Shared storage volume6 copies × 3 AZ, auto-grow

Compute (instance) ar storage alada: storage HA, compute cluster multi-AZ.

PointSummary
CompatibilityPostgreSQL / MySQL compatible API
Storage6 replica, 3 AZ (bodlano jay na), highly available, self-healing, auto-scaling
ComputeDB instance er cluster, multi-AZ; read replica auto-scaling
EndpointsWriter endpoint ar reader endpoint (custom endpoint o)
Security / monitoring / maintenanceRDS er moto

Aurora ServerlessUnpredictable / intermittent workload, capacity planning nai

Aurora Machine LearningAurora theke SageMaker & Comprehend diye ML

"OLTP + unpredictable spike, age theke jani na" → Aurora Serverless; DynamoDB on-demand spike handle kore kintu NoSQL, OLTP relational na (S6-Q17). "Cross-region DR, < 1 s replication" → Aurora Global. "Production theke test DB druto" → Cloning.

"RDS" - RDS makes it easy to set up, operate, and scale a relational database in the cloud. It provides cost-efficient and resizable capacity while automating time-consuming administration tasks such as hardware provisioning, database setup, patching, and backups. It's not a NoSQL database.
