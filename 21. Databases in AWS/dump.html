21·1D-Q210SAA-C03 dump · Q210

A company runs a containerized application on a Kubernetes cluster in an on-premises data center. The company is using a MongoDB database for data storage. The company wants to migrate some of these environments to AWS, but no code changes or deployment method changes are possible at this time. The company needs a solution that minimizes operational overhead. Which solution meets these requirements?

একটি company on-premises data center-এ একটি Kubernetes cluster-এ একটি containerized application চালায়। company data storage-এর জন্য একটি MongoDB database ব্যবহার করছে। company এই environment-গুলোর কয়েকটি AWS-এ migrate করতে চায়, কিন্তু এই মুহূর্তে কোনো code change বা deployment method change সম্ভব নয়। company-র এমন একটি solution দরকার, যা operational overhead কমায়। কোন solution এই requirement পূরণ করে?

Correct: D. Why it is right

No code change ar no deployment method change: Kubernetes thakbe, tai EKS. Fargate e worker node manage korte hoy na: minimal operational overhead.

MongoDB er jonno DocumentDB: MongoDB-compatible, fully managed, 3 AZ e replicate (PDF p. 524), tai app code change lage na.

Why the other options are wrong

  • A. ECS e gele Kubernetes deployment method change hoy; MongoDB EC2 te nije manage korte hoy.
  • B. ECS deployment method change; DynamoDB er API MongoDB theke alada, code change lagbe.
  • C. EKS thik, kintu EC2 worker node manage korte hoy; DynamoDB te code change lagbe.

Keyword: Kubernetes + MongoDB + no code/deployment change + min overhead → EKS on Fargate + DocumentDB

Dump explanation (English)

Amazon DocumentDB (with MongoDB compatibility) is a fast, reliable, and fully managed database service. Amazon DocumentDB makes it easy to set up, operate, and scale MongoDB-compatible databases in the cloud. With Amazon DocumentDB, you can run the same application code and use the same drivers and tools that you use with MongoDB. https: //docs.aws.amazon.com/documentdb/latest/developerguide/what-is.html

References: https://docs.aws.amazon.com/documentdb/latest/developerguide/what-is.html

21·2D-Q682SAA-C03 dump · Q682

A company wants to build a map of its IT infrastructure to identify and enforce policies on resources that pose security risks. The company's security team must be able to query data in the IT infrastructure map and quickly identify security risks. Which solution will meet these requirements with the LEAST operational overhead?

একটি company security risk তৈরি করে এমন resource চিহ্নিত করতে এবং সেগুলোর ওপর policy enforce করতে তাদের IT infrastructure-এর একটি map তৈরি করতে চায়। company-র security team-কে IT infrastructure map-এর data query করতে এবং দ্রুত security risk চিহ্নিত করতে পারতে হবে। কোন solution সবচেয়ে কম operational overhead (LEAST operational overhead) দিয়ে এই requirement পূরণ করবে?

Correct: B. Why it is right

IT infrastructure er map = resource gulor moddhe relationship (kon instance kon SG/role/network e connected). Highly connected data er jonno Neptune graph database: billions of relations, millisecond query (PDF p. 525).

SPARQL graph query language; relationship khuje security risk druto pawa jay. Fully managed: least overhead.

Why the other options are wrong

  • A. RDS relational; onek level er relationship query onek join lage, complex ar slow.
  • C. Redshift OLAP warehouse analytics er jonno; connected graph data query er jonno na.
  • D. DynamoDB key/value NoSQL, join nai; relationship (graph) query kora kothin.

Keyword: map of infrastructure + relationships + query risks → Neptune (graph)

Dump explanation (English)

Understanding the Requirement: The company needs to map its IT infrastructure to identify and enforce security policies, with the ability to quickly query and identify security risks. Analysis of Options: Amazon RDS: While suitable for relational data, it is not optimized for handling complex relationships and querying those relationships, which is essential for an IT infrastructure map. Amazon Neptune: A graph database service designed for handling highly connected data. It uses SPARQL to query graph data efficiently, making it ideal for mapping IT infrastructure and identifying relationships that pose security risks. Amazon Redshift: A data warehouse solution optimized for complex queries on large datasets but not specifically for graph data. Amazon DynamoDB: A NoSQL database that uses PartiQL for querying, but it is not optimized for complex relationships in graph data. Best Option for Mapping and Querying IT Infrastructure: Amazon Neptune provides the most suitable solution with the least operational overhead. It is purpose- built for graph data and enables efficient querying of complex relationships to identify security risks. Reference: Amazon Neptune Querying with SPARQL

21·3D-Q743SAA-C03 dump · Q743

A social media company wants to store its database of user profiles, relationships, and interactions in the AWS Cloud. The company needs an application to monitor any changes in the database. The application needs to analyze the relationships between the data entities and to provide recommendations to users. Which solution will meet these requirements with the LEAST operational overhead?

একটি social media company তাদের user profile, relationship এবং interaction-এর database AWS Cloud-এ store করতে চায়। database-এর যেকোনো পরিবর্তন monitor করতে company-র একটি application দরকার। application-কে data entity-গুলোর মধ্যে relationship analyze করতে এবং user-দের recommendation দিতে হবে। কোন solution সবচেয়ে কম operational overhead (LEAST operational overhead) দিয়ে এই requirement পূরণ করবে?

Correct: B. Why it is right

User profile, relationships, interactions, recommendation: Neptune graph database (social network, recommendation engine, PDF p. 525).

Database er change monitor korte Neptune Streams: graph er protita change er real-time ordered sequence, duplicate nai, HTTP REST API diye pora jay (PDF p. 526). Built-in, extra pipeline nai: LEAST overhead.

Why the other options are wrong

  • A. Neptune thik, kintu Kinesis Data Streams nije Neptune er change dhorte pare na; alada pipeline/code lage.
  • C. QLDB ledger database (immutable history), relationship analysis/recommendation er jonno na; QLDB ekhon end of support o.
  • D. Neptune Streams shudhu Neptune er jonno; QLDB er change porte pare na, ar QLDB graph DB o na.

Keyword: relationships + recommendations + monitor changes → Neptune + Neptune Streams

Dump explanation (English)

Amazon Neptune: Neptune is a fully managed graph database service that is optimized for storing and querying highly connected data. It supports both property graph and RDF graph models, making it suitable for applications that need to analyze relationships between data entities. Neptune Streams: Neptune Streams captures changes to the graph and streams these changes to other AWS services. This is useful for applications that need to monitor and respond to changes in real-time, such as providing recommendations based on user interactions and relationships. Least Operational Overhead: Using Neptune Streams directly with Amazon Neptune ensures that the solution is tightly integrated, reducing the need for additional components and minimizing operational overhead. This integration simplifies the architecture by eliminating the need for a separate service like Kinesis for change processing. Reference: Amazon Neptune Documentation Neptune Streams Documentation

21·4D-Q828SAA-C03 dump · Q828⚠ outdated

A company maintains its accounting records in a custom application that runs on Amazon EC2 instances. The company needs to migrate the data to an AWS managed service for development and maintenance of the application data. The solution must require minimal operational support and provide immutable, cryptographically verifiable logs of data changes. Which solution will meet these requirements MOST cost-effectively?

একটি company তাদের accounting record একটি custom application-এ রাখে, যা Amazon EC2 instance-এ চলে। application data-র development ও maintenance-এর জন্য company-কে data একটি AWS managed service-এ migrate করতে হবে। solution-এ ন্যূনতম operational support লাগতে হবে এবং data change-এর immutable, cryptographically verifiable log দিতে হবে। কোন solution এই requirement সবচেয়ে cost-effectively (MOST cost-effectively) পূরণ করবে?

⚠ Outdated: Amazon QLDB er end of support 31 July 2025 e hoye geche; ekhon ar use kora jay na. AWS ekhon Aurora PostgreSQL (audit/pgAudit diye) e migrate korte bole. Exam e QLDB answer purono dhorte hobe. source

Correct: D. Why it is right

Immutable, cryptographically verifiable log of data changes = Ledger database: Amazon QLDB (PDF p. 518). Managed ar serverless, tai minimal operational support.

Outdated: QLDB er end of support 31 July 2025 e hoye geche; AWS ekhon Aurora PostgreSQL (pgAudit diye audit) e migrate korte bole. Exam e ei keyword dekhle purono answer QLDB.

Why the other options are wrong

  • A. Redshift analytics data warehouse; cryptographically verifiable change history dey na, cluster cost o beshi.
  • B. Neptune graph database relationship er jonno; immutable verifiable journal nai.
  • C. Timestream time series database (IoT, metrics); verifiable ledger na.

Keyword: immutable + cryptographically verifiable logs → QLDB (ekhon end of support)

Dump explanation (English)

Amazon QLDB is the most cost-effective and suitable service for maintaining immutable, cryptographically verifiable logs of data changes. QLDB provides a fully managed ledger database with a built-in cryptographic hash chain, making it ideal for recording changes to accounting records, ensuring data integrity and security. QLDB reduces operational overhead by offering fully managed services, so there’s no need for server management, and it’s built specifically to ensure immutability and verifiability, making it the best fit for the given requirements. Option A (Redshift): Redshift is designed for analytics and not for immutable, cryptographically verifiable logs. Option B (Neptune): Neptune is a graph database, which is not suitable for this use case. Option C (Timestream): Timestream is a time series database optimized for time-stamped data, but it does not provide immutable or cryptographically verifiable logs. AWS Reference: Amazon QLDB How QLDB Works

21·5D-Q1001SAA-C03 dump · Q1001

A company has 5 TB of datasets. The datasets consist of 1 million user profiles and 10 million connections. The user profiles have connections as many-to-many relationships. The company needs a performance-efficient way to find mutual connections up to five levels. Which solution will meet these requirements?

একটি company-র 5 TB dataset আছে। dataset-গুলোতে 1 million user profile এবং 10 million connection আছে। user profile-গুলোর connection many-to-many relationship হিসেবে আছে। company-র পাঁচ (five) level পর্যন্ত mutual connection খুঁজে বের করার একটি performance-efficient উপায় দরকার। কোন solution এই requirement পূরণ করবে?

Correct: B. Why it is right

User profile ar many-to-many connections, five levels porjonto mutual connection: eta graph traversal. Neptune graph database: data vertices (user) ar edges (connection) hisabe rakhe, highly connected dataset er complex query millisecond e (PDF p. 525).

Why the other options are wrong

  • A. Athena te 5 level er self JOIN onek boro scan, slow ar dami; graph traversal er jonno na.
  • C. QuickSight shudhu visualization; connection khuje ber korar query engine na.
  • D. RDS e 5 level JOIN onek slow; relational DB highly connected graph query er jonno optimized na.

Keyword: many-to-many relationships + connections up to five levels → Neptune (graph)

21·6D-Q1011SAA-C03 dump · Q1011not in course

A company launches a new web application that uses an Amazon Aurora PostgreSQL database. The company wants to add new features to the application that rely on AI. The company requires vector storage capability to use AI tools. Which solution will meet this requirement MOST cost-effectively?

একটি company একটি নতুন web application launch করেছে, যা একটি Amazon Aurora PostgreSQL database ব্যবহার করে। company application-এ AI-নির্ভর নতুন feature যোগ করতে চায়। AI tool ব্যবহার করতে company-র vector storage capability দরকার। কোন solution এই requirement সবচেয়ে cost-effectively (MOST cost-effectively) পূরণ করবে?

Not in the course: Aurora PostgreSQL er pgvector extension (vector embedding rakha) course e porano hoy na.

Correct: D. Why it is right

Already Aurora PostgreSQL ache. pgvector extension install korle oi database-i vector embedding store ar similarity search korte pare. Notun kono cluster ba service er taka lage na: MOST cost-effective.

(pgvector course e porano hoy na.)

Why the other options are wrong

  • A. OpenSearch vector index korte pare, kintu alada cluster/service er extra cost ar data sync lage.
  • B. DocumentDB notun cluster: extra cost, ar app ke alada database e likhte hoy.
  • C. Neptune ML graph + ML er jonno, alada cluster er extra cost; simple vector storage er jonno overkill.

Keyword: existing Aurora PostgreSQL + vector storage + MOST cost-effective → pgvector extension

Dump explanation (English)

Aurora PostgreSQL supports the pgvector extension, which allows storage and querying of vector embeddings directly inside the database. This eliminates the need for external vector databases and provides cost-effective and performant integration for AI workloads. Reference: AWS Documentation – Amazon Aurora PostgreSQL and pgvector Support
