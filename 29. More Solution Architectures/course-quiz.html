29·1U29-Q1Udemy quiz · sec 29 · Q1

You are working on a Serverless application where you want to process objects uploaded to an S3 bucket. You have configured S3 Events on your S3 bucket to invoke a Lambda function every time an object has been uploaded. You want to ensure that events that can't be processed are sent to a Dead Letter Queue (DLQ) for further processing. Which AWS service should you use to set up the DLQ?

Correct: C. Why it is right

S3 Event Notification Lambda ke asynchronous bhabe invoke kore. Async invocation e Lambda nijei internally retry kore (3 bar), tarpor fail hole message discard hoy, na hole DLQ e jay (PDF p. 806).

Course er rule: SQS + Lambda hole DLQ thake SQS side e; kintu async (SNS/S3) + Lambda hole DLQ set korte hoy Lambda function side e. Tai DLQ (SQS queue ba SNS topic) Lambda function e configure korbe.

Why the other options are wrong

  • A. S3 Events shudhu event pathay; S3 er kono DLQ setting nai. Fail handling Lambda er async invocation side e hoy.
  • B. SNS topic DLQ er target hote pare, kintu DLQ ta set korte hoy Lambda function e. Tachara ekhane SNS flow e nai, S3 direct Lambda ke call kore.

Keyword: S3 Events invoke Lambda (asynchronous) + DLQ → DLQ set koro Lambda function e

Instructor feedback (English)

C: The Lambda function's invocation is "asynchronous", so the DLQ has to be set on the Lambda function side.

29·2U29-Q2Udemy quiz · sec 29 · Q2

As a Solutions Architect, you have created an architecture for a company that includes the following AWS services: CloudFront, Web Application Firewall (AWS WAF), AWS Shield, Application Load Balancer, and EC2 instances managed by an Auto Scaling Group. Sometimes the company receives malicious requests and wants to block these IP addresses. According to your architecture, Where should you do it?

Correct: B. Why it is right

Architecture e shobar shamne CloudFront. Client er connection CloudFront e terminate hoy, tai ALB porjonto ja ashe ta CloudFront er public IP, client er IP na (PDF p. 817).

Tai client IP block korte hobe AWS WAF diye (CloudFront e attach kora), WAF er IP address filtering rule (IP set) diye. Course slide e NACL ke ei setup e "NOT helpful" bola ache.

Why the other options are wrong

  • A. CloudFront nije shudhu Geo Restriction (country level) dite pare, specific IP block er jonno WAF lagbe.
  • C. Shield holo DDoS protection; specific IP block korar rule Shield e likhte paro na.
  • D. ALB Security Group e shudhu CloudFront er IP dekha jay, client IP na. Tachara SG te deny rule nai, shudhu allow.
  • E. EC2 private subnet e, traffic ashe ALB theke; client IP EC2 porjonto pouchay na. SG te deny rule o nai.
  • F. NACL e deny rule thakleo, CloudFront thakay NACL client er IP dekhe na, CloudFront er IP dekhe. Tai ekhane NACL kaj kore na.

Keyword: CloudFront shamne + block IP addresses → AWS WAF (IP filtering)

29·3U29-Q3Udemy quiz · sec 29 · Q3

You have a set of Linux EC2 instances deployed in a Cluster Placement Group in order to perform High-Performance Computing (HPC). You would like to maximize network performance between your EC2 instances. What should you use?

Correct: A. Why it is right

Elastic Fabric Adapter (EFA) holo HPC er jonno improved ENA, shudhu Linux e kaj kore (PDF p. 821).

  • Inter-node communication ar tightly coupled workload er jonno best.
  • MPI standard use kore, Linux OS bypass kore low latency, reliable transport dey.

Cluster placement group + Linux + HPC + maximum network performance → EFA.

Why the other options are wrong

  • B. ENI holo shudhu ekta virtual network card; network performance baray na.
  • C. ENA enhanced networking (up to 100 Gbps) dey, kintu EFA hocche ENA er improved version, OS bypass soho; HPC inter-node er jonno EFA beshi fast.
  • D. FSx for Lustre holo HPC er file system (storage), networking component na.

Keyword: Linux + HPC + maximize network performance between instances → EFA
