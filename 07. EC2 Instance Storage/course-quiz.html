7·1U07-Q1Udemy quiz · sec 07 · Q1

You have just terminated an EC2 instance in us-east-1a, and its attached EBS volume is now available. Your teammate tries to attach it to an EC2 instance in us-east-1b but he can't. What is a possible cause for this?

আপনি সবেমাত্র us-east-1a-তে একটি EC2 instance terminate করেছেন, এবং এর attached EBS volume এখন available। আপনার সহকর্মী এটি us-east-1b-র একটি EC2 instance-এ attach করার চেষ্টা করছেন, কিন্তু পারছেন না। এর একটি সম্ভাব্য কারণ কী?

Correct: C. Why it is right

EBS volume ekta specific AZ e bandha (PDF p. 95-96). us-east-1a er volume shudhu us-east-1a er instance e attach hoy; us-east-1b er instance e hoy na.

Onno AZ e nite hole: age snapshot nao, tarpor oi snapshot theke us-east-1b te notun volume create koro (PDF p. 99).

Why the other options are wrong

  • A. IAM permission thakleo AZ alada hole attach hoy na. Question er asol clue holo 1a vs 1b, mane alada AZ.
  • B. EBS Region e na, aro choto scope AZ e bandha. Region lock hole same Region er 1b te attach hoye jeto.

Keyword: us-east-1a er volume → us-east-1b er instance e attach hoy na → EBS AZ locked

Instructor feedback (English)

C: EBS Volumes are created for a specific AZ. It is possible to migrate them between different AZs using EBS Snapshots.

7·2U07-Q2Udemy quiz · sec 07 · Q2

You have launched an EC2 instance with two EBS volumes, Root volume type and the other EBS volume type to store the data. A month later you are planning to terminate the EC2 instance. What's the default behavior that will happen to each EBS volume?

আপনি দুটি EBS volume-সহ একটি EC2 instance launch করেছেন: Root volume type এবং data store করার জন্য অন্য EBS volume type। এক মাস পরে আপনি EC2 instance terminate করার পরিকল্পনা করছেন। প্রতিটি EBS volume-এর ক্ষেত্রে default-ভাবে কী ঘটবে?

Correct: B. Why it is right

Default Delete on Termination: root EBS volume e enabled, tai instance terminate e root delete hoy. Baki attached EBS volume e disabled, tai sheta theke jay (PDF p. 98).

Root volume rakhte chaile root er Delete on Termination off koro (console ba CLI).

Why the other options are wrong

  • A. Shudhu root er attribute default e on. Extra data volume er default off, tai sheta delete hoy na.
  • C. Ulta bola: default e root delete hoy, extra volume thake.
  • D. Root er Delete on Termination default e enabled, tai root delete hoy.

Keyword: default behavior on terminate → root delete, extra EBS volume thake

Instructor feedback (English)

B: By default, the Root volume type will be deleted as its "Delete On Termination" attribute checked by default. Any other EBS volume types will not be deleted as its "Delete On Termination" attribute disabled by default.

7·3U07-Q3Udemy quiz · sec 07 · Q3

You can use an AMI in N.Virginia Region us-east-1 to launch an EC2 instance in any AWS Region.

আপনি N.Virginia Region us-east-1-এর একটি AMI ব্যবহার করে যেকোনো AWS Region-এ একটি EC2 instance launch করতে পারেন।

Correct: B. Why it is right

False. AMI ekta specific Region er jonno build hoy (PDF p. 101). us-east-1 er AMI diye shudhu us-east-1 e launch kora jay.

Onno Region e launch korte age AMI ta oi Region e copy koro, tarpor copied AMI theke launch koro.

Why the other options are wrong

  • A. AMI Regional; onno Region e shorashori use hoy na, age copy lagbe.

Keyword: us-east-1 er AMI → any AWS Region? → False (AMI Regional, copy lage)

Instructor feedback (English)

B: AMIs are built for a specific AWS Region, they're unique for each AWS Region. You can't launch an EC2 instance using an AMI in another AWS Region, but you can copy the AMI to the target AWS Region and then use it to create your EC2 instances.

7·4U07-Q4Udemy quiz · sec 07 · Q4

Which of the following EBS volume types can be used as boot volumes when you create EC2 instances?

EC2 instance তৈরি করার সময় নিচের কোন EBS volume type-গুলো boot volume হিসেবে ব্যবহার করা যায়?

Correct: B. Why it is right

Boot volume hote pare shudhu SSD type: gp2/gp3 ar io1/io2 (PDF p. 105). HDD type st1 ar sc1 boot volume hote pare na (PDF p. 108).

Original explanation e Magnetic (standard) o ache: eta purono previous-generation type, boot hoy, kintu option e nai.

Why the other options are wrong

  • A. st1 ar sc1 HDD, boot volume hote pare na. Ei list e shudhu gp2/gp3 thik.
  • C. io1/io2 thik, kintu st1/sc1 HDD boot volume hote pare na.

Keyword: boot volumes → shudhu SSD: gp2, gp3, io1, io2 (st1/sc1 na)

Instructor feedback (English)

B: When creating EC2 instances, you can only use the following EBS volume types as boot volumes: gp2, gp3, io1, io2, and Magnetic (Standard).

7·5U07-Q5Udemy quiz · sec 07 · Q5

What is EBS Multi-Attach?

EBS Multi-Attach কী?

Correct: C. Why it is right

EBS Multi-Attach: ek-i EBS volume same AZ er multiple EC2 instance e ekshathe attach (PDF p. 110). Shudhu io1/io2 family te; max 16 instance; protita instance er full read/write permission.

Use case: clustered Linux app (ex: Teradata); cluster-aware file system lage.

Why the other options are wrong

  • A. Multi-AZ hoy na: Multi-Attach soho EBS ek AZ e bandha. Onek AZ jure share lagle EFS.
  • B. Ek instance e onek volume attach kora normal EBS behaviour, eta Multi-Attach na.
  • D. EBS onno AZ er instance e attach-i hoy na, ar eta Multi-Attach er definition o na.

Keyword: same volume → multiple instances → same AZ = Multi-Attach

Instructor feedback (English)

C: Using EBS Multi-Attach, you can attach the same EBS volume to multiple EC2 instances in the same AZ. Each EC2 instance has full read/write permissions.

7·6U07-Q6Udemy quiz · sec 07 · Q6

You would like to encrypt an unencrypted EBS volume attached to your EC2 instance. What should you do?

আপনি আপনার EC2 instance-এ attach করা একটি unencrypted EBS volume encrypt করতে চান। আপনার কী করা উচিত?

Correct: A. Why it is right

Existing unencrypted EBS volume in-place encrypt hoy na. Course er dhap (PDF p. 112): volume er snapshot nao → snapshot copy koro ar encrypt tick dao (KMS key) → encrypted snapshot theke notun volume banao → original instance e attach.

Encrypted snapshot theke banano volume automatic encrypted. Hands-on shortcut: unencrypted snapshot theke create volume er somoy-i encryption on kora jay.

Why the other options are wrong

  • B. Edit Attributes e emon kono encrypt option nai; existing volume er encryption in-place on kora jay na.
  • C. Kaj kore, kintu nijer haate sob data copy korte onek time, manual kaj ar khoroch lage (boro volume e aro beshi). Snapshot route shohoj, AWS er documented way.
  • D. AWS Support tomar volume encrypt kore dey na; snapshot route e tumi nijei korte paro.

Keyword: encrypt an unencrypted EBS volume → snapshot → copy + encrypt → new volume

Instructor feedback (English)

C: This can be done but it'll take a lot of manual work, time, and will be costly especially if your EBS volume has a lot of data.

7·7U07-Q7Udemy quiz · sec 07 · Q7

You have a fleet of EC2 instances distributes across AZs that process a large data set. What do you recommend to make the same data to be accessible as an NFS drive to all of your EC2 instances?

AZ-গুলো জুড়ে ছড়ানো আপনার EC2 instance-এর একটি fleet আছে, যেগুলো একটি বড় data set process করে। একই data আপনার সব EC2 instance-এর কাছে একটি NFS drive হিসেবে accessible করতে আপনি কী recommend করবেন?

Correct: B. Why it is right

EFS holo managed NFS (network file system): onek EC2 te mount hoy, ar instance gulo alada AZ e thakleo cholbe (PDF p. 113). Sob instance ek-i data dekhe.

Keyword: 'NFS drive' + 'across AZs' + 'same data' = EFS.

Why the other options are wrong

  • A. EBS ek AZ e bandha ar sadharonoto ek instance e mount hoy (Multi-Attach o shudhu same AZ); eta NFS na.
  • C. Instance Store oi host er physical disk, shudhu oi instance er; share kora jay na, ar ephemeral.

Keyword: across AZs + same data + NFS drive → EFS

Instructor feedback (English)

A: EBS volumes are locked to an AZ and can only be mounted on one EC2 instance at a time.

B: EFS is a network file system (NFS) that allows you to mount the same file system on EC2 instances that are in different AZs.

C: EC2 Instance Store is a storage located on disks that are physically attached to the host of your EC2 instance. Can be used only on one EC2 instance at a time. It's ideal for temporary storage such as buffers, caches, etc.

7·8U07-Q8Udemy quiz · sec 07 · Q8

You would like to have a high-performance local cache for your application hosted on an EC2 instance. You don't mind losing the cache upon the termination of your EC2 instance. Which storage mechanism do you recommend as a Solutions Architect?

একটি EC2 instance-এ hosted আপনার application-এর জন্য আপনি একটি high-performance local cache চান। আপনার EC2 instance terminate হলে cache হারালে আপনার আপত্তি নেই। একজন Solutions Architect হিসেবে আপনি কোন storage mechanism recommend করবেন?

Correct: C. Why it is right

EC2 Instance Store = host server e physically lagano disk: better I/O performance, sobcheye beshi IOPS (PDF p. 103-104). Kintu ephemeral: stop/terminate e data jay.

Course bole eta buffer / cache / scratch / temporary content er jonno bhalo. Ekhane cache harale problem nai, tai perfect fit.

Why the other options are wrong

  • A. EBS network drive, ektu latency ache; performance bhalo kintu 'limited', Instance Store er moto local na.
  • B. EFS network file system, onek instance share kore; local high-performance cache er jonno na, ar dami.

Keyword: high-performance local cache + don't mind losing on termination → Instance Store

Instructor feedback (English)

A: EBS are network drives which makes it provides less I/O performance than Instance Store.

B: EFS volumes are network file systems that can be mounted on many EC2 instances. EFS volumes are accessible through network which makes it provides less performance I/O than Instance Store.

C: EC2 Instance Store provides the best disk I/O performance.

7·9U07-Q9Udemy quiz · sec 07 · Q9

You are running a high-performance database that requires an IOPS of 310,000 for its underlying storage. What do you recommend?

আপনি একটি high-performance database চালাচ্ছেন, যার underlying storage-এর জন্য 310,000 IOPS দরকার। আপনি কী recommend করবেন?

Correct: C. Why it is right

EBS er sobcheye fast volume io2 Block Express er max 256,000 IOPS (PDF p. 107). 310,000 IOPS kono EBS volume dite pare na, tai EC2 Instance Store (i3 er moto instance e millions IOPS, PDF p. 104).

Shorto: instance store ephemeral, tai replication/backup tomar dayitto (PDF p. 103). Note: explanation er 'io2 64,000' purono; ekhon sob io2 volume-i Block Express (256,000).

Why the other options are wrong

  • A. gp2 er max 16,000 IOPS (PDF p. 106), 310,000 er dhare kache na.
  • B. io1 er max 64,000 IOPS (Nitro), onno instance e 32,000 (PDF p. 107); onek kom.
  • D. io2 Block Express er max 256,000 IOPS; 310,000 er cheye kom.

Keyword: 310,000 IOPS (EBS max 256,000 er beshi) → Instance Store

Instructor feedback (English)

A: 16,000 is the maximum IOPS you can achieve when you're using the EBS gp2 volume type.

B: 64,000 is the maximum IOPS you can achieve when you're using EBS io1 or io2 volume types.

C: You can run a database on an EC2 instance that uses an Instance Store, but you'll have a problem that the data will be lost if the EC2 instance is stopped (it can be restarted without problems). One solution is that you can set up a replication mechanism on another EC2 instance with an Instance Store to have a standby copy. Another solution is to set up backup mechanisms for your data. It's all up to you how you want to set up your architecture to validate your requirements. In this use case, it's around IOPS, so we have to choose an EC2 Instance Store.

D: 256,000 is the maximum IOPS you can achieve when you're using the EBS io2 Block Express volume type.
