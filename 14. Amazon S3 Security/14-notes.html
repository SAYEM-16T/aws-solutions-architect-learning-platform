S3 object encryption er 5 ta upay + encryption in transit

Shohoj kore (locker er chabi): Bank er locker e jinish rakhcho. Prosno holo chabi kar kache? (1) Bank nijei chabi rakhe, tumi dekho-o na = SSE-S3. (2) Bank er alada chabi-ghor (KMS) e chabi, kintu kon chabi, ke use korbe tumi thik koro, ar register e lekha thake ke kokhon khulecho = SSE-KMS. (3) Protibar tumi nijer chabi niye jao, bank kaj shesh kore chabi ferot dey, rakhe na = SSE-C. (4) Tumi bashay-i jinish ta tala mere bank e dao, bank jane-i na bhitore ki = client-side. Ar bank e jawar rasta nirapod kina (armored van) = encryption in transit (HTTPS).

4+1 ta method (PDF p. 315 (part p. 2))

  • Server-Side Encryption (SSE): S3 nije server e encrypt kore. 4 rokom:
    • SSE-S3: S3-managed key. Default e enabled.
    • SSE-KMS: AWS KMS e rakha KMS key.
    • DSSE-KMS: KMS key diye dual-layer.
    • SSE-C: customer-provided key.
  • Client-Side Encryption: client nije encrypt kore tarpor upload.
  • Slide: "kon ta kon situation e" bujha exam er jonno important.

DSSE-KMS (PDF p. 319 (part p. 6))

  • Dual-Layer Server-Side Encryption, key KMS handle/manage kore.

  • Header: "x-amz-server-side-encryption": "aws:kms:dsse".
  • Course page bole: June 2023 e eseche, exam e na ashle porabe na (Lecture 2 card).

  • Key protiti HTTP request er header e dite hoy (upload-o, read-o).

CORS: browser er onno origin theke file ana

Shohoj kore: Tumi example.com er page e acho. Page bole "other.com theke chobi ano". Browser bhoy pay: "onno barir jinish, ora ki allow kore?" Tai age jiggesh kore (preflight). other.com jodi bole "ha, example.com theke ashle dibo" (CORS header), tobe browser ane. Na bolle block. Mane allow ta dite hoy jei server/bucket theke jinish ana hocche (cross-origin), tar upor.

Origin ki (PDF p. 325 (part p. 12))

  • CORS = Cross-Origin Resource Sharing.
  • Origin = scheme (protocol) + host (domain) + port. Ex: https://www.example.com (HTTPS er implied port 443, HTTP er 80).
  • CORS = web browser based mechanism: main origin visit korar shomoy onno origin e request allow/deny.
  • Onno origin CORS header (ex: Access-Control-Allow-Origin) diye allow na korle request fulfil hoy na.

Original explanation (English)

The shared responsibility model for infrastructure services, such as Amazon Elastic Compute Cloud (Amazon EC2) for example, specifies that AWS manages the security of the following assets:

  • Facilities
  • Physical security of hardware
  • Network infrastructure
  • Virtualization infrastructure 

You as the customer are responsible for the security of the following assets:

  • Amazon Machine Images (AMIs)
  • Operating systems
  • Applications
  • Data in transit
  • Data at rest
  • Data stores
  • Credentials
  • Policies and configuration
