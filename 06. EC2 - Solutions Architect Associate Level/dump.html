6·1D-Q158SAA-C03 dump · Q158

A company runs a high performance computing (HPC) workload on AWS. The workload required low-latency network performance and high network throughput with tightly coupled node-to-node communication. The Amazon EC2 instances are properly sized for compute and storage capacity, and are launched using default options. What should a solutions architect propose to improve the performance of the workload?

একটি company AWS-এ একটি high performance computing (HPC) workload চালায়। workload-টির tightly coupled node-to-node communication-সহ low-latency network performance এবং high network throughput প্রয়োজন ছিল। Amazon EC2 instance-গুলো compute এবং storage capacity-র জন্য সঠিকভাবে sized, এবং default option দিয়ে launch করা হয়েছে। workload-এর performance উন্নত করতে একজন solutions architect-এর কী প্রস্তাব করা উচিত?

Correct: A. Why it is right

Cluster placement group instance gulo ek AZ e kache kache rakhe, tai low latency ar high network throughput pay (PDF p. 85). Tightly coupled HPC node-to-node communication er jonno eta-i use hoy.

Why the other options are wrong

  • B. Dedicated tenancy hardware alada kore (compliance er jonno), network latency/throughput barabe na.
  • C. Elastic Inference ML inference er GPU accelerator chilo; network performance er sathe somporko nai.
  • D. Capacity reservation capacity guarantee kore, kintu instance gulor majhe network latency kombay na.

Keyword: HPC + low-latency + tightly coupled node-to-node → cluster placement group

Dump explanation (English)

https: //docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/aws-resource-ec2- placementgroup.html "A cluster placement group is a logical grouping of instances within a single Availability Zone that benefit from low network latency, high network throughput"

6·2D-Q538SAA-C03 dump · Q538

A company is deploying an application that processes large quantities of data in parallel. The company plans to use Amazon EC2 instances for the workload. The network architecture must be configurable to prevent groups of nodes from sharing the same underlying hardware. Which networking solution meets these requirements?

একটি company এমন একটি application deploy করছে, যা parallel-ভাবে বিপুল পরিমাণ data process করে। company workload-এর জন্য Amazon EC2 instance ব্যবহারের পরিকল্পনা করছে। network architecture এমনভাবে configurable হতে হবে যাতে node-এর group-গুলো একই underlying hardware share না করে। কোন networking solution এই requirement-গুলো পূরণ করে?

Correct: A. Why it is right

Nodes jeno same underlying hardware share na kore → spread placement group. Spread protita instance ke alada hardware (rack) e rakhe; ek AZ e max 7 instance per group (PDF p. 85, 87).

Check er note: 'groups of nodes' er jonno partition placement group aro valo fit hoto, kintu option e nai; dewa option er moddhe spread-i ekmatro placement solution.

Why the other options are wrong

  • B. Alada account e rakhle hardware alada hobe guarantee nai; account billing/security boundary, hardware placement control kore na.
  • C. Dedicated tenancy mane onno customer er sathe hardware share hoy na, kintu nijer instance gulo same hardware e thakte pare.
  • D. Shared tenancy default; hardware placement nie kono control dey na.

Keyword: prevent nodes from sharing the same underlying hardware → placement group (spread)

Dump explanation (English)

it allows the company to deploy an application that processes large quantities of data in parallel and prevent groups of nodes from sharing the same underlying hardware. By running the EC2 instances in a spread placement group, the company can launch a small number of instances across distinct underlying hardware to reduce correlated failures. A spread placement group ensures that each instance is isolated from each other at the rack level. Reference: Placement Groups Spread Placement Groups

6·3D-Q759SAA-C03 dump · Q759

A company plans to run a high performance computing (HPC) workload on Amazon EC2 Instances The workload requires low-latency network performance and high network throughput with tightly coupled node-to-node communication. Which solution will meet these requirements?

একটি company Amazon EC2 Instance-এ একটি high performance computing (HPC) workload চালানোর পরিকল্পনা করছে। workload-টির tightly coupled node-to-node communication-সহ low-latency network performance এবং high network throughput প্রয়োজন। কোন solution এই requirement-গুলো পূরণ করবে?

Correct: A. Why it is right

Cluster placement group instance gulo ek AZ e same rack er kachakachi rakhe: low latency, high network throughput (10 Gbps bandwidth between instances), tightly coupled HPC er jonno (PDF p. 85-86).

Why the other options are wrong

  • B. Dedicated Instance shudhu hardware ar kono customer er sathe share hoy na; network latency/throughput barai na.
  • C. Spot instance khoroch komay, kintu interrupt hote pare; latency/throughput er sathe somporko nai.
  • D. Capacity Reservation shudhu capacity guarantee kore; instance kachakachi rakhe na.

Keyword: low-latency + high network throughput + tightly coupled HPC → cluster placement group

Dump explanation (English)

Cluster Placement Group: This type of placement group is designed to provide low-latency network performance and high throughput by grouping instances within a single Availability Zone. It is ideal for applications that require tightly coupled node-to-node communication. Configuration: When launching EC2 instances, specify the option to launch them in a cluster placement group. This ensures that the instances are physically located close to each other, reducing latency and increasing network throughput. Benefits: Low-Latency Communication: Instances in a cluster placement group benefit from enhanced networking capabilities, enabling low-latency communication. High Network Throughput: The network performance within a cluster placement group is optimized for high throughput, which is essential for HPC workloads. Reference: Placement Groups High Performance Computing on AWS
