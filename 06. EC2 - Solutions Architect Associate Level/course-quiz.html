6·1U06-Q1Udemy quiz · sec 06 · Q1

You have launched an EC2 instance that will host a NodeJS application. After installing all the required software and configured your application, you noted down the EC2 instance public IPv4 so you can access it. Then, you stopped and then started your EC2 instance to complete the application configuration. After restart, you can't access the EC2 instance, and you found that the EC2 instance public IPv4 has been changed. What should you do to assign a fixed public IPv4 to your EC2 instance?

আপনি একটি EC2 instance launch করেছেন, যা একটি NodeJS application host করবে। সব প্রয়োজনীয় software install করে এবং application configure করার পরে, access করার জন্য আপনি EC2 instance-এর public IPv4 লিখে রেখেছেন। তারপর application configuration শেষ করতে আপনি EC2 instance stop করে আবার start করলেন। restart-এর পরে আপনি EC2 instance-এ access করতে পারছেন না, এবং দেখলেন EC2 instance-এর public IPv4 বদলে গেছে। আপনার EC2 instance-এ একটি fixed public IPv4 assign করতে আপনার কী করা উচিত?

Correct: A. Why it is right

EC2 instance stop → start korle tar public IPv4 bodlate pare (AWS er pool theke notun IP ashe). Fixed public IPv4 lagle Elastic IP allocate kore instance e associate koro (PDF p. 82).

Elastic IP holo ekta public IPv4 ja tumi own koro jotokkhon release (delete) na koro; ek somoy ek instance e attach hoy. Course hands-on e dekhano: EIP attach thakle stop/start er poreo IP same thake.

Why the other options are wrong

  • B. OS er bhitore public IP set kora jay na: instance er OS shudhu private IP dekhe (hostname e private IP), public IP AWS network level e map hoy. Static config dile network-i bhenge jete pare.
  • C. AWS Support er emon kono 'fixed public IP' service nai; console theke nijei Elastic IP allocate kora jay.
  • D. Bhul: Elastic IP diye fixed public IPv4 deya jay. Private IP to stop/start e emnitei same thake.

Keyword: public IPv4 changed after stop/start + fixed public IPv4 → Elastic IP

Instructor feedback (English)

A: Elastic IP is a public IPv4 that you own as long as you want and you can attach it to one EC2 instance at a time.

C: This can't be done, there's no such thing in AWS Support.

D: You can assign both public and private IPv4 to your EC2 instances.

6·2U06-Q2Udemy quiz · sec 06 · Q2

You have an application performing big data analysis hosted on a fleet of EC2 instances. You want to ensure your EC2 instances have the highest networking performance while communicating with each other. Which EC2 Placement Group should you choose?

EC2 instance-এর একটি fleet-এ আপনার একটি big data analysis করা application hosted আছে। আপনি নিশ্চিত করতে চান যে আপনার EC2 instance-গুলো একে অপরের সাথে communicate করার সময় সবচেয়ে বেশি networking performance পায়। আপনার কোন EC2 Placement Group বেছে নেওয়া উচিত?

Correct: B. Why it is right

Cluster placement group instance gulo ke ek AZ er bhitore low-latency hardware e pashapashi rakhe. Enhanced Networking on thakle instance gulor moddhe 10 Gbps bandwidth, low latency, high throughput (PDF p. 86).

Course er use case: Big Data job ja druto shesh korte hobe, ba app jar instance gulor moddhe extremely low latency + high network throughput lage. Ekhane exactly tai chawa hocche.

Why the other options are wrong

  • A. Spread protita instance alada physical hardware e (multi-AZ) rakhe failure risk komate; instance gulo dure dure thake, tai network performance best na.
  • C. Partition instance gulo ke alada rack er partition e bhag kore (Hadoop, Cassandra er moto) failure alada rakhar jonno; highest network performance er jonno na.

Keyword: highest networking performance between instances (big data) → Cluster placement group

Instructor feedback (English)

A: Spread Placement Group won't be suitable here as your EC2 instances are placed on different physical hardware. Thus, increases latency between your EC2 instances.

B: Cluster Placement Groups place your EC2 instances next to each other which gives you high-performance computing and networking.

C: Partition Placement Group won't be suitable here as your EC2 instances are grouped into partitions and distributed across different physical hardware. Thus, increases latency between your EC2 instances.

6·3U06-Q3Udemy quiz · sec 06 · Q3

You have a critical application hosted on a fleet of EC2 instances in which you want to achieve maximum availability when there's an AZ failure. Which EC2 Placement Group should you choose?

EC2 instance-এর একটি fleet-এ আপনার একটি critical application hosted আছে, যেখানে AZ failure হলে আপনি সর্বোচ্চ availability পেতে চান। আপনার কোন EC2 Placement Group বেছে নেওয়া উচিত?

Correct: C. Why it is right

Spread placement group e protita instance alada physical hardware e thake, ar group ta multiple AZ jure span korte pare. Tai ekta hardware ba ekta AZ fail korleo baki instance gulo bache (PDF p. 87).

Course er use case: app jar maximum high availability lage, ar critical app jekhane protita instance er failure onno gulo theke isolated. Limit: 7 instance per AZ per group.

Why the other options are wrong

  • A. Cluster sob instance ek AZ te rakhe; AZ fail korle sob instance ekshathe fail kore, ja maximum availability er ulto.
  • B. Partition boro distributed workload (HDFS, Cassandra) er jonno rack failure alada rakhe, kintu ek partition er onek instance ekshathe pore jete pare. Critical app er protita instance alada rakhte Spread better.

Keyword: critical application + maximum availability (AZ failure) → Spread placement group

Instructor feedback (English)

A: Cluster Placement Groups won't be suitable here your EC2 instances are placed next to each other which gives you high-performance computing and networking.

B: Partition Placement Group won't be suitable here as your EC2 instances are grouped into partitions and distributed across different physical hardware. The question doesn't ask about connectivity between EC2 instances.

C: Spread Placement Group places your EC2 instances on different physical hardware across different AZs.

6·4U06-Q4Udemy quiz · sec 06 · Q4

Elastic Network Interface (ENI) can be attached to EC2 instances in another AZ.

Elastic Network Interface (ENI) অন্য AZ-এর EC2 instance-এ attach করা যায়।

Correct: B. Why it is right

False. ENI ekta specific Availability Zone e bandha (PDF p. 90). ENI banate subnet choose korte hoy, ar subnet ek AZ er; tai shudhu oi AZ er EC2 instance e attach ba move kora jay.

Failover er jonno ENI ek instance theke arek instance e move kora jay, kintu dui instance-i same AZ e thakte hobe.

Why the other options are wrong

  • A. Bhul: ENI AZ-bound, onno AZ er instance e attach hoy na. Onno AZ e lagle oi AZ er subnet e notun ENI banate hobe.

Keyword: ENI + another AZ → False (ENI is bound to one AZ)

Instructor feedback (English)

B: Elastic Network Interfaces (ENIs) are bounded to a specific AZ. You can not attach an ENI to an EC2 instance in a different AZ.

6·5U06-Q5Udemy quiz · sec 06 · Q5

The following are true regarding EC2 Hibernate, EXCEPT:

EC2 Hibernate সম্পর্কে নিচেরগুলো সত্য, তবে এটি বাদে (EXCEPT):

Correct: A. Why it is right

EXCEPT proshno: bhul statement ta khujte hobe. Hibernate e RAM er state root EBS volume er ekta file e likha hoy, tai root volume must be EBS, encrypted, not instance store, ar RAM dhorar moto boro (PDF p. 92-93).

Tai 'root volume must be Instance Store' bhul → eta-i answer. Baki tin ta (On-Demand/Reserved support, RAM < 150 GB, root EBS) slide onujayi thik.

Why the other options are wrong

  • B. Thik statement: Hibernate On-Demand, Reserved ar Spot instance e available (PDF p. 93). EXCEPT proshne thik statement answer na.
  • C. Thik statement: instance RAM 150 GB er kom hote hobe (slide er limit; instructor bole limit bodlate pare, exam e dharona-i main).
  • D. Thik statement: root volume EBS hote hobe (ar encrypted), karon RAM er dump oi EBS e likha hoy.

Keyword: EXCEPT + Hibernate root volume → Instance Store bhul (must be encrypted EBS)

Instructor feedback (English)

A: To enable EC2 Hibernate, the EC2 Instance Root Volume type must be an EBS volume and must be encrypted to ensure the protection of sensitive content.
