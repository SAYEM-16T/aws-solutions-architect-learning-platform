27·1U27-Q1Udemy quiz · sec 27 · Q1

What does this CIDR 10.0.4.0/28 correspond to?

এই CIDR 10.0.4.0/28 কোন range নির্দেশ করে?

Correct: A. Why it is right

/28 mane 32 - 28 = 4 bit change hote pare, tai 2^4 = 16 ta IP (PDF p. 704). Base IP 10.0.4.0 theke shuru, tai range 10.0.4.0 - 10.0.4.15.

Shortcut: /24 er niche hole shudhu shesh octet bodlay; /28 = 16, /27 = 32, /26 = 64.

Why the other options are wrong

  • B. 10.0.4.0 theke 10.0.32.0 holo hazar hazar IP; /28 e mattro 16 ta IP, third octet bodlay na.
  • C. /28 er 28 ta IP mane na; 28 holo mask bit. /28 = 2^4 = 16 IP, shesh IP .15.
  • D. Eta third octet change kora boro range (/20 er kachakachi); /28 e shudhu shesh octet er 16 ta value.

Keyword: /28 → 2^(32-28) = 16 IP → 10.0.4.0 - 10.0.4.15

Instructor feedback (English)

A: /28 means 16 IPs (=2^(32-28) = 2^4), means only the last digit can change.

27·2U27-Q2Udemy quiz · sec 27 · Q2

You have a corporate network of size 10.0.0.0/8 and a satellite office of size 192.168.0.0/16. Which CIDR is acceptable for your AWS VPC if you plan on connecting your networks later on?

আপনার 10.0.0.0/8 size-এর একটি corporate network এবং 192.168.0.0/16 size-এর একটি satellite office আছে। পরে আপনার network-গুলো connect করার পরিকল্পনা থাকলে আপনার AWS VPC-র জন্য কোন CIDR গ্রহণযোগ্য?

Correct: B. Why it is right

Pore network jurte chaile VPC CIDR onno network er sathe overlap korbe na (PDF p. 708). 10.0.0.0/8 ar 192.168.0.0/16 baad dile baki private range 172.16.0.0/12.

Kintu VPC er ek CIDR er max size /16, tai /12 cholbe na. Uttor 172.16.0.0/16.

Why the other options are wrong

  • A. 172.16.0.0/12 overlap kore na thik, kintu VPC CIDR /16 er cheye boro hote pare na (max /16).
  • C. 10.0.16.0/16 corporate 10.0.0.0/8 er bhitore pore, overlap korbe.
  • D. 192.168.4.0/18 satellite office er 192.168.0.0/16 er bhitore, overlap korbe.

Keyword: connect later (no overlap) + VPC max /16 → 172.16.0.0/16

Instructor feedback (English)

B: CIDR not should overlap, and the max CIDR size in AWS is /16.

27·3U27-Q3Udemy quiz · sec 27 · Q3

You plan on creating a subnet and want it to have at least capacity for 28 EC2 instances. What's the minimum size you need to have for your subnet?

আপনি একটি subnet তৈরি করার পরিকল্পনা করছেন এবং চান এতে কমপক্ষে 28টি EC2 instance-এর capacity থাকুক। আপনার subnet-এর ন্যূনতম size কত হতে হবে?

Correct: C. Why it is right

AWS proti subnet e 5 ta IP reserve kore (first 4 + last 1), egulo EC2 ke dewa jay na (PDF p. 711).

  • /27 = 32 - 5 = 27 usable < 28, kom.
  • /26 = 64 - 5 = 59 usable ≥ 28, cholbe.

Slide er exam tip ei same hisab (29 IP er jonno /26).

Why the other options are wrong

  • A. /28 = 16 IP, 5 reserved, mattro 11 usable; 28 instance er jonno onek kom.
  • B. /27 = 32 IP, 5 reserved, 27 usable; 28 ta instance dhorbe na.
  • D. /25 = 128 IP, kaj korbe kintu question minimum size chay; /26 ei jothesto.

Keyword: at least 28 instances + minimum size + 5 reserved IP → /26

Instructor feedback (English)

A: Too small, it's 16 IPs, 5 of them already reserved by AWS.

B: Too small, it's 32 IPs, 5 of them already reserved by AWS.

C: Perfect size, 64 IPs.

D: Too big, it's 128 IPs.

27·5U27-Q5Udemy quiz · sec 27 · Q5

You have attached an Internet Gateway to your VPC, but your EC2 instances still don't have access to the internet. What is NOT a possible issue?

আপনি আপনার VPC-তে একটি Internet Gateway attach করেছেন, কিন্তু আপনার EC2 instance-গুলোর এখনও internet-এ access নেই। কোনটি সম্ভাব্য সমস্যা নয় (NOT a possible issue)?

Correct: C. Why it is right

Security Group stateful: instance theke outbound request gele tar return traffic automatic allowed, inbound rule lage na (PDF p. 731). Tai "SG inbound allow kore na" instance er internet access atkabe na, eta NOT possible issue.

Baki tin ta (route nai, public IP nai, NACL block) shotti karon hote pare.

Why the other options are wrong

  • A. IGW attach korlei hoy na, route table e 0.0.0.0/0 → IGW route lage (PDF p. 712); route na thakle internet nai, tai eta possible issue.
  • B. Public IP (ba EIP) chara instance internet e reachable na, eta possible issue.
  • D. NACL stateless; outbound deny korle traffic ber-i hobe na, tai eta possible issue.

Keyword: NOT a possible issue + SG stateful → SG inbound

Instructor feedback (English)

C: Security groups are stateful and if traffic can go out, then it can go back in.

27·6U27-Q6Udemy quiz · sec 27 · Q6

You would like to provide Internet access to your EC2 instances in private subnets with IPv4 while making sure this solution requires the least amount of administration and scales seamlessly. What should you use?

আপনি IPv4 দিয়ে private subnet-এর আপনার EC2 instance-গুলোকে Internet access দিতে চান, এবং নিশ্চিত করতে চান যে এই solution-এ সবচেয়ে কম administration লাগে এবং seamlessly scale করে। আপনার কী ব্যবহার করা উচিত?

"Least administration" + "scales seamlessly" = NAT Gateway.

Why the other options are wrong

  • A. NAT instance kaj korbe, kintu nijer EC2: patch, SG, failover script tomake manage korte hoy, bandwidth instance type e atka; auto scale hoy na.
  • B. Egress-only Internet Gateway shudhu IPv6 er jonno; question e IPv4.

Keyword: IPv4 + least administration + scales seamlessly → NAT Gateway

Instructor feedback (English)

A: This means creating a NAT EC2 Instance and although this would work, it would require some integration and would not scale seamlessly.

B: This is for IPv6 only.

VPC Peering has been enabled between VPC A and VPC B, and the route tables have been updated for VPC A. But, the EC2 instances cannot communicate. What is the likely issue?

VPC A ও VPC B-র মধ্যে VPC Peering enable করা হয়েছে, এবং VPC A-র route table update করা হয়েছে। কিন্তু EC2 instance-গুলো communicate করতে পারছে না। সম্ভাব্য সমস্যা কী?

Instructor feedback (English)

B: Route tables must be updated in both VPCs that are peered.

আপনি আপনার corporate data center ও আপনার AWS account-এর VPC A-র মধ্যে একটি Direct Connect connection set up করেছেন। আপনার corporate datacenter থেকে আরেকটি AWS region-এর VPC B-ও access করতে হবে। আপনার কী করা উচিত?

27·23U27-Q23Udemy quiz · sec 27 · Q23

A web application hosted on a fleet of EC2 instances managed by an Auto Scaling Group. You are exposing this application through an Application Load Balancer. Both the EC2 instances and the ALB are deployed on a VPC with the following CIDR 192.168.0.0/18. How do you configure the EC2 instances' security group to ensure only the ALB can access them on port 80?

একটি web application একটি Auto Scaling Group দিয়ে managed EC2 instance-এর একটি fleet-এ host করা। আপনি এই application একটি Application Load Balancer-এর মাধ্যমে expose করছেন। EC2 instance ও ALB দুটোই 192.168.0.0/18 CIDR সহ একটি VPC-তে deploy করা। শুধু ALB-ই যাতে port 80-এ EC2 instance-গুলো access করতে পারে, তা নিশ্চিত করতে EC2 instance-গুলোর security group কীভাবে configure করবেন?

Correct: C. Why it is right

EC2 SG er inbound rule e source hisebe ALB er Security Group reference koro (port 80). Tokhon shudhu oi SG wala ALB-i EC2 te ashte pare, IP bodlaleo kaj kore. Eta course er SG referencing er main pattern (ALB SG → EC2 SG).

Why the other options are wrong

  • A. 0.0.0.0/0 sobai ke port 80 e dhukte dey; shudhu ALB na.
  • B. VPC CIDR dile VPC er sob resource dhukte parbe, shudhu ALB na.
  • D. SSL certificate HTTPS encryption er jonno; ke EC2 access korbe ta control kore na.

Keyword: only the ALB can access EC2 → source = ALB's Security Group

C: This is the most secure way of ensuring only the ALB can access the EC2 instances. Referencing by security groups in rules is an extremely powerful rule and many questions at the exam rely on it. Make sure you fully master the concepts behind it!
