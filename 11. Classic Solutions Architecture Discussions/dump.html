11·1D-Q205SAA-C03 dump · Q205not in course

A company has a web application that is based on Java and PHP. The company plans to move the application from on premises to AWS. The company needs the ability to test new site features frequently. The company also needs a highly available and managed solution that requires minimum operational overhead Which solution will meet these requirements?

একটি company-র Java ও PHP-ভিত্তিক একটি web application আছে। company application-টি on premises থেকে AWS-এ সরানোর পরিকল্পনা করছে। company-র ঘন ঘন নতুন site feature test করার সুবিধা দরকার। company-র এমন একটি highly available ও managed solution-ও দরকার, যাতে minimum operational overhead লাগে। কোন solution এই requirement-গুলো পূরণ করবে?

Not in the course: Elastic Beanstalk er 'swap environment URLs' (blue/green) course e shekhano hoy na.

Correct: B. Why it is right

Elastic Beanstalk Java ar PHP app managed vabe chalay: EC2, ASG, ELB sob nije banay, tai highly available + minimum operational overhead (PDF p. 263).

Feature test er jonno alada Beanstalk environment banano jay, ar URL swap diye traffic notun environment e switch kora jay (blue/green). URL swap course e shekhano hoy na; Beanstalk er feature.

Why the other options are wrong

  • A. S3 static hosting Java/PHP server-side app chalate pare na; puro app Lambda te rewrite korte hobe.
  • C. EC2 + ASG + ALB kaj kore, kintu sob nijei configure/manage korte hoy, ar feature testing er sohoj mechanism nai.
  • D. Containerize kore Load Balancer Controller (Kubernetes) chalano onek kaj; managed, kom overhead solution na.

Keyword: Java and PHP + test features frequently + managed, minimum operational overhead → Elastic Beanstalk + URL swap

Dump explanation (English)

Frequent feature testing -- Multiple Elastic Beanstalk environments can be created easily for development, testing and production use cases. - Traffic can be routed between environments for A/B testing and feature iteration using simple URL swapping techniques. No complex routing rules or infrastructure changes required.

11·2D-Q452SAA-C03 dump · Q452

A solutions architect is implementing a complex Java application with a MySQL database. The Java application must be deployed on Apache Tomcat and must be highly available. What should the solutions architect do to meet these requirements?

একজন solutions architect একটি MySQL database সহ একটি complex Java application implement করছেন। Java application-টি Apache Tomcat-এ deploy করতে হবে এবং highly available হতে হবে। এই requirement-গুলো পূরণ করতে solutions architect-এর কী করা উচিত?

Correct: B. Why it is right

Elastic Beanstalk e Java on Tomcat managed platform ache (PDF p. 265). Load-balanced environment ALB + Auto Scaling + multi-AZ instance banay, tai highly available (HA with load balancer mode, PDF p. 267). Rolling deployment e batch batch update hoy, sob instance ekbare down hoy na.

Infra nije banate hoy na, tai simple ar HA.

Why the other options are wrong

  • A. Lambda Apache Tomcat server chalay na; complex Java Tomcat app ke Lambda te nite rewrite lagbe.
  • C. ElastiCache in-memory cache, MySQL er replacement na; app er relational DB dorkar, ar eta HA o deploy er problem solve kore na.
  • D. EC2 te MySQL install kore AMI banale protiti instance e alada DB copy hobe (data mile na), ar DB HA o manage nijeke korte hoy.

Keyword: Java on Apache Tomcat + highly available → Elastic Beanstalk load-balanced environment

Dump explanation (English)

AWS Elastic Beanstalk provides an easy and quick way to deploy, manage, and scale applications. It supports a variety of platforms, including Java and Apache Tomcat. By using Elastic Beanstalk, the solutions architect can upload the Java application and configure the environment to run Apache Tomcat.
