11·1U11-Q1Udemy quiz · sec 11 · Q1

Your website TriangleSunglasses.com is hosted on a fleet of EC2 instances managed by an Auto Scaling Group and fronted by an Application Load Balancer. Your ASG has been configured to scale on-demand based on the traffic going to your website. To reduce costs, you have configured the ASG to scale based on the traffic going through the ALB. To make the solution highly available, you have updated your ASG and set the minimum capacity to 2. How can you further reduce the costs while respecting the requirements?

আপনার website TriangleSunglasses.com একটি Auto Scaling Group দ্বারা managed EC2 instance-এর একটি fleet-এ hosted এবং সামনে একটি Application Load Balancer আছে। আপনার ASG আপনার website-এ আসা traffic-এর ভিত্তিতে on-demand scale করার জন্য configure করা হয়েছে। cost কমাতে, আপনি ASG-কে ALB দিয়ে যাওয়া traffic-এর ভিত্তিতে scale করার জন্য configure করেছেন। solution-টি highly available করতে, আপনি ASG update করে minimum capacity 2 সেট করেছেন। requirement-গুলো মেনে আপনি কীভাবে cost আরও কমাতে পারেন?

Correct: B. Why it is right

ASG er minimum capacity 2 mane ei 2 ta instance sob somoy cholbe (protita AZ e ekta, HA er jonno). Je instance sara bochor cholbe, segulo Reserved Instance korle On-Demand er cheye onek sosta (PDF p. 239, WhatIsTheTime.com er shesh dhap).

Scale-out e je extra instance ashe, segulo temporary, On-Demand e thakuk. Ei bhabe cost kome, kintu HA ar scaling duita-i thake.

Why the other options are wrong

  • A. ALB soriye Elastic IP dile ek IP ek instance e bandha; load balancing, health check ar ASG er scaling er subidha harabe. HA ar scaling duita-i bhange.
  • C. Min 1 korle ek AZ e ekta instance thakbe; oi instance ba AZ gele app down. Requirement (highly available) bhange.
  • D. Min 0 korle traffic kom thakle kono instance-i thakbe na, app downtime pabe. HA to durer kotha.

Keyword: minimum capacity 2 (sob somoy chole) + further reduce costs + HA rakhte hobe → oi 2 ta Reserve koro

Instructor feedback (English)

A: This is not efficient for scaling purposes.

B: This is the way to save further costs as we will run 2 EC2 instances no matter what.

C: Our solution won't be highly available anymore.

D: Our solution will experience downtime.

11·2U11-Q2Udemy quiz · sec 11 · Q2

Which of the following will NOT help us while designing a STATELESS application tier?

একটি STATELESS application tier design করার সময় নিচের কোনটি আমাদের সাহায্য করবে না (NOT)?

Correct: D. Why it is right

Prosno ta NOT chay. Stateless tier mane je kono EC2 je kono request serve korte parbe, tai session data shared jaygay ba client er kache rakhte hobe.

EBS volume ek AZ e bandha ar sadharonoto ek somoy ek instance e attach thake. Session EBS e rakhle shudhu oi instance session jane; onno instance pay na. Tai eta stateless design e help kore na (MyClothes.com, PDF p. 245).

Why the other options are wrong

  • A. RDS e session rakhle sob EC2 same database theke porte pare, tai web tier stateless thake. Eta help kore, NOT er uttor na.
  • B. ElastiCache course er main session store: cookie te session_id, data ElastiCache e, je kono EC2 pore (PDF p. 245). Help kore.
  • C. Client cookie te session rakhle EC2 ke kichu mone rakhte hoy na, tai stateless (PDF p. 244). Help kore (cookie 4 KB limit, validate lage).

Keyword: STATELESS + NOT help → session EBS e (ek instance/AZ e bandha, share hoy na)

Instructor feedback (English)

A: This will help as the data can be accessed from multiple EC2 instances.

B: This will help as the data can be accessed from multiple EC2 instances.

C: This will help as the clients send their session data so that our EC2 instances don't need to remember/store session data.

D: EBS volumes are created in a specific AZ and can only be attached to one EC2 instance at a time.

11·3U11-Q3Udemy quiz · sec 11 · Q3

You want to install software updates on 100s of Linux EC2 instances that you manage. You want to store these updates on shared storage which should be dynamically loaded on the EC2 instances and shouldn't require heavy operations. What do you suggest?

আপনি যে 100s Linux EC2 instance manage করেন, সেগুলোতে software update install করতে চান। আপনি এই update-গুলো একটি shared storage-এ store করতে চান, যা EC2 instance-গুলোতে dynamically load হবে এবং যার জন্য ভারী operation লাগবে না। আপনি কী suggest করবেন?

Correct: B. Why it is right

EFS holo managed NFS network file system. Onek (100s) Linux EC2 eki file system ekshathe mount korte pare, onek AZ theke-o (PDF p. 113, MyWordPress.com PDF p. 257).

Update gulo EFS e rakho, protita instance startup e EFS mount kore update pore nibe. Kono sync ba copy er jhamela nai = kom operation.

Why the other options are wrong

  • A. EBS share hoy na, tai protita AZ e master ar replication software lagbe. Eta native AWS feature na, ar heavy operation.
  • C. Protita update er jonno snapshot theke notun EBS volume banano kaj korbe, kintu onek manual kaj; ar EBS share hoy na. Heavy operation.
  • D. RDS relational data er jonno, software update er moto boro binary file rakhar ba mount korar jonno na.

Keyword: 100s of Linux EC2 + shared storage + no heavy operations → EFS mount

Instructor feedback (English)

A: This requires too many operations and is not a native AWS feature.

B: EFS is a network file system (NFS) that allows you to mount the same file system to 100s of EC2 instances. Storing software updates on an EFS allows each EC2 instance to access them.

C: This requires too many operations although it would work.

D: RDS is meant to store relational data, not big binary files.

11·4U11-Q4Udemy quiz · sec 11 · Q4

As a Solutions Architect, you're planning to migrate a complex ERP software suite to AWS Cloud. You're planning to host the software on a set of Linux EC2 instances managed by an Auto Scaling Group. The software traditionally takes over an hour to set up on a Linux machine. How do you recommend you speed up the installation process when there's a scale-out event?

একজন Solutions Architect হিসেবে, আপনি একটি complex ERP software suite AWS Cloud-এ migrate করার পরিকল্পনা করছেন। আপনি software-টি একটি Auto Scaling Group দ্বারা managed কিছু Linux EC2 instance-এ host করার পরিকল্পনা করছেন। software-টি সাধারণত একটি Linux machine-এ setup হতে এক ঘণ্টার বেশি সময় নেয়। scale-out event হলে installation process দ্রুত করতে আপনি কী recommend করবেন?

Correct: A. Why it is right

Golden AMI = software age theke install ar configure kore banano AMI. ASG scale-out e notun EC2 oi AMI theke boot kore, tai 1 ghontar install ar lage na; sobcheye druto start (PDF p. 260).

Course er niyom: slow, ek-i rokom install AMI te; shudhu dynamic config User Data te.

Why the other options are wrong

  • B. User Data install ta automate kore, kintu install protita notun instance e boot er somoy ghote, tai ekhono 1 ghonta lagbe.
  • C. RDS relational data rakhe, application install rakhe na ba chalay na.
  • D. Setup file EFS theke anle download hoyto shohoj, kintu install ar configure korte ekhono 1 ghonta lagbe.

Keyword: over an hour to set up + speed up scale-out → Golden AMI

Instructor feedback (English)

A: Golden AMI is an image that contains all your software installed and configured so that future EC2 instances can boot up quickly from that AMI.

B: EC2 User Data allows you to automate the installation steps, but the installation would still take one hour to complete.

C: RDS is used to store relational data, not applications.

D: Retrieving application setup files from EFS won't help speed up the installation and configuration time.

11·5U11-Q5Udemy quiz · sec 11 · Q5

You're developing an application and would like to deploy it to Elastic Beanstalk with minimal cost. You should run it in ..................

আপনি একটি application develop করছেন এবং minimal cost-এ এটি Elastic Beanstalk-এ deploy করতে চান। আপনার এটি .................. -এ চালানো উচিত

Correct: A. Why it is right

Beanstalk er Single Instance mode e ekta EC2 + Elastic IP (load balancer nai), optional RDS. Course bole eta dev er jonno great (PDF p. 267).

Development stage + minimal cost → Single Instance. Beanstalk nije free, tumi shudhu resource er dam dao, tai kom resource = kom dam.

Why the other options are wrong

  • B. High Availability mode ALB + ASG e multi-AZ e onek EC2 (ar RDS Multi-AZ) banay. Production er jonno bhalo, kintu load balancer ar beshi instance er jonno beshi dam.

Keyword: developing + minimal cost → Single Instance mode

Instructor feedback (English)

A: The question mentions that you're still in the development stage and you want to reduce costs. Single Instance Mode will create one EC2 instance and one Elastic IP.

B: This will create one or more EC2 instances and one Elastic Load Balancer (this costs more).

11·6U11-Q6Udemy quiz · sec 11 · Q6

You're deploying your application to an Elastic Beanstalk environment but you notice that the deployment process is painfully slow. After reviewing the logs, you found that your dependencies are resolved on each EC2 instance each time you deploy. How can you speed up the deployment process with minimal impact?

আপনি আপনার application একটি Elastic Beanstalk environment-এ deploy করছেন, কিন্তু দেখছেন deployment process খুবই ধীর। log review করে দেখলেন, প্রতিবার deploy করার সময় প্রতিটি EC2 instance-এ আপনার dependency-গুলো resolve হচ্ছে। minimal impact-এ আপনি কীভাবে deployment process দ্রুত করতে পারেন?

Correct: C. Why it is right

Problem: protita deploy e protita EC2 te dependency resolve/download hocche. Dependency gulo Golden AMI te age theke install kore rakho, Beanstalk ke oi custom AMI diye EC2 launch korte dao. Tahole deploy e shudhu code jay, dependency step bad (PDF p. 260).

Code e kono change lage na = minimal impact. Beanstalk nijei Golden AMI + User Data hybrid principle use kore.

Why the other options are wrong

  • A. Dependency soriye dile app bhenge jete pare; code change lage. Minimal impact na.
  • B. EFS e rakhle file shared hoy, kintu dependency resolve/install er step protita instance e ekhono chole; ar network drive theke load slow hote pare.

Keyword: dependencies resolved on each EC2 each deploy + minimal impact → dependency soho Golden AMI

Instructor feedback (English)

C: Golden AMI is an image that contains all your software, dependencies, and configurations, so that future EC2 instances can boot up quickly from that AMI.
