8·1U08-Q1Udemy quiz · sec 08 · Q1

Scaling an EC2 instance from r4.large to r4.4xlarge is called .....................

Correct: B. Why it is right

Instance er size barano (r4.large → r4.4xlarge) = Vertical Scalability, mane scale up (PDF p. 121, 124). Instance er sonkhya same thake, shudhu ekta-i boro hoy.

Vertical scaling er hardware limit ache, ar eta DB er moto non-distributed system e common.

Why the other options are wrong

  • A. Horizontal = instance er sonkhya barano (scale out/in). Ekhane sonkhya na, size barche.

Keyword: r4.large → r4.4xlarge (boro size) → Vertical (scale up)

8·2U08-Q2Udemy quiz · sec 08 · Q2

Running an application on an Auto Scaling Group that scales the number of EC2 instances in and out is called .....................

Correct: A. Why it is right

ASG instance er sonkhya barano-komano kore (scale out / scale in) = Horizontal Scalability (PDF p. 122, 124). Horizontal scaling distributed system e hoy, web app e common.

Why the other options are wrong

  • B. Vertical = ekta instance er size barano (scale up/down). ASG instance er size bodlay na, sonkhya bodlay.

Keyword: ASG number of instances in/out → Horizontal

8·3U08-Q3Udemy quiz · sec 08 · Q3

Elastic Load Balancers provide a .......................

Correct: B. Why it is right

Sob ELB ekta static DNS name dey (XXX.region.elb.amazonaws.com), app ei ek endpoint use kore (PDF p. 126, 137). Pichoner infrastructure AWS bodlaleo DNS name same thake.

Static IP dey shudhu NLB (AZ proti ekta, Elastic IP o dewa jay). Tai general ELB er uttor: static DNS name.

Why the other options are wrong

  • A. Static IPv4 shob ELB dey na; shudhu NLB dey. ALB/CLB er IP bodlate pare, tai DNS name use koro.
  • C. ELB static IPv6 dey na. Fixed endpoint holo DNS name.

Keyword: Elastic Load Balancers provide (sob type) → static DNS name

Instructor feedback (English)

B: Only Network Load Balancer provides both static DNS name and static IP. While, Application Load Balancer provides a static DNS name but it does NOT provide a static IP. The reason being that AWS wants your Elastic Load Balancer to be accessible using a static endpoint, even if the underlying infrastructure that AWS manages changes.

8·4U08-Q4Udemy quiz · sec 08 · Q4

You are running a website on 10 EC2 instances fronted by an Elastic Load Balancer. Your users are complaining about the fact that the website always asks them to re-authenticate when they are moving between website pages. You are puzzled because it's working just fine on your machine and in the Dev environment with 1 EC2 instance. What could be the reason?

Correct: C. Why it is right

Dev e 1 ta instance, tai sob request ek-i instance e jay, session thake. Production e 10 ta instance: ELB request gulo alada instance e pathay, notun instance e user er session nai, tai abar login chay.

Fix: Sticky Sessions (session affinity). Cookie diye ek client ke sob somoy ek-i instance e pathay, user session data harabe na (PDF p. 143).

Why the other options are wrong

  • A. Website e bug na; 1 instance e thik chole. Problem holo request alada instance e jacche, session share hocche na.
  • B. Instance client IP na dekhle-o logout kore na. Client IP lagle X-Forwarded-For header ache; login harano stickiness er problem.

Keyword: 10 instances + bar bar re-authenticate, 1 instance e thik → Sticky Sessions nai

Instructor feedback (English)

C: ELB Sticky Session feature ensures traffic for the same client is always redirected to the same target (e.g., EC2 instance). This helps that the client does not lose his session data.

8·5U08-Q5Udemy quiz · sec 08 · Q5

You are using an Application Load Balancer to distribute traffic to your website hosted on EC2 instances. It turns out that your website only sees traffic coming from private IPv4 addresses which are in fact your Application Load Balancer's IP addresses. What should you do to get the IP address of clients connected to your website?

Correct: B. Why it is right

ALB connection termination kore: EC2 te notun connection khole nijer private IP diye. Tai app shudhu ALB er IP dekhe (PDF p. 137).

Ashol client IP ALB header X-Forwarded-For e boshay. Backend ei header theke client IP porbe.

Why the other options are wrong

  • A. User ke IP pathate bola lagbe na, ar user er pathano IP bishwasjoggo na. ALB nijei X-Forwarded-For e client IP dey.
  • C. X-Forwarded-Port e client er port thake, IP na.
  • D. X-Forwarded-Proto e protocol (HTTP/HTTPS) thake, IP na.

Keyword: ALB er private IP dekhe, client IP chai → X-Forwarded-For

Instructor feedback (English)

B: When using an Application Load Balancer to distribute traffic to your EC2 instances, the IP address you'll receive requests from will be the ALB's private IP addresses. To get the client's IP address, ALB adds an additional header called "X-Forwarded-For" contains the client's IP address.

C: "X-Forwarded-Port" used to get the client's requested port.

D: "X-Forwarded-Proto" used to get the client's requested protocol.

8·6U08-Q6Udemy quiz · sec 08 · Q6

You hosted an application on a set of EC2 instances fronted by an Elastic Load Balancer. A week later, users begin complaining that sometimes the application just doesn't work. You investigate the issue and found that some EC2 instances crash from time to time. What should you do to protect users from connecting to the EC2 instances that are crashing?

Correct: A. Why it is right

ELB Health Check port ar route (ex: /health) e check kore; 200 OK na pele instance unhealthy, ELB oi instance e traffic pathano bondho kore (PDF p. 128).

Tai crash kora instance e user ar jabe na.

Why the other options are wrong

  • B. Stickiness ek client ke ek-i instance e bendhe rakhe; crash kora instance e user atke jete pare, problem barbe.
  • C. SSL termination holo HTTPS decrypt kora LB e; instance healthy ki na ta dekhe na.
  • D. Cross-zone sob AZ er instance e shoman traffic bhag kore; unhealthy instance ke bad dey na.

Keyword: kichu instance crash, user jeno oikhane na jay → ELB Health Checks

Instructor feedback (English)

A: When you enable ELB Health Checks, your ELB won't send traffic to unhealthy (crashed) EC2 instances.

8·7U08-Q7Udemy quiz · sec 08 · Q7

You are working as a Solutions Architect for a company and you are required to design an architecture for a high-performance, low-latency application that will receive millions of requests per second. Which type of Elastic Load Balancer should you choose?

Correct: C. Why it is right

NLB Layer 4 (TCP/UDP), millions of requests per second handle kore, ultra-low latency (PDF p. 138). Extreme performance lagle NLB.

Why the other options are wrong

  • A. ALB Layer 7, HTTP request er bhitor dekhe routing kore; flexible kintu NLB er moto extreme performance/lowest latency na.
  • B. CLB purono generation (deprecated); high performance er jonno na.

Keyword: high-performance, low-latency, millions of requests per second → NLB

Instructor feedback (English)

C: Network Load Balancer provides the highest performance and lowest latency if your application needs it.

8·8U08-Q8Udemy quiz · sec 08 · Q8

Application Load Balancers support the following protocols, EXCEPT:

Correct: C. Why it is right

ALB Layer 7: HTTP, HTTPS, WebSocket (ar HTTP/2) support kore (PDF p. 129, 132). Plain TCP Layer 4, sheta NLB er kaj.

Why the other options are wrong

  • A. HTTP ALB support kore (Layer 7 er mul protocol).
  • B. HTTPS ALB support kore; ACM certificate diye SSL termination o kore.
  • D. WebSocket ALB support kore (PDF p. 132).

Keyword: ALB EXCEPT → TCP (TCP = NLB)

Instructor feedback (English)

C: Application Load Balancers support HTTP, HTTPS and WebSocket

8·9U08-Q9Udemy quiz · sec 08 · Q9

Application Load Balancers can route traffic to different Target Groups based on the following, EXCEPT:

Correct: A. Why it is right

ALB routing kore URL path, hostname, query string, header diye (PDF p. 133); listener rule condition e source IP ar HTTP method o ache (hands-on).

Client er geography (location) diye ALB route kore na; location based routing Route 53 er kaj.

Why the other options are wrong

  • B. Hostname routing ALB kore: one.example.com vs other.example.com (PDF p. 133).
  • C. Path routing ALB kore: example.com/users vs /posts (PDF p. 133).
  • D. Listener rule e source IP condition dewa jay, tai eta ALB support kore.

Keyword: ALB routing EXCEPT → Client Location (Geography)

Instructor feedback (English)

A: ALBs can route traffic to different Target Groups based on URL Path, Hostname, HTTP Headers, and Query Strings.

8·10U08-Q10Udemy quiz · sec 08 · Q10

Registered targets in a Target Groups for an Application Load Balancer can be one of the following, EXCEPT:

Correct: B. Why it is right

ALB target group e thakte pare: EC2 instances, ECS tasks, Lambda functions, private IP addresses (PDF p. 135).

NLB ALB er target hote pare na. Ulto ta hoy: ALB NLB er target hote pare (PDF p. 140).

Why the other options are wrong

  • A. EC2 instance ALB er sobcheye common target (ASG manage korte pare).
  • C. Private IP target hoy, jemon on-premises server (PDF p. 135, 136).
  • D. Lambda ALB er target hoy; HTTP request JSON event e translate hoy (PDF p. 135).

Keyword: ALB target EXCEPT → Network Load Balancer (ulto ta valid: NLB → ALB)

8·11U08-Q11Udemy quiz · sec 08 · Q11

For compliance purposes, you would like to expose a fixed static IP address to your end-users so that they can write firewall rules that will be stable and approved by regulators. What type of Elastic Load Balancer would you choose?

Correct: B. Why it is right

NLB e AZ proti ekta static IP, ar Elastic IP assign kora jay (PDF p. 138). User/regulator ei fixed IP diye firewall rule likhte pare, IP bodlabe na.

Why the other options are wrong

  • A. ALB e Elastic IP attach kora jay na. ALB shudhu static DNS name dey, IP bodlate pare.
  • C. CLB o shudhu static DNS name dey, fixed static IP na. Ar CLB deprecated.

Keyword: fixed static IP + firewall rules → NLB

Instructor feedback (English)

A: You can't attach an Elastic IP address to Application Load Balancers.

B: Network Load Balancer has one static IP address per AZ and you can attach an Elastic IP address to it. Application Load Balancers and Classic Load Balancers have a static DNS name.

You want to create a custom application-based cookie in your Application Load Balancer. Which of the following you can use as a cookie name?

Custom application-based cookie er naam tumi dao, kintu AWSALB, AWSALBAPP, AWSALBTG use kora jabe na: ei naam gulo ELB er jonno reserved (PDF p. 144).

Tai APPUSERC er moto onno naam valid.

  • C. AWSALBTG ELB er reserved naam, custom cookie te use kora jay na.
  • D. AWSALB reserved: ALB er duration-based cookie er naam.

8·13U08-Q13Udemy quiz · sec 08 · Q13

You have a Network Load Balancer that distributes traffic across a set of EC2 instances in us-east-1. You have 2 EC2 instances in us-east-1b AZ and 5 EC2 instances in us-east-1e AZ. You have noticed that the CPU utilization is higher in the EC2 instances in us-east-1b AZ. After more investigation, you noticed that the traffic is equally distributed across the two AZs. How would you solve this problem?

Correct: A. Why it is right

NLB e cross-zone default off (PDF p. 146). Off thakle traffic age AZ proti shoman (50% / 50%), tarpor AZ er bhitore. us-east-1b er 2 ta instance protiti 25% pay, 1e er 5 ta protiti 10%: tai 1b er CPU beshi.

Cross-Zone Load Balancing enable korle sob AZ er 7 ta instance e shoman bhag hoy (PDF p. 145). NLB e on korle inter-AZ data charge lage.

Why the other options are wrong

  • B. Sticky session ek client ke ek instance e bendhe rakhe; AZ er moddhe asoman bhag thik kore na, ulto imbalance barate pare.
  • C. Health check unhealthy instance bad dey; instance gulo healthy, problem traffic er bhag.
  • D. SSL termination encryption er bishoy; traffic distribution bodlay na.

Keyword: AZ e instance 2 vs 5, traffic AZ e equally → Cross-Zone Load Balancing

Instructor feedback (English)

A: When Cross-Zone Load Balancing is enabled, ELB distributes traffic evenly across all registered EC2 instances in all AZs.

8·14U08-Q14Udemy quiz · sec 08 · Q14

Which feature in both Application Load Balancers and Network Load Balancers allows you to load multiple SSL certificates on one listener?

Correct: B. Why it is right

SNI (Server Name Indication): client SSL handshake e hostname bole dey, LB oi hostname er certificate khuje dey. Ete ek listener e onek SSL certificate load kora jay (PDF p. 149-150).

SNI kaj kore ALB, NLB ar CloudFront e; CLB e na.

Why the other options are wrong

  • A. TLS termination = LB e HTTPS decrypt kora; eta multiple certificate er feature na.
  • C. Security policy purono SSL/TLS version (legacy client) support er jonno (PDF p. 148); certificate select kore na.
  • D. Host header ALB er routing condition; certificate load kora na.

Keyword: multiple SSL certificates on one listener (ALB + NLB) → SNI

8·15U08-Q15Udemy quiz · sec 08 · Q15

You have an Application Load Balancer that is configured to redirect traffic to 3 Target Groups based on the following hostnames: users.example.com, api.external.example.com, and checkout.example.com. You would like to configure HTTPS for each of these hostnames. How do you configure the ALB to make this work?

Correct: C. Why it is right

Tin ta hostname, protita te nijer certificate. HTTPS listener e onek certificate rakha jay, ar SNI diye client je hostname chay oi certificate dewa hoy (PDF p. 148-150). Tarpor host rule thik target group e pathay.

Why the other options are wrong

  • A. HTTP → HTTPS redirect user ke HTTPS e pathay, kintu protita hostname er certificate er problem solve kore na.
  • B. Security group firewall; 'security group SSL certificate' bole kono feature nai.

Keyword: ek ALB, 3 hostnames, sobai HTTPS → SNI

Instructor feedback (English)

C: Server Name Indication (SNI) allows you to expose multiple HTTPS applications each with its own SSL certificate on the same listener. Read more here: https://aws.amazon.com/blogs/aws/new-application-load-balancer-sni/

8·16U08-Q16Udemy quiz · sec 08 · Q16

You have an application hosted on a set of EC2 instances managed by an Auto Scaling Group that you configured both desired and maximum capacity to 3. Also, you have created a CloudWatch Alarm that is configured to scale out your ASG when CPU Utilization reaches 60%. Your application suddenly received huge traffic and is now running at 80% CPU Utilization. What will happen?

Correct: A. Why it is right

ASG kokhono maximum capacity er upore jay na. Desired already 3 = max 3, tai CPU 80% e alarm trigger holeo notun instance add hobe na: kichui hoy na.

Scale out chaile max size barate hobe (PDF p. 153, 155).

Why the other options are wrong

  • B. Desired max er beshi hote pare na; max 3 thakle desired 4 hobe na.
  • C. Alarm nijer theke max capacity bodlay na; max tumi set koro.

Keyword: desired = maximum = 3 → scale out alarm e-o Nothing

Instructor feedback (English)

A: The Auto Scaling Group can't go over the maximum capacity (you configured) during scale-out events.

8·17U08-Q17Udemy quiz · sec 08 · Q17

You have an Auto Scaling Group fronted by an Application Load Balancer. You have configured the ASG to use ALB Health Checks, then one EC2 instance has just been reported unhealthy. What will happen to the EC2 instance?

আপনার একটি Auto Scaling Group আছে, যার সামনে একটি Application Load Balancer রয়েছে। আপনি ASG-কে ALB Health Checks ব্যবহার করার জন্য configure করেছেন, তারপর একটি EC2 instance এইমাত্র unhealthy হিসেবে report হয়েছে। EC2 instance-টির কী হবে?

Correct: C. Why it is right

ASG ke ALB (ELB) health check use korte set korle, ALB unhealthy bolle ASG oi instance ke terminate kore, ar notun instance launch kore (PDF p. 152, 154).

Default (EC2 health check) e shudhu EC2 status dekhe; ELB check on thakle app level er failure o dhore.

Why the other options are wrong

  • A. ASG application restart kore na; unhealthy instance terminate kore replace kore.
  • B. Detach kore chalu rakha ASG er health check er behavior na; unhealthy instance terminate hoy.

Keyword: ASG uses ALB Health Checks + instance unhealthy → terminate (ar replace)

Instructor feedback (English)

C: You can configure the Auto Scaling Group to determine the EC2 instances' health based on Application Load Balancer Health Checks instead of EC2 Status Checks (default). When an EC2 instance fails the ALB Health Checks, it is marked unhealthy and will be terminated while the ASG launches a new EC2 instance.

8·18U08-Q18Udemy quiz · sec 08 · Q18

Your boss asked you to scale your Auto Scaling Group based on the number of requests per minute your application makes to your database. What should you do?

আপনার boss আপনাকে বলেছেন, আপনার application প্রতি মিনিটে database-এ যতগুলো request করে, সেই সংখ্যার ভিত্তিতে Auto Scaling Group scale করতে। আপনার কী করা উচিত?

Correct: A. Why it is right

'App theke database e request per minute' er kono built-in CloudWatch metric nai. Tai app theke CloudWatch custom metric push koro, tar upor CloudWatch Alarm baniye ASG scale koro (PDF p. 156, 159: 'any custom metric').

Why the other options are wrong

  • B. Impossible na: custom metric + alarm diye je kono metric e scale kora jay.
  • C. Detailed monitoring shudhu EC2 metric 1 minute e dey; DB request count er moto app metric dey na.

Keyword: requests per minute to your database (built-in metric nai) → custom metric + alarm

Instructor feedback (English)

A: There's no CloudWatch Metric for "requests per minute" for backend-to-database connections. You need to create a CloudWatch Custom Metric, then create a CloudWatch Alarm.

8·19U08-Q19Udemy quiz · sec 08 · Q19

An application is deployed with an Application Load Balancer and an Auto Scaling Group. Currently, you manually scale the ASG and you would like to define a Scaling Policy that will ensure the average number of connections to your EC2 instances is around 1000. Which Scaling Policy should you use?

একটি application একটি Application Load Balancer এবং একটি Auto Scaling Group দিয়ে deploy করা আছে। বর্তমানে আপনি ASG manually scale করেন, এবং আপনি এমন একটি Scaling Policy define করতে চান যা নিশ্চিত করবে যে আপনার EC2 instance-গুলোতে গড় connection সংখ্যা প্রায় 1000 থাকবে। কোন Scaling Policy ব্যবহার করা উচিত?

'Average ~1000 connection rakho' = ekta metric ke target value er kache rakha. Eta Target Tracking policy (PDF p. 157: 'average ASG CPU ~40% e rakho'). ASG nije alarm baniye scale out/in kore.
