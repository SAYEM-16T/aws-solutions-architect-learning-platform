28·1U28-Q1Udemy quiz · sec 28 · Q1

As part of your Disaster Recovery plan, you would like to have only the critical infrastructure up and running in AWS. You don't mind a longer Recovery Time Objective (RTO). Which DR strategy do you recommend?

আপনার Disaster Recovery plan-এর অংশ হিসেবে, আপনি AWS-এ শুধু critical infrastructure চালু রাখতে চান। একটি দীর্ঘ Recovery Time Objective (RTO)-তে আপনার আপত্তি নেই। আপনি কোন DR strategy recommend করবেন?

Correct: B. Why it is right

Pilot Light: app er ekta chhoto version, mane shudhu critical core (jemon RDS running) cloud e shob shomoy chole; EC2 gulo running thake na (PDF p. 783).

Disaster e baki infra chalu korte hoy, tai RTO Warm Standby er theke beshi, kintu Backup and Restore er theke kom. 'Longer RTO cholbe' + 'shudhu critical infra' = Pilot Light.

Why the other options are wrong

  • A. Backup and Restore e kichui running thake na, shudhu backup/snapshot; question e critical infra running chawa hoyeche.
  • C. Warm Standby e full system minimum size e running thake; shudhu critical na, ar khoroch beshi.
  • D. Multi-Site e full production scale active-active chole; sobcheye beshi khoroch, critical-only na.

Keyword: only the critical infrastructure running + longer RTO ok → Pilot Light

Instructor feedback (English)

B: If you're interested, read more about Disaster Recovery options in AWS here: https://docs.aws.amazon.com/whitepapers/latest/disaster-recovery-workloads-on-aws/disaster-recovery-options-in-the-cloud.html

28·2U28-Q2Udemy quiz · sec 28 · Q2

You would like to get the Disaster Recovery strategy with the lowest Recovery Time Objective (RTO) and Recovery Point Objective (RPO), regardless of the cost. Which DR should you choose?

খরচ যাই হোক না কেন, আপনি সবচেয়ে কম Recovery Time Objective (RTO) এবং Recovery Point Objective (RPO) সহ Disaster Recovery strategy পেতে চান। আপনার কোন DR বেছে নেওয়া উচিত?

Correct: D. Why it is right

DR strategy gulo RTO onujayi: Backup and Restore → Pilot Light → Warm Standby → Multi-Site (PDF p. 781).

Multi Site / Hot Site e full production scale on-premise ar AWS dui jaygay active chole, tai RTO minutes ba seconds; kintu very expensive (PDF p. 785). 'Regardless of cost' + lowest RTO/RPO = Multi-Site.

Why the other options are wrong

  • A. Backup and Restore er RPO ar RTO sobcheye beshi (sobcheye slow), lowest na.
  • B. Pilot Light e baki system chalu korte shomoy lage; RTO lowest na.
  • C. Warm Standby e scale up korte hoy, Multi-Site er cheye RTO beshi.

Keyword: lowest RTO and RPO, regardless of cost → Multi-Site

Instructor feedback (English)

D: If you're interested, read more about Disaster Recovery options in AWS here: https://docs.aws.amazon.com/whitepapers/latest/disaster-recovery-workloads-on-aws/disaster-recovery-options-in-the-cloud.html

28·3U28-Q3Udemy quiz · sec 28 · Q3

Which of the following Disaster Recovery strategies has a potentially high Recovery Point Objective (RPO) and Recovery Time Objective (RTO)?

নিচের কোন Disaster Recovery strategy-র সম্ভাব্যভাবে high Recovery Point Objective (RPO) এবং Recovery Time Objective (RTO) আছে?

Correct: A. Why it is right

Backup and Restore slide er title-i 'High RPO' (PDF p. 782). Backup (snapshot, S3/Glacier) shudhu schedule e hoy, tai last backup er por er data harate pare (high RPO).

Disaster e sob kichu backup theke notun kore create korte hoy, tai RTO o beshi. Sobcheye shosta, kintu sobcheye slow.

Why the other options are wrong

  • B. Pilot Light e critical core (DB) running ar replicate hoy, tai RPO/RTO Backup and Restore er theke kom.
  • C. Warm Standby e full system minimum size e running, RTO/RPO onek kom.
  • D. Multi-Site e RTO minutes/seconds; sobcheye kom, high na.

Keyword: potentially high RPO and RTO → Backup and Restore

Instructor feedback (English)

A: If you're interested, read more about Disaster Recovery options in AWS here: https://docs.aws.amazon.com/whitepapers/latest/disaster-recovery-workloads-on-aws/disaster-recovery-options-in-the-cloud.html

28·4U28-Q4Udemy quiz · sec 28 · Q4

You want to make a Disaster Recovery plan where you have a scaled-down version of your system up and running, and when a disaster happens, it scales up quickly. Which DR strategy should you choose?

আপনি এমন একটি Disaster Recovery plan তৈরি করতে চান, যেখানে আপনার system-এর একটি scaled-down version চালু থাকে, এবং disaster ঘটলে এটি দ্রুত scale up করে। আপনার কোন DR strategy বেছে নেওয়া উচিত?

Correct: C. Why it is right

Warm Standby: full system up and running, kintu minimum size e (jemon ASG minimum, RDS secondary running). Disaster hole production load e scale up kora hoy (PDF p. 784).

Why the other options are wrong

  • A. Backup and Restore e kono system running thake na, shudhu backup.
  • B. Pilot Light e shudhu critical core (DB) running, full system na; baki gulo pore chalu korte hoy.
  • D. Multi-Site e full production scale already running, scaled-down na.

Keyword: scaled-down version running, scales up on disaster → Warm Standby

Instructor feedback (English)

C: If you're interested, read more about Disaster Recovery options in AWS here: https://docs.aws.amazon.com/whitepapers/latest/disaster-recovery-workloads-on-aws/disaster-recovery-options-in-the-cloud.html

28·5U28-Q5Udemy quiz · sec 28 · Q5

You have an on-premises Oracle database that you want to migrate to AWS, specifically to Amazon Aurora. How would you do the migration?

আপনার একটি on-premises Oracle database আছে, যা আপনি AWS-এ, বিশেষ করে Amazon Aurora-তে migrate করতে চান। আপনি কীভাবে migration করবেন?

Correct: A. Why it is right

Oracle → Aurora holo heterogeneous migration (engine alada). Tai dui step (PDF p. 791-792):

  • SCT (Schema Conversion Tool) database er schema ek engine theke onno engine e convert kore.
  • Tarpor DMS data migrate kore (full load + CDC).

Why the other options are wrong

  • B. Role ulta: DMS schema convert kore na, data migrate kore; SCT schema convert kore, data na.

Keyword: Oracle → Aurora (different engine) → SCT schema, DMS data

28·6U28-Q6Udemy quiz · sec 28 · Q6

You are running many resources in AWS such as EC2 instances, EBS volumes, DynamoDB tables... You want an easy way to manage backups across all these AWS services from a single place. Which AWS offering makes this process easy?

আপনি AWS-এ অনেক resource চালাচ্ছেন, যেমন EC2 instance, EBS volume, DynamoDB table... আপনি একটি single place থেকে এই সব AWS service জুড়ে backup manage করার একটি সহজ উপায় চান। কোন AWS offering এই process সহজ করে?

Correct: C. Why it is right

AWS Backup fully managed service; ek jayga theke onek AWS service er backup centrally manage ar automate kore (PDF p. 797).

EC2/EBS, S3, RDS, Aurora, DynamoDB, EFS, FSx ityadi support kore; Backup Plan e frequency ar retention set kora jay, custom script lage na.

Why the other options are wrong

  • A. S3 storage service; backup jaygay hote pare, kintu sob service er backup manage kore na.
  • B. Storage Gateway on-premise ke AWS storage er sathe connect kore; AWS service gulor backup centrally manage kore na.
  • D. EC2/EBS snapshot shudhu EBS volume er; DynamoDB ityadi cover kore na, central management o na.

Keyword: manage backups across EC2, EBS, DynamoDB from a single place → AWS Backup

Instructor feedback (English)

C: AWS Backup enables you to centralize and automate data protection across AWS services. It helps you support your regulatory compliance or business policies for data protection.

28·7U28-Q7Udemy quiz · sec 28 · Q7

A company planning to migrate its existing websites, applications, servers, virtual machines, and data to AWS. They want to do a lift-and-shift migration with minimum downtime and reduced costs. Which AWS service can help in this scenario?

একটি company তার বিদ্যমান website, application, server, virtual machine এবং data AWS-এ migrate করার পরিকল্পনা করছে। তারা সর্বনিম্ন downtime এবং কম খরচে একটি lift-and-shift migration করতে চায়। এই scenario-তে কোন AWS service সাহায্য করতে পারে?

Correct: B. Why it is right

AWS Application Migration Service (MGN): lift-and-shift (rehost) solution; physical, virtual, cloud server ke AWS e natively run korar moto convert kore (PDF p. 802).

Continuous replication kore, cutover e minimal downtime, reduced costs. Question er words slide er sathe mile.

Why the other options are wrong

  • A. DMS shudhu database migrate kore; puro server, VM, website lift-and-shift kore na.
  • C. AWS Backup backup manage kore; migration tool na.
  • D. SCT database schema convert kore; server migrate kore na.

Keyword: lift-and-shift servers/VMs, minimum downtime → Application Migration Service (MGN)

28·9U28-Q9Udemy quiz · sec 28 · Q9

A company is using RDS for MySQL as their main database but, lately they have been facing issues in managing the database, performance issues, and the scalability. And they have decided to use Aurora for MySQL instead for better performance, less complexity and less administrative tasks required. What is the best way and most cost-effective way to migrate from RDS for MySQL to Aurora for MySQL?

একটি company তাদের main database হিসেবে RDS for MySQL ব্যবহার করছে, কিন্তু ইদানীং তারা database manage করা, performance সমস্যা এবং scalability নিয়ে সমস্যার সম্মুখীন হচ্ছে। এবং তারা আরও ভালো performance, কম জটিলতা এবং কম administrative task-এর জন্য এর বদলে Aurora for MySQL ব্যবহার করার সিদ্ধান্ত নিয়েছে। RDS for MySQL থেকে Aurora for MySQL-এ migrate করার সবচেয়ে ভালো এবং সবচেয়ে cost-effective উপায় কী?

Correct: D. Why it is right

RDS MySQL → Aurora MySQL er Option 1: RDS MySQL er DB snapshot niye seta Aurora MySQL DB hisebe restore koro (PDF p. 794).

Option 2 (Aurora Read Replica, lag 0 hole promote) o ache, kintu slide e bola 'can take time and cost $'. Tai simple ar cost-effective holo snapshot restore.

Why the other options are wrong

  • A. Bhul: migration supported; support ticket lagbe na.
  • B. Dump (mysqldump) kaaj kore, kintu slow ar beshi kaaj; course e eta external MySQL er jonno, RDS theke snapshot restore sohoj.
  • C. Bhul: direct migration possible (snapshot restore ba Aurora read replica); custom app lagbe na.

Keyword: RDS MySQL → Aurora MySQL, cost-effective → snapshot restore to Aurora

28·10U28-Q10Udemy quiz · sec 28 · Q10

Which AWS service can you use to automate the backup across different AWS services such as RDS, DynamoDB, Aurora, and EFS file systems, and EBS volumes?

RDS, DynamoDB, Aurora, এবং EFS file system, এবং EBS volume-এর মতো বিভিন্ন AWS service জুড়ে backup automate করতে আপনি কোন AWS service ব্যবহার করতে পারেন?

Correct: C. Why it is right

AWS Backup RDS (all engines), Aurora, DynamoDB, EFS, EBS sob service er backup ek jayga theke automate kore (PDF p. 797). Backup Plan e frequency, window, retention set koro (PDF p. 798).

Why the other options are wrong

  • A. S3 Lifecycle Policy shudhu S3 object er storage class change/expire kore; RDS, DynamoDB backup kore na.
  • B. DataSync data copy/sync kore (on-premise ↔ AWS storage); service backup automate kore na.
  • D. Glacier archive storage class; nije onno service er backup automate kore na.

Keyword: automate backup across RDS, DynamoDB, Aurora, EFS, EBS → AWS Backup
