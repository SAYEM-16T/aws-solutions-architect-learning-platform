25·1U25-Q1Udemy quiz · sec 25 · Q1

You have strong regulatory requirements to only allow fully internally audited AWS services in production. You still want to allow your teams to experiment in a development environment while services are being audited. How can you best set this up?

আপনার কঠোর regulatory requirement আছে যে production-এ শুধু পুরোপুরি internally audited AWS service allow করা যাবে। Service-গুলো audit হওয়ার সময়েও আপনি আপনার team-গুলোকে একটি development environment-এ experiment করতে দিতে চান। আপনি এটি সবচেয়ে ভালোভাবে কীভাবে set up করতে পারেন?

Correct: C. Why it is right

AWS Organizations e Prod OU ar Dev OU banao (course er 'Environmental Lifecycle' OU example, PDF p. 625). Prod OU te SCP attach koro je shudhu audited service allow kore (allowlist).

SCP OU er sob account er user/role (root o) ke restrict kore (PDF p. 626), ar Dev OU te restriction nai tai team experiment korte pare.

Why the other options are wrong

  • A. Dev ke alada account dile experiment hoy, kintu Prod e audited service enforce korar kono mechanism hoy na; central governance nai.
  • B. IAM policy user/group/role e attach hoy, 'global' account-wide guardrail na; root user ke restrict kore na, ar admin chaile shoray dite pare.
  • D. Config Rule shudhu non-compliant detect kore; action prevent kore na (PDF p. 616: no deny).

Keyword: only audited services in prod + dev e experiment → Prod/Dev OU + SCP on Prod

25·2U25-Q2Udemy quiz · sec 25 · Q2

You are managing the AWS account for your company, and you want to give one of the developers access to read files from an S3 bucket. You have updated the bucket policy to this, but he still can't access the files in the bucket. What is the problem?

{

    "Version": "2012-10-17",

    "Statement": [{

        "Sid": "AllowsRead",

        "Effect": "Allow",

        "Principal": {

            "AWS": "arn:aws:iam::123456789012:user/Dave"

        },

        "Action": "s3:GetObject",

        "Resource": "arn:aws:s3:::static-files-bucket-xxx"

     }]

}

আপনি আপনার company-র AWS account manage করছেন, এবং আপনি একজন developer-কে একটি S3 bucket থেকে file read করার access দিতে চান। আপনি bucket policy এটিতে update করেছেন, কিন্তু তিনি এখনও bucket-এর file access করতে পারছেন না। সমস্যা কী?

{

"Version": "2012-10-17",

"Statement": [{

"Sid": "AllowsRead",

"Effect": "Allow",

"Principal": {

"AWS": "arn:aws:iam::123456789012:user/Dave"

},

"Action": "s3:GetObject",

"Resource": "arn:aws:s3:::static-files-bucket-xxx"

}]

}

Correct: C. Why it is right

s3:GetObject holo object-level permission, tai Resource hobe arn:aws:s3:::static-files-bucket-xxx/* (PDF p. 632).

Bucket ARN (/* chara) shudhu bucket-level action er jonno, jemon s3:ListBucket. Ekhane resource match kore na, tai Dave read korte pare na.

Why the other options are wrong

  • A. Logout/login e policy thik hoy na; resource ARN bhul thakle access asbe na.
  • B. Bucket khali thakle 'file nai' dekhabe, access denied na; asol problem policy er resource ARN.

Keyword: s3:GetObject + resource = bucket ARN → /* lagbe (object-level)

25·3U25-Q3Udemy quiz · sec 25 · Q3

You have 5 AWS Accounts that you manage using AWS Organizations. You want to restrict access to certain AWS services in each account. How should you do that?

আপনার 5টি AWS Accounts আছে, যেগুলো আপনি AWS Organizations ব্যবহার করে manage করেন। আপনি প্রতিটি account-এ নির্দিষ্ট কিছু AWS service-এর access restrict করতে চান। আপনার এটি কীভাবে করা উচিত?

Correct: B. Why it is right

Organizations er Service Control Policy (SCP) OU ba account e attach hoy, ar oi account er users/roles kon service/action use korte parbe tar maximum limit set kore (PDF p. 626). 5 account e ek jaygay theke service restrict korar thik tool.

Why the other options are wrong

  • A. IAM Role permission dey (assume kora jay), account-level e service block korar central mechanism na.
  • C. Config resource configuration evaluate kore; kono action restrict/deny kore na.

Keyword: Organizations + restrict services in each account → SCP

25·4U25-Q4Udemy quiz · sec 25 · Q4

Which of the following IAM condition key you can use only to allow API calls to a specified AWS region?

শুধু একটি নির্দিষ্ট AWS region-এ API call allow করতে আপনি নিচের কোন IAM condition key ব্যবহার করতে পারেন?

Correct: D. Why it is right

aws:RequestedRegion API call kon region e jacche ta restrict kore (PDF p. 630). Shudhu nirdishto region e call allow korte eta-i condition key.

Arekta: aws:SourceIp client IP restrict kore.

Why the other options are wrong

  • A. aws:RequiredRegion nam e kono IAM condition key nai.
  • B. aws:SourceRegion nam e global key nai; region er jonno key holo aws:RequestedRegion.
  • C. aws:InitialRegion nam e kono key nai.

Keyword: allow API calls to a specified region → aws:RequestedRegion

25·5U25-Q5Udemy quiz · sec 25 · Q5

When configuring permissions for EventBridge to configure a Lambda function as a target you should use ………………….. but when you want to configure a Kinesis Data Streams as a target you should use …………………..

EventBridge-এর জন্য permission configure করার সময় একটি Lambda function-কে target হিসেবে configure করতে আপনার ………………….. ব্যবহার করা উচিত, কিন্তু যখন একটি Kinesis Data Streams-কে target হিসেবে configure করতে চান, তখন আপনার ………………….. ব্যবহার করা উচিত

Correct: B. Why it is right

EventBridge rule challe target e permission lage (PDF p. 636):

  • Lambda, SNS, SQS, S3, API Gateway: target er resource-based policy e EventBridge ke allow koro.
  • Kinesis Data Streams, EC2 Auto Scaling, SSM Run Command, ECS task: EventBridge ekta IAM role (identity-based policy) use kore.

Why the other options are wrong

  • A. Ulta order: Lambda resource-based policy use kore, Kinesis Data Streams IAM role.
  • C. Lambda target e resource-based policy lage, IAM role na; tai duitai identity-based bhul.
  • D. Kinesis Data Streams e resource-based policy diye EventBridge ke allow kora hoy na; EventBridge IAM role diye write kore.

Keyword: EventBridge target: Lambda = resource-based, Kinesis = IAM role (identity-based)
