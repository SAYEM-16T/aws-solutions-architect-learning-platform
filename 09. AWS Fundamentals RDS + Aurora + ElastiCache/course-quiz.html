Why the other options are wrong

  • C. MariaDB (MySQL er fork) RDS e ache, tai eta EXCEPT er uttor na.
  • D. Microsoft SQL Server RDS er commercial engine, support kore.

Keyword: RDS supports ... EXCEPT → NoSQL MongoDB

Instructor feedback (English)

A: RDS supports MySQL, PostgreSQL, MariaDB, Oracle, MS SQL Server, and Amazon Aurora.

9·2U09-Q2Udemy quiz · sec 09 · Q2

You're planning for a new solution that requires a MySQL database that must be available even in case of a disaster in one of the Availability Zones. What should you use?

আপনি একটি নতুন solution-এর পরিকল্পনা করছেন, যার জন্য একটি MySQL database দরকার যা Availability Zone-গুলোর একটিতে disaster হলেও available থাকতে হবে। আপনার কী ব্যবহার করা উচিত?

Correct: C. Why it is right

Multi-AZ = Disaster Recovery. Master ek AZ e, standby onno AZ e, SYNC replication. Master er AZ gele automatic failover standby te, ek-i DNS name thake (PDF p. 168).

Tai ek AZ e disaster holeo MySQL available thake.

Why the other options are wrong

  • A. Read Replica holo read scaling er jonno; replication ASYNC, failover automatic na (manual promote lage). AZ disaster er DR er jonno Multi-AZ.
  • B. Encryption data ke secure kore, kintu AZ down hole DB available rakhe na.

Keyword: available even in disaster of one Availability Zone → Multi-AZ

Instructor feedback (English)

A: Read Replicas don't help with disaster recovery, it helps then you want to scale reads across AZs.

C: Multi-AZ helps when you plan a disaster recovery for an entire AZ going down. If you plan against an entire AWS Region going down, you should use backups and replication across AWS Regions.

9·3U09-Q3Udemy quiz · sec 09 · Q3

We have an RDS database that struggles to keep up with the demand of requests from our website. Our million users mostly read news, and we don't post news very often. Which solution is NOT adapted to this problem?

আমাদের একটি RDS database আছে যা আমাদের website থেকে আসা request-এর চাহিদা সামলাতে হিমশিম খাচ্ছে। আমাদের লক্ষ user মূলত news পড়ে, এবং আমরা খুব ঘন ঘন news post করি না। কোন solution এই সমস্যার জন্য উপযুক্ত নয় (NOT adapted)?

Correct: B. Why it is right

Prosno ta NOT chay. Problem holo onek read (million user news pore, kom post).

Multi-AZ er standby read-o kore na, write-o kore na; shudhu failover er jonno boshe thake (PDF p. 168). Tai read load komay na → eta-i "not adapted".

ElastiCache (common query cache) ar Read Replica duitai read load kome.

Why the other options are wrong

  • A. ElastiCache frequently read data in-memory cache kore, RDS er read load komay. Tai eta kaj kore, NOT er uttor na.
  • C. Read Replica (15 porjonto) read traffic niye ney, read-heavy load er jonno thik solution. NOT er uttor na.

Keyword: mostly read + NOT adapted → Multi-AZ (standby read kore na)

Instructor feedback (English)

B: Be very careful with the way you read questions at the exam. Here, the question is asking which solution is NOT adapted to this problem. ElastiCache and RDS Read Replicas do indeed help with scaling reads.

9·4U09-Q4Udemy quiz · sec 09 · Q4

You have set up read replicas on your RDS database, but users are complaining that upon updating their social media posts, they do not see their updated posts right away. What is a possible cause for this?

আপনি আপনার RDS database-এ read replica set up করেছেন, কিন্তু user-রা অভিযোগ করছে যে তাদের social media post update করার পরে তারা সঙ্গে সঙ্গে updated post দেখতে পাচ্ছে না। এর একটি সম্ভাব্য কারণ কী?

Correct: B. Why it is right

Read Replica te replication ASYNC. Write main DB te hoy, replica te pouchate ektu shomoy lage. Tai reads eventually consistent: user post update korar por replica theke purono post dekhte pare (PDF p. 165).

Why the other options are wrong

  • A. App er bug na; eta read replica er normal behaviour (async replication er lag).
  • C. Multi-AZ standby read serve kore na; shudhu DR er jonno. Read scale korte replica-i lage, ar lag tar nature.

Keyword: Read Replica + update er por purono data dekhay → ASYNC, eventual consistency

9·5U09-Q5Udemy quiz · sec 09 · Q5

Which RDS (NOT Aurora) feature when used does not require you to change the SQL connection string?

RDS-এর (Aurora নয় / NOT Aurora) কোন feature ব্যবহার করলে আপনাকে SQL connection string পরিবর্তন করতে হয় না?

Correct: A. Why it is right

Multi-AZ e app ekta-i DNS name e connect kore. Failover hole oi DNS name standby ke point kore, tai connection string bodlate hoy na (PDF p. 168).

Read Replica te protita replica er nijer endpoint; app ke connection string update korte hoy (PDF p. 165).

Why the other options are wrong

  • B. Protita Read Replica er nijer DNS endpoint; read load balance korte app e oigulo add korte hoy, mane connection string bodlay.

Keyword: does not require changing connection string → Multi-AZ (ek DNS name)

Instructor feedback (English)

A: Multi-AZ keeps the same connection string regardless of which database is up.

B: Read Replicas add new endpoints with their own DNS name. We need to change our application to reference them individually to balance the read load.

9·6U09-Q6Udemy quiz · sec 09 · Q6

Your application running on a fleet of EC2 instances managed by an Auto Scaling Group behind an Application Load Balancer. Users have to constantly log back in and you don't want to enable Sticky Sessions on your ALB as you fear it will overload some EC2 instances. What should you do?

আপনার application একটি Application Load Balancer-এর পেছনে একটি Auto Scaling Group দিয়ে manage করা EC2 instance-এর fleet-এ চলছে। user-দের বারবার আবার log in করতে হচ্ছে, এবং আপনি আপনার ALB-তে Sticky Sessions enable করতে চান না, কারণ আপনার ভয় এতে কিছু EC2 instance overload হয়ে যাবে। আপনার কী করা উচিত?

Correct: C. Why it is right

Session data ElastiCache e rakho (User Session Store pattern, PDF p. 189). User je instance e-i jak, oi instance ElastiCache theke session pore, abar login lage na.

Fole app stateless hoy, sticky session lage na. ElastiCache in-memory, tai RDS er cheye onek druto.

Why the other options are wrong

  • A. Nijer load balancer banale operational overhead bare, ar session sharing er problem thik hoy na.
  • B. RDS e session rakha jay, kintu disk-based DB, ElastiCache er moto high performance dey na.
  • D. EBS volume default e ek EC2 te-i attach hoy (Multi-Attach er limitation ache), ar ASG er instance gulo ek volume share korte pare na. Performance-o ElastiCache er moto na.

Keyword: bar bar log back in + Sticky Sessions chai na → session ElastiCache e

Instructor feedback (English)

B: RDS could work to store session data, but wouldn't provide you with high performance as ElastiCache.

C: Storing Session Data in ElastiCache is a common pattern to ensuring different EC2 instances can retrieve your user's state if needed.

D: By default, EBS volumes can not be attached to multiple EC2 instances. You can use EBS Multi-Attach, but it has certain limitations. Also, EBS volumes wouldn't provide you with high performance as ElastiCache.
