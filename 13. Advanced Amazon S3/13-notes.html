Lecture 6 · S3 Performance · PDF p. 304-306 (part p. 11-13)

S3 performance: per-prefix request rate, multi-part upload, Transfer Acceleration, byte-range fetch

Shohoj kore (supermarket): Protita prefix holo ekta alada cash counter: protita counter second e 3,500 jon er jinish jama nite (PUT) ar 5,500 jon ke jinish dite (GET) pare. Lok beshi? Counter barao (prefix barao), counter er sonkhar kono limit nai. Boro jinish ek-bare na niye tukra kore onek hat e ekshathe nao (multi-part / byte-range). Ar durer dokan theke anle highway diye ano (Transfer Acceleration: edge location + AWS private network).

Baseline performance (PDF p. 304 (part p. 11))

  • S3 automatically onek beshi request rate e scale kore. Latency: first byte paite 100-200 ms.
  • App kompokkhe 3,500 PUT/COPY/POST/DELETE ba 5,500 GET/HEAD request per second per prefix pete pare.
  • Bucket e prefix er sonkhar kono limit nai.
  • Prefix = bucket ar file name er majhkhaner path.
Object pathPrefix

bucket/folder1/sub2/file/folder1/sub2/
bucket/1/file/1/

  • Protita prefix alada: protita te 3,500 PUT ar 5,500 GET per second.
  • Upor er 4 ta prefix e read shoman bhabe chorale: 4 × 5,500 = 22,000 GET/HEAD request per second.

Upload druto: Multi-part upload (PDF p. 305 (part p. 12))

  • 100 MB er beshi file e recommended, 5 GB er beshi file e must (use korte-i hobe).
  • Upload parallelize kore → transfer druto, bandwidth puro use.
  • Boro file ke part (chhoto tukra) e bhag kore, protita part parallel e upload. Sob part pouchale S3 nije abar jore boro file banay.

Upload / download druto: S3 Transfer Acceleration (PDF p. 305 (part p. 12))

  • Edge location Region er cheye onek beshi: subtitle bole 200 er beshi, barche.
  • Multi-part upload er shathe compatible.
  • Udaharon: file USA te, bucket Australia te. USA er edge location porjonto public internet (kom path, fast), tarpor edge location theke Australia fast private AWS network e.
  • Idea: public internet kom, private AWS network beshi.
